## 1. Executive Summary

Milestone **BE.07.05** proves that the integrated AI conversation system can recover safely from process termination, worker interruption, database outages, and incomplete generation execution without losing accepted work or corrupting canonical conversation state.

All acceptance scenarios were executed against the live PostgreSQL database (`DATABASE_URL`) using the actual domain repositories (`PrismaAiConversationRepository`, `PrismaAiConversationTurnRepository`, `PrismaAiConversationMessageRepository`), the background dispatcher (`AiTurnDispatcherService`), the recovery worker (`AiTurnGenerationWorker`), and the transactional runner (`PrismaAiConversationTransactionRunner`).

### Key Verification Highlights

1. **Worker Termination at Execution Boundaries**:
   - Termination before execution starts: Committed `PENDING` turns are discovered by the restarted worker and dispatched to completion.
   - Termination after ownership acquired (`STREAMING`): Stalled turns whose leases have expired are detected by `findPendingOrStalledTurns`, re-dispatched, and successfully finalized to `COMPLETED`.
   - Termination during retrieval or inference: Initial failure leaves zero partial canonical state; upon restart, inference re-executes cleanly and saves the canonical answer.
   - Termination after LLM completion but before finalization commit: The turn remains recoverable; on recovery, the finalization transaction executes and marks the assistant message canonical.

2. **Pending Dispatch Recovery**:
   - Accepted work remains durably persisted in PostgreSQL regardless of API or worker process crashes.
   - Pending dispatch records are reliably discovered by worker polling (`findPendingOrStalledTurns`).
   - Duplicate delivery is safe: In-flight duplicates return `ALREADY_ACTIVE`, while duplicate deliveries for completed turns return `ALREADY_COMPLETED` and bypass RAG inference.
   - A transient dispatch outage (e.g. queue broker downtime) does not discard reserved turns, as the initial reservation transaction commits durably before dispatch.

3. **Lease Expiration, Stale Execution & Transactional Fencing**:
   - Stalled turns with expired leases (`leaseExpiresAt < now`) are safely reclaimed by the background recovery worker.
   - If an active attempt is superseded (e.g. `activeAttemptNumber` incremented), any late stale worker attempting to finalize is fenced out inside the atomic transaction, aborting with `errorCode: 'ATTEMPT_SUPERSEDED'`. No stale answer overwrites authoritative state.
   - Heartbeats or attempts to execute on cancelled or completed turns are strictly rejected with `InvalidConversationLifecycleError`.

4. **Database Outage, Rollback & Reconnection**:
   - A simulated database crash mid-transaction triggers a complete transaction rollback; zero partial assistant messages or corrupted flags remain.
   - The application never claims success to clients before a durable database commit.
   - `AiTurnErrorClassifier` sanitizes database exceptions, preventing database connection strings, credentials, or raw SQL details from leaking to users.
   - Upon reconnection, callers can retry safely with the same `clientTurnId`, recovering the canonical result (`isIdempotentReplay: true`).

5. **Crash During Finalization (Before vs After Commit)**:
   - **Crash Before Commit**: Transaction rolls back completely; 0 canonical messages exist in PostgreSQL; turn remains in recoverable state.
   - **Crash After Commit**: The canonical answer is safely persisted (`isCanonical: true`, `status: SUCCESS`); retries or duplicate acknowledgements never create duplicate messages.

6. **Operational Shutdown and Restart**:
   - Clean shutdown (`onApplicationShutdown`): Polling is stopped, timer cleared, and active executions are given a shutdown budget before aborting with `WORKER_SHUTDOWN`.
   - Incomplete work left after shutdown is discovered and completed by the restarted worker.

## 2. Recovery Mechanisms & Failure Injection Architecture

```
                                      [Worker / Process Restart]
                                                  │
                                                  ▼
                                      [AiTurnGenerationWorker.poll()]
                                                  │
                                                  ├─► Query: findPendingOrStalledTurns()
                                                  │   WHERE status = 'PENDING'
                                                  │      OR (status = 'STREAMING' AND leaseExpiresAt < now)
                                                  ▼
                                      [AiTurnDispatcherService.dispatchTurn()]
                                                  │
                  ┌───────────────────────────────┴───────────────────────────────┐
                  ▼                                                               ▼
        [Turn is ALREADY_ACTIVE]                                        [Turn Dispatched to Execute]
        Returns { dispatched: false }                                             │
                                                                                  ▼
                                                                [ExecuteConversationTurnUseCase]
                                                                                  │
                                                  ┌───────────────────────────────┴───────────────────────────────┐
                                                  ▼                                                               ▼
                                       [Turn is COMPLETED]                                            [Run RAG & Finalize Work]
                                       Fast-path return                                                           │
                                       (No RAG re-execution)                                                      ▼
                                                                                                    [Transactional Fencing Guard]
                                                                                                    inTxTurn.activeAttempt == attempt
                                                                                                    inTxTurn.status != CANCELLED
                                                                                                                  │
                                                                                                  ┌───────────────┴───────────────┐
                                                                                                  ▼                               ▼
                                                                                           [Valid Lease/Attempt]       [Superseded / Cancelled]
                                                                                           Commit Canonical Answer     Abort (ATTEMPT_SUPERSEDED)
```

### Failure Injection Methods Used in Tests

| Failure Point                  | Injection Method                                                           | Expected Recovery Action                                            |
| :----------------------------- | :------------------------------------------------------------------------- | :------------------------------------------------------------------ |
| **Crash before dispatch**      | Omit dispatcher on initial turn creation (`undefined`)                     | Worker polls PostgreSQL for `PENDING` turns and dispatches          |
| **Crash during `STREAMING`**   | Set `status: STREAMING`, `leaseExpiresAt: now - 300s`                      | Worker detects expired lease and reclaims execution                 |
| **Retrieval / Inference Drop** | Inject `Error('Retrieval database connection terminated')` in RAG pipeline | Initial execution fails; subsequent recovery worker run succeeds    |
| **Crash before Tx Commit**     | Throw `Error('Worker SIGKILL')` inside mock transaction runner             | Tx rolls back; message remains non-canonical; retry commits cleanly |
| **Attempt Superseded**         | Bump `activeAttemptNumber: 2` in PostgreSQL during inference               | Fencing guard aborts stale finalization with `ATTEMPT_SUPERSEDED`   |
| **Database Outage**            | Throw connection termination error inside transaction                      | Complete rollback; error classifier sanitizes; retry succeeds       |
| **Worker Shutdown**            | Call `worker.onApplicationShutdown('SIGTERM')`                             | Timer cleared; active turns signaled with `WORKER_SHUTDOWN`         |

## 6. Defects Fixed During Milestone

1. **`chk_terminal_attempt_no_active_lease` Constraint Violation**:
   - **Defect:** When finalizing a turn from `STREAMING` with an existing lease, `PrismaAiConversationMessageMapper.toPrismaUpdate` did not nullify `leaseExpiresAt`, `leaseToken`, and `leaseOwnerInstanceId`. This violated check constraint `chk_terminal_attempt_no_active_lease` in PostgreSQL upon transitioning to terminal `SUCCESS` or `FAILED`.
   - **Fix:** In `PrismaAiConversationMessageMapper.toPrismaUpdate`, explicitly set `data.leaseToken = null; data.leaseOwnerInstanceId = null; data.leaseExpiresAt = null;` when `update.status` is terminal (`SUCCESS`, `FAILED`, `CANCELLED`, `INTERRUPTED`).
2. **Background Dispatch Asynchronous Racing in Teardown**:
   - **Defect:** Unhandled background dispatch executions from previous tests occasionally raced with `beforeEach` `DELETE FROM "ai_conversations"`, causing PostgreSQL transaction deadlock `40P01`.
   - **Fix:** Added `dispatcher.abortAllActive('TEARDOWN')` and microtask flushing in `beforeEach` to ensure no background transactions hold database row locks during test setup.

## 7. Remaining Operational Limitations

1. **Single-Worker In-Memory Registry**:
   - `AiTurnDispatcherService` tracks active in-flight executions in an in-memory Map (`activeExecutions`). In a multi-instance cluster, concurrency deduplication across distinct worker nodes relies on the PostgreSQL unique index `ai_conversation_active_generation_idx` and lease timestamps rather than in-memory state.
2. **Deterministic Lease Timeout**:
   - The default production recovery worker poll interval is 15 seconds with a 5-minute stale threshold (`DEFAULT_TURN_GENERATION_WORKER_OPTIONS`). Crashed workers with active leases are recovered after this lease threshold expires.
