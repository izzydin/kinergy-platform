## 1. Executive Summary

This deliverable establishes the integration boundary, clean architectural dependency direction, and composition root wiring connecting the **AI-08 RAG Orchestration Layer** (`RAGOrchestratorService` implementing `IGenerateGroundedAnswerUseCase`) to the canonical **AI-09.3 Conversation Application Layer** (`ExecuteConversationTurnUseCase`).

The integration strictly respects the architectural separation between stateless grounded RAG execution and canonical multi-turn persistence, eliminating data duplication and maintaining absolute tenant isolation.

### 3.1. Absence of Secondary Store

A critical requirement of BE.06.01 is ensuring AI-08 does not maintain a parallel conversation or message store:

- `RAGTurnPipelineAdapter` forwards `command.canonicalHistory` as `conversationHistory: ChatMessage[]`.
- `RAGTurnPipelineAdapter` **omits `conversationId`** when constructing `GenerateGroundedAnswerCommand`.
- As a result, AI-08 utilizes the provided canonical history for multi-turn prompt construction in-memory, but never invokes its internal store (`recordTurn`), leaving AI-09.3 as the sole, canonical persistence authority.

## 4. Contracts & Implementations Added

### 4.1. Core Ports (`packages/core/src/ai/ports/inbound/rag-turn-pipeline.port.ts`)

- **`IRAGTurnPipelinePort`**: Clean application port defining `executeTurn(command: RAGTurnExecutionCommand): Promise<RAGTurnExecutionResult>`.
- **`RAGTurnExecutionCommand`**: Encapsulates `tenantId`, `turnId`, `query`, `canonicalHistory`, `authContext`, and optional `config`.
- **`RAGTurnExecutionResult`**: Yields `outcome` (`SUCCESS`, `ABSTAINED`, `CANCELLED`, `FAILED`), `content`, `sources`, `metrics`, and optional `errorDetails`.

### 4.2. Core Use Case (`packages/core/src/ai/application/use-cases/execute-conversation-turn.use-case.ts`)

- Implements `IExecuteConversationTurnUseCase`.
- Validates that conversation exists, belongs to tenant, and is not archived.
- Validates that turn exists, belongs to conversation, and is not in terminal state (`COMPLETED`, `CANCELLED`, `FAILED`).
- Gathers canonical history excluding any pending/uncommitted assistant placeholders.
- Transitions turn status to `STREAMING`.
- Executes pipeline via `IRAGTurnPipelinePort`.
- Updates assistant placeholder message via `PersistMessageStateUseCase`:
  - **`SUCCESS` / `ABSTAINED`**: Status `SUCCESS`, `isCanonical: true`, persists full content, sources, and metadata.
  - **`CANCELLED`**: Status `CANCELLED`, `isCanonical: false`.
  - **`FAILED`**: Status `FAILED`, `isCanonical: false`.
- Updates turn status to `COMPLETED`, `CANCELLED`, or `FAILED`.
- Updates conversation `lastActivityAt`.

### 4.3. API Adapter (`apps/api/src/ai/adapters/rag/rag-turn-pipeline.adapter.ts`)

- Implements `IRAGTurnPipelinePort`.
- Injects `GENERATE_GROUNDED_ANSWER_USE_CASE_PORT` (`IGenerateGroundedAnswerUseCase`).
- Maps `canonicalHistory` into AI-08's `ChatMessage[]` domain format.
- Translates roles into visibility scopes via `resolveVisibilityScopes(roles)`.
- Handles exceptions:
  - `GenerationCancelledException` -> `RAGTurnExecutionOutcome.CANCELLED`.
  - Low similarity / insufficient context -> `RAGTurnExecutionOutcome.ABSTAINED`.
  - Uncaught pipeline errors -> `RAGTurnExecutionOutcome.FAILED`.

### 4.4. Composition Root Wiring (`apps/api/src/ai/ai.module.ts`)

- Registered `RAG_TURN_PIPELINE_PORT` providing `RAGTurnPipelineAdapter`.
- Registered `ExecuteConversationTurnUseCase` injecting `RAG_TURN_PIPELINE_PORT`, conversation/turn repos, and `PersistMessageStateUseCase`.
- Exported from `AiModule` for downstream consumers (REST/SSE).
