## 1. Executive Summary

Milestone **BE.07.04** proves that client retries, duplicate HTTP submissions, concurrent reservations, and repeated dispatch delivery cannot create duplicate logical turns or duplicate canonical assistant messages. The client-provided `clientTurnId` and canonical application idempotency mechanisms remain authoritative across the full request-to-generation lifecycle.

All verification was conducted against the live PostgreSQL database (`DATABASE_URL`) using independent database connections, real transaction isolation, and the actual domain repositories and use cases.

### Key Verification Highlights

1. **Initial Conversation Idempotency**:
   - Replaying an initial conversation creation with identical `clientTurnId` and payload returns the existing canonical conversation and turn (`isIdempotentReplay: true`, `idempotencyOutcome: 'EXISTING_RECOVERED'`).
   - Exactly 1 conversation, 1 turn, and 2 messages exist in PostgreSQL; no duplicates are persisted.
   - Replaying with the same `clientTurnId` but a modified prompt is rejected with `DuplicateClientTurnPayloadMismatchError` (HTTP 409 Conflict).
   - Distinct client turn IDs with identical prompts create independent conversations without false deduplication.

2. **Subsequent Turn Idempotency Across Lifecycle States**:
   - In-flight turns (`PENDING`) recover the reserved turn cleanly.
   - Completed turns (`COMPLETED`) return the canonical turn with status `COMPLETED`.
   - Cancelled turns (`CANCELLED`) preserve and return the terminal `CANCELLED` status.
   - Attempting to reuse a `clientTurnId` from conversation A on conversation B triggers `PersistenceConflictError` (HTTP 409 Conflict).

3. **Canonical Payload Hashing**:
   - `AiPayloadHasher` normalizes CRLF and LF newlines (`\r\n` $\rightarrow$ `\n`) and trims leading/trailing whitespace into identical SHA-256 hashes.
   - Metadata keys are canonicalized and sorted recursively across all nesting levels.
   - Meaningful internal whitespace differences and metadata values produce distinct hashes.
   - Unicode characters (e.g. `🦵`, `🦶`) hash deterministically (64 hex characters).
   - Empty or whitespace-only prompts fail input validation with `InvalidTurnInputError`.

4. **Duplicate Dispatch and Execution Suppression**:
   - `AiTurnDispatcherService` tracks active executions and rejects duplicate in-flight dispatches with `{ dispatched: false, status: 'ALREADY_ACTIVE' }`.
   - Dispatches for already completed turns return `{ dispatched: false, status: 'ALREADY_COMPLETED' }`.
   - `ExecuteConversationTurnUseCase` incorporates a fast-path for completed turns, returning canonical content immediately without re-invoking the RAG pipeline (`mockRagPipeline` execution count remains 1).

5. **Response Consistency & Information Hiding**:
   - API response DTOs (`CreateConversationResponseDto`, `ReserveTurnResponseDto`) strictly expose only canonical identifiers (`conversationId`, `turnId`, `userMessageId`, `assistantAttemptId`, `turnStatus`, `isIdempotentReplay`).
   - Internal implementation secrets—`idempotencyPayloadHash`, `leaseToken`, `leaseOwnerInstanceId`, `txId`, and internal Prisma keys—are omitted from public responses.

6. **Failure Boundaries & Network Disconnect Recovery**:
   - Simulating a client timeout or network disconnect after database commit: the client retry recovers the existing conversation aggregate without orphaned records.
   - Simulating client retry after worker finalization: returns the completed turn and verified canonical assistant message (`isCanonical: true`, `status: SUCCESS`).

## 2. Idempotency Architecture & Contract

The system enforces idempotency through coordinated database constraints, domain hashing, and dispatch fencing:

```
[Client / API Caller]
         │
         │ HTTP POST /conversations (clientTurnId, prompt, metadata)
         ▼
[AiPayloadHasher] ──────────► Deterministic SHA-256 (CRLF normalized, sorted metadata)
         │
         ▼
[Turn Repository (PostgreSQL)]
         │
         ├─── Check: findByClientTurnId(tenantId, clientTurnId)
         │       │
         │       ├── If found AND hash matches  ──► Return existing turn (isIdempotentReplay: true)
         │       ├── If found AND hash differs  ──► Throw DuplicateClientTurnPayloadMismatchError (409)
         │       └── If not found ──────────────► Continue to Insert
         │
         ▼
[INSERT INTO ai_conversation_turns]
         │
         └── UNIQUE (tenant_id, client_turn_id)  [PostgreSQL Unique Constraint]
                 └── On 23505 race: Catch constraint violation, await winner commit, recover
```

### Dispatch and Execution Deduplication Flow

```
[AiTurnDispatcherService]
         │
         ├── Active Execution Map check:
         │       └── If turnId is currently executing ──► Return { dispatched: false, status: 'ALREADY_ACTIVE' }
         │
         ├── Turn Status check:
         │       └── If turn.status === COMPLETED     ──► Return { dispatched: false, status: 'ALREADY_COMPLETED' }
         │
         ▼
[ExecuteConversationTurnUseCase]
         │
         └── If turn.status === COMPLETED ────────────► Fast-path return canonical answer (No RAG re-run)
```
