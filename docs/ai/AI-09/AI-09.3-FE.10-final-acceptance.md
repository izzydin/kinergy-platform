## 3. Authorization & Multi-Tenant Isolation Audit

A thorough security and isolation audit was conducted across frontend query structures and backend controller handlers:

### 3.1 Server-Authoritative Identity Derivation

- **No Client Trust**: Client requests never supply `tenantId` or `userId` in query parameters or request bodies.
- **JWT Context Binding**: The backend extracts tenant and actor identity strictly via the `@TrustedAi()` parameter decorator, which parses and cryptographically validates the incoming JWT claim.
- **IDOR Protection**: Accessing or attempting to mutate a conversation belonging to a different tenant or user returns `404 Not Found` (via `ConversationNotFoundError`) rather than `403 Forbidden`. This eliminates thread enumeration vulnerabilities.

### 3.2 Client-Side Query Partitioning & Cache Scrubbing

- **Partitioned Query Keys**: TanStack Query keys are explicitly scoped by `[tenantId, userId]` across all conversation summaries, details, and message lists (e.g. `aiAssistantKeys.conversations(tenantId, userId)`).
- **Zero Cross-User Cache Leakage**: Switching user accounts triggers complete query cache invalidation and reset via `queryClient.clear()`, preventing data bleed across clinical operator sessions on shared terminals.

## 4. PostgreSQL Persistence Authority & Database Concurrency

The relational schema and concurrency safeguards implemented in PostgreSQL guarantee absolute persistence integrity:

1. **Active Generation Guard (Partial Unique Index)**:

   ```sql
   CREATE UNIQUE INDEX "ai_conversation_active_generation_idx"
   ON "ai_conversations" ("id")
   WHERE ("active_generation_status" IN ('PENDING', 'STREAMING'));
   ```

   This index enforces at the database level that no conversation can have more than one active in-flight generation. Concurrent reservation attempts trigger an immediate `409 Conflict` database exception before reaching the AI inference pipeline.

2. **Sequential Turn Ordering**:
   `sequenceNumber` strictly increments per turn within each conversation. Message history is retrieved with deterministic ordering:

   ```sql
   ORDER BY "sequence_number" ASC, "created_at" ASC
   ```

3. **Soft-Delete Lifecycle & Audit Retention**:
   The `DELETE /ai/conversations/:id` endpoint sets `archivedAt = NOW()` and `isArchived = true`. Cascade deletions are disallowed, ensuring medical audit trails and clinical decision provenance remain preserved indefinitely in PostgreSQL.

## 7. AI-09.2 Regression & Safety Audit

The implementation strictly maintains all guarantees established in AI-09.1 and AI-09.2:

1. **Context Window Bounding**: Bounded to a maximum of 10 prior completed canonical turns, preventing token explosion and context degradation.
2. **Citations & Sources**: Authoritative citations and source attributions returned by the AI-08 RAG engine are reconciled and rendered via `CitationCard` and `SourceDrawer`.
3. **Accessibility Standards**: WCAG 2.1 AA compliant. Live regions (`role="status"`, `aria-live="polite"`, `sr-only`) broadcast generation state changes; keyboard navigation supports Tab, Enter, Shift+Enter, and Escape shortcuts.
4. **Draft Protection**: Network interruptions, server timeouts, or accidental navigation do not clear clinician input in `ChatComposer`.
