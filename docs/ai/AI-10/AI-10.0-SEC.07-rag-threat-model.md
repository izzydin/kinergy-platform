## 1. Scope, Methodology, and Assumptions

### 1.1 Scope

This formal threat model evaluates the complete **Kynergy Intelligence** ecosystem based on the architectural, cryptographic, and operational evidence gathered across SEC.01 through SEC.06. It encompasses:

- Browser Client (`apps/web` Intelligence Assistant & Knowledge Center).
- API Gateway & Authentication Guards (`apps/api` NestJS controllers, JWT & RBAC guards).
- Ingestion Orchestration & Background Recovery (`IngestionOrchestratorService`, `IngestionRecoveryWorker`).
- Document Processing & Parsing (`DocumentContentValidatorService`, `PdfParserAdapter`, `DocxParserAdapter`).
- Storage Subsystem (`LocalStorageAdapter`, `S3StorageAdapter`, `StorageKeyUtil`).
- Vector Indexing & Lifecycle (`VectorIndexingOrchestratorService`, `IndexGenerationCompletenessValidatorService`).
- Vector & Relational Persistence (`PostgreSQL`, `pgvector`, `PrismaSemanticRetrievalRepository`, `PrismaLexicalRetrievalRepository`).
- Query Embedding & LLM Inference (`OllamaEmbeddingAdapter`, `OllamaLLMAdapter`, `QueryEmbeddingService`).
- Context Assembly & Generation Verification (`RAGContextBuilderService`, `GroundedGenerationService`, `CitationValidatorService`).
- Conversation & Telemetry Observability (`AiConversationController`, `GenerationObservabilityService`, `RetrievalObservabilityService`).

### 1.2 Threat Modeling Methodology

The threat modeling process utilizes an integrated approach:

1. **Asset & Actor Profiling:** Identification of critical data, credentials, and adversary profiles.
2. **Data-Flow Diagrams (DFDs) & Trust Boundaries:** Visualizing components, boundaries, and communication paths.
3. **STRIDE Analysis:** Systematically identifying threats (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege) across all boundaries.
4. **Attack Tree Modeling:** Deconstructing multi-stage attack paths for critical risk scenarios.
5. **Risk Scoring (CVSS v3.1 & DREAD):** Rigorous calculation of likelihood, exploitability, and organizational impact.
6. **Defense-in-Depth Control Mapping:** Evaluating mitigating controls and determining residual risks.

### 1.3 Key Architectural Assumptions

- **Logical Multi-Tenancy:** Multi-tenancy is enforced via a logical discriminator column (`tenant_id`) across all tables. There is no physical database-level tenant separation or schema-per-tenant.
- **Local Model Deployment:** The production design assumes Ollama runs locally on loopback (`http://127.0.0.1:11434`), precluding external cloud provider data-retention agreements for AI inference.
- **Trusted Worker Environment:** Background jobs execute in the same Node.js application process and container context as the API gateway.

### Trust Boundary Analysis

1. **TB-01: Browser to API Gateway:** Untrusted to Trusted boundary. Mitigated by `AuthenticationGuard`, `Argon2id`, and CORS.
2. **TB-02: Uploaded File to Parser:** Untrusted document content entering the Node.js parsing runtime. Mitigated by `DocumentContentValidatorService` (magic bytes, ZIP bomb limits).
3. **TB-03: Retrieval Query to Database:** Application domain to PostgreSQL. Mitigated by parameterized Prisma raw SQL queries and 3-way tenant joins.
4. **TB-04: Untrusted Chunks to LLM Prompt:** Passive retrieved text entering LLM context. Mitigated by XML encapsulation (`<evidence_chunk>`) and delimiter escaping.
5. **TB-05: Application to Local Inference Daemon:** HTTP communication over loopback (`127.0.0.1:11434`). Zero cloud exposure.

## 5. STRIDE Threat Analysis

### 5.1 Spoofing (S)

- **T-S01: Client Tenant Spoofing:** An authenticated user in Tenant A attempts to supply `tenantId: "tenant_b"` in the HTTP request body.
  - _Mitigation:_ System strictly ignores body `tenantId` and extracts tenant identity from the signed JWT claim (`req.user.tenantId`). **[IMMUNE]**
- **T-S02: Citation Preview Token Forgery:** An attacker generates a fake preview token to stream restricted documents.
  - _Vulnerability:_ `PreviewTokenService` uses a hardcoded fallback secret (`'kinergy-secure-document-preview-secret-salt-2026'`) if environment variables are missing. **[CONFIRMED RISK: SEC06-F02]**
- **T-S03: Conversational Role Spoofing:** A client submits preceding turns with `{"role": "system", "content": "override"}`.
  - _Mitigation:_ `ConversationHistoryManagerService` strips all client messages where `role === 'system'`. **[IMMUNE]**

### 5.2 Tampering (T)

- **T-T01: Same-Tenant Conversation Title/Archival Tampering:** An attacker in Tenant A modifies or archives a peer's conversation.
  - _Vulnerability:_ `updateTitle` and `archiveConversation` only verify `tenantId`, omitting `userId === actorId`. **[CONFIRMED VULNERABILITY: SEC06-F01]**
- **T-T02: Vector Index Manipulation:** An attacker alters chunk content in PostgreSQL to bypass vector similarity.
  - _Mitigation:_ `content_fingerprint` (SHA-256) is recorded on both chunks and embeddings; `IndexGenerationCompletenessValidatorService` audits fingerprints during reindexing. **[MITIGATED]**
- **T-T03: Metadata Injection in Retrieval:** Injecting SQL control characters into retrieval metadata filters.
  - _Mitigation:_ `RetrievalMetadataFilter` validates against a 10-key allowlist, bounds lengths, rejects SQL keywords, and binds via JSONB containment (`@> $param::jsonb`). **[IMMUNE]**

### 5.3 Repudiation (R)

- **T-R01: Administrative Inspection Repudiation:** A privileged Owner inspects sensitive clinical conversations without an audit trail.
  - _Mitigation:_ `POST :id/audit-inspect` creates an immutable record in `ai_conversation_audit_logs` recording inspector ID, role, target owner ID, reason, IP, and timestamp. **[MITIGATED]**
- **T-R02: Generation & Retrieval Telemetry Loss:** Operations occur without forensic audit trails.
  - _Mitigation:_ `GenerationObservabilityService` and `RetrievalObservabilityService` log all queries, pseudonyms, latencies, and outcomes with unique `requestId` and `correlationId`. **[MITIGATED]**

### 5.4 Information Disclosure (I)

- **T-I01: Cross-Tenant Document Leakage via Semantic Search:** Chunks from Tenant B leak into Tenant A's RAG responses.
  - _Mitigation:_ Mandatory SQL pre-filtering requires `ig.tenant_id = $2 AND kd.tenant_id = $2 AND kc.tenant_id = $2` before similarity ranking. Adversarial tests confirm 100% isolation. **[IMMUNE]**
- **T-I02: Low-Level Vector Store Cross-Tenant Bleed:** An internal caller uses `IVectorStorePort.similaritySearch` across tenants.
  - _Vulnerability:_ Method queries `WHERE index_generation_id = $2` without checking `tenant_id`. **[CONFIRMED RISK: SEC04-F01]**
- **T-I03: System Prompt Extraction:** User prompts the model to repeat its system prompt.
  - _Mitigation:_ System prompt Rule 9 prohibits disclosure, but no automated post-generation regex scrubber exists. **[RESIDUAL RISK: SEC05-F01]**
- **T-I04: Phishing & Malicious Hyperlink Injection:** An ingested document contains phishing links rendered in Markdown.
  - _Vulnerability:_ Web client renders `http://` and `https://` links without domain allowlists or warning modals. **[CONFIRMED RISK: SEC05-F02]**
- **T-I05: Shared Workstation LocalStorage Exposure:** Clinical conversation messages stored unencrypted in `localStorage`.
  - _Vulnerability:_ Logs out clear access tokens, but conversation cache remains on disk. **[CONFIRMED RISK: SEC06-F03]**

### 5.5 Denial of Service (DoS)

- **T-D01: DOCX Decompression Bomb:** An attacker uploads a nested 10 KB zip file expanding to 100 GB.
  - _Mitigation:_ `DocumentContentValidatorService` validates ZIP central directory before decompression: entry count $\le 1000$, uncompressed size $\le 50\text{ MB}$, ratio $\le 100:1$. **[IMMUNE]**
- **T-D02: PDF Parser CPU Exhaustion:** An attacker uploads a complex 500-page PDF with recursive loops.
  - _Mitigation:_ Pure JS parsing via `unpdf` bounded by 500 pages, 10 MB, and an explicit 30-second `Promise.race` timeout. **[MITIGATED WITH RESIDUAL EVENT-LOOP RISK: SEC03-F03]**
- **T-D03: LLM Inference Saturation:** Submitting flood of concurrent synthesis queries.
  - _Mitigation:_ `chatMaxConcurrent: 1` concurrency lock and circuit breaker tripping after 3 consecutive failures. **[MITIGATED]**

### 5.6 Elevation of Privilege (E)

- **T-E01: Role-Based Clearance Bypass in Document Retrieval:** A trainer (`ALL_STAFF`) attempts to retrieve `CLINICAL_STAFF` documents.
  - _Mitigation:_ `RetrievalSecurityPolicyService` maps roles to visibility scopes; SQL query enforces `kd.visibility_scope IN ($allowedScopes)`. **[IMMUNE]**
- **T-E02: Tool-Based Remote Code Execution via LLM:** An injected prompt instructs LLM to execute shell commands or database mutations.
  - _Mitigation:_ Ollama integration has zero tools or function calling enabled; model is strictly read-only. **[NOT APPLICABLE]**

## 7. Critical Attack Trees

### Attack Tree 1: Same-Tenant Conversation Vandalism (SEC06-F01)

```
Attacker Goal: Soft-delete or deface peer user's clinical conversation
├── 1. Obtain valid authenticated session in Tenant A (e.g. Trainer account)
│   └── Acquire JWT via legitimate login (/api/v1/auth/login)
├── 2. Discover target conversation UUID
│   ├── Predictable UUID probing (low probability)
│   └── Shared workstation shoulder surfing or client localStorage inspection
└── 3. Execute Unauthorized State Mutation
    ├── Subcase A: Deface title via PATCH /api/v1/ai/conversations/:targetId/title
    │   └── Bypasses check because controller only verifies tenantId [SUCCESS]
    └── Subcase B: Soft-delete thread via DELETE /api/v1/ai/conversations/:targetId
        └── Bypasses check because controller only verifies tenantId [SUCCESS]
```

### Attack Tree 2: Unauthorized Citation Content Exfiltration (SEC06-F02)

```
Attacker Goal: Stream restricted clinical document via forged preview token
├── 1. Identify missing environment variable configuration
│   └── Deployment administrator omits AI_PREVIEW_TOKEN_SECRET and JWT_SECRET
├── 2. Forge Preview Token
│   ├── Inspect open-source/decompiled PreviewTokenService code
│   ├── Extract hardcoded fallback: 'kinergy-secure-document-preview-secret-salt-2026'
│   └── Craft HMAC-SHA256 signature for target documentId and tenantId
└── 3. Stream Content via Public Endpoint
    └── Send GET /api/v1/ai/conversations/:cId/messages/:mId/citations/:citId/content?token=FORGED
        └── Endpoint is @Public(); signature validates against fallback secret [SUCCESS]
```

### Attack Tree 3: Indirect Prompt Injection Phishing (SEC05-F02)

```
Attacker Goal: Induce clinic staff to navigate to external credential harvester
├── 1. Craft Malicious Document
│   ├── Embed legitimate clinical text on knee rehabilitation
│   └── Inject Markdown link: [Actualización de Protocolo Clínico](https://phishing.com/login)
├── 2. Ingest Document into Knowledge Base
│   └── Upload via POST /api/v1/ai/knowledge/documents (allowed by upload validator)
├── 3. Trigger User Inquiry
│   └── Clinical user asks: "¿Cuál es el protocolo actualizado de rodilla?"
├── 4. LLM Reproduces Injected Hyperlink
│   ├── Model summarizes chunk and includes the Markdown link
│   └── Citation validator passes response (text grounded in retrieved chunk)
└── 5. Frontend Renders Clickable Hyperlink
    ├── markdown-renderer.tsx validates isSafeUrl("https://phishing.com/login") -> true
    └── User clicks link in chat feed and is redirected to phishing site [SUCCESS]
```

## 8. Risk-Scoring Methodology & Risk Register

### 8.1 Scoring Methodology

Risks are evaluated using **CVSS v3.1** (Common Vulnerability Scoring System) and cross-checked with **DREAD** metrics (Damage, Reproducibility, Exploitability, Affected Users, Discoverability).

- **CRITICAL (9.0 - 10.0):** Immediate remote code execution, full tenant bypass, or unauthenticated secret compromise.
- **HIGH (7.0 - 8.9):** Cross-tenant data leakage, unauthenticated data modification, or privilege escalation.
- **MEDIUM (4.0 - 6.9):** Same-tenant object manipulation (BOLA), token forgery under missing config, or storage accumulation.
- **LOW (0.1 - 3.9):** Event-loop latency, prompt extraction without data leakage, or minor UI spoofing.

## 9. Existing Mitigations and Defense-in-Depth

```
Layer 1: Edge & Transport  --> Rate limiting, CORS strict origin matching, in-memory tokens.
Layer 2: Authentication    --> JWT cryptographic validation, Argon2id password hashing.
Layer 3: Pre-Retrieval RBAC--> Role-to-VisibilityScope mapping, fail-closed zero clearance.
Layer 4: Relational DB     --> Parameterized SQL, 3-way tenant joins, soft-delete filtering.
Layer 5: Ingestion & Upload--> Magic byte sniffing, ZIP bomb limits, StorageKeyUtil tenant prefix.
Layer 6: Context Building  --> XML delimitation, closing tag escaping, complete chunk dropping.
Layer 7: Model Inference   --> Local loopback deployment, JSON structure enforcement, zero tools.
Layer 8: Post-Generation   --> Citation verification against evidence set, hallucination stripping.
Layer 9: Output Rendering  --> Custom React DOM parsing, protocol filtering (no javascript:/data:).
```

## 10. Residual Risk Assessment

1. **BOLA / IDOR Risk:** Residual risk remains **MEDIUM** until `conv.userId === actor.userId` is explicitly added to `updateTitle` and `archiveConversation`.
2. **Preview Token Forgery Risk:** Residual risk remains **MEDIUM** in misconfigured environments that lack `AI_PREVIEW_TOKEN_SECRET`.
3. **Indirect Phishing Link Risk:** Residual risk remains **MEDIUM** until an interstitial link warning modal is deployed on the frontend.
4. **Physical Storage Leakage:** Residual risk remains **LOW/MEDIUM**; files are private but accumulate indefinitely without a purge lifecycle worker.

## 11. Prioritized Security Recommendations Roadmap

### Priority 1: High-Impact / Low-Effort Hardening (Sprint AI-10.1)

1. **Fix Same-Tenant BOLA (SEC06-F01):** Pass `userId` from `TrustedAiContext` into `UpdateConversationTitleUseCase` and `ArchiveConversationUseCase`, asserting `conv.userId === input.userId`.
2. **Remove Hardcoded Secret Fallback (SEC06-F02):** Eliminate the hardcoded salt in `PreviewTokenService`. Throw a startup error if `AI_PREVIEW_TOKEN_SECRET` is unset, and document it in `.env.example`.
3. **Add Tenant Assertion to Low-Level Vector Search (SEC04-F01):** Add `tenantId` to `VectorSearchOptions` and enforce an inner join with `index_generations` in `PrismaVectorStoreRepository.similaritySearch`.

### Priority 2: Resilience & Privacy Hardening (Sprint AI-10.2)

4. **Implement External Link Confirmation (SEC05-F02):** Add an interstitial modal in `MarkdownRenderer` intercepting external clicks.
5. **Purge Browser LocalStorage on Logout (SEC06-F03):** Hook `assistantStorage.clearAllForUser(tenantId, userId)` into `AuthTokenStore.subscribe('logout')`.
6. **Denormalize `tenant_id` onto `document_embeddings` (SEC04-F03):** Add `tenant_id` column to `document_embeddings` with compound indexes.

### Priority 3: Operational & Lifecycle Hardening (Post-MVP Scale)

7. **Document Retention Purge Worker (SEC03-F01):** Implement a scheduled job that hard-deletes object files and chunk rows for documents soft-deleted $> 90$ days.
8. **Offload Heavy Document Parsing (SEC03-F03):** Offload `unpdf` and `mammoth` execution to Node.js `worker_threads`.
9. **Post-Generation System Prompt Scrubber (SEC05-F01):** Add an automated string similarity check preventing system prompt reproduction in model answers.
