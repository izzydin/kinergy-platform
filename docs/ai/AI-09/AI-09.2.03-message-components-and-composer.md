# AI-09.2.03 — Message Components & Message Composer Implementation Report

## Executive Summary

Milestone **AI-09.2.03** establishes the presentation foundation for Kynergy Intelligence conversational interactions. We decomposed message rendering from a single monolithic display into specialized, accessible, secure, and responsive micro-components. In addition, we delivered an enterprise-grade multiline message composer integrated with keyboard shortcuts, auto-expanding layout, character counters, draft preservation, and strict content sanitization.

All implementations strictly adhere to:

- Zero unapproved third-party dependencies (custom AST-based Markdown parser without raw `dangerouslySetInnerHTML`).
- Content security against Cross-Site Scripting (XSS), malicious protocols (`javascript:`, `data:`), and unauthorized HTML execution.
- Strict WCAG 2.1 AA accessibility standards (`role="region"`, `role="status"`, `role="alert"`, `aria-live`, explicit `aria-label` attributes, keyboard navigation).
- Preservation of existing contracts (`ChatMessageItemProps`, `ChatComposerProps`, canonical chronologic order, and existing route wrappers).

## 1. Architectural Component Decomposition

To avoid an oversized component handling all conversational responsibilities, message presentation was decomposed into modular components under `apps/web/src/modules/intelligence/assistant/components/`:

```
apps/web/src/modules/intelligence/assistant/components/
├── code-block.tsx               # Accessible pre/code block with language tag & copy action
├── markdown-renderer.tsx        # Pure AST-based safe Markdown & table renderer (zero unsafe HTML)
├── message-status-indicator.tsx # Phased indicator (pending synthesis, alert/retry on error)
├── message-metadata.tsx         # Localized timestamp, LLM model identifier, latency telemetry
├── message-citations.tsx        # Verified RAG source citations tray with document links
├── message-actions.tsx          # Copy to clipboard with transient feedback ("Copiado!")
├── user-message.tsx             # User turn bubble, text wrapping, user avatar, metadata
├── assistant-message.tsx        # Assistant turn bubble, bot avatar, markdown body, citations
├── chat-message-item.tsx        # Polymorphic dispatcher routing to UserMessage or AssistantMessage
└── chat-composer.tsx            # Multiline auto-resizing composer with draft preservation & limits
```

## 2. Security & Content Sanitization Model

Because generative AI outputs can potentially contain unvalidated markdown, malicious links, or unintended script injections, strict sanitization rules were implemented:

1. **Zero Raw HTML Injection**:
   - `MarkdownRenderer` does **NOT** use `dangerouslySetInnerHTML` or third-party wrappers with DOM bypasses.
   - Text is parsed into typed React nodes (`<p>`, `<strong>`, `<em>`, `<code>`, `<a>`, `<table>`).
2. **Safe Link Protocol Enforcement**:
   - Only `http://`, `https://`, `mailto:`, and relative `/` URIs are permitted in markdown hyperlinks `[label](url)`.
   - Links starting with `javascript:`, `data:`, `vbscript:`, or malformed protocols are neutralized into plain inert text (`<span>label</span>`).
   - All external hyperlinks render with `target="_blank"` and `rel="noopener noreferrer"`.
3. **No Dynamic Code Execution**:
   - Code blocks (`CodeBlock`) render strictly inside read-only `<pre><code>` containers with `tabIndex={0}` for keyboard navigation. No client-side evaluation (`eval`, Function, iframe) is ever performed.

## 3. Multiline Message Composer Architecture

The `ChatComposer` component provides:

- **Auto-expanding Multiline Textarea**: Auto-computes `scrollHeight` up to a maximum cap of `160px`, preventing viewport occlusion on mobile devices.
- **Keyboard Shortcuts**:
  - `Enter` (without Shift): Submits query if valid.
  - `Shift + Enter`: Inserts a standard newline without submitting.
  - `Ctrl + Enter` / `Cmd + Enter`: Submits query from anywhere within multiline text.
- **Character Counter & Validation**:
  - Minimum query length: 3 characters.
  - Maximum query length: 1,000 characters.
  - Live accessible counter (`{length}/1000`) turning into `text-destructive` font-semibold if exceeded.
- **Draft Preservation on Failure**:
  - The draft is only cleared when the submission promise resolves successfully.
  - If submission throws or rejects (e.g., transient network partition or quota exhaustion), the input draft is retained in the textarea, ensuring the practitioner never loses clinical prompt context.
- **Autofocus & Reset**:
  - Automatically resets textarea height to default single-line height upon acknowledged submission and preserves input focus.
