## 1. Executive Summary

Document ingestion pipelines operate directly on untrusted user-supplied binary files. Malicious actors frequently leverage complex document formats (PDF, DOCX/OpenXML) to exploit parser vulnerabilities, including Arbitrary Command Execution (RCE), Server-Side Request Forgery (SSRF), Local File Inclusion (LFI), XML External Entity (XXE) expansion, Zip Bomb / Decompression amplification, and Denial of Service (DoS) via thread starvation or out-of-memory (OOM) crashes.

Under milestone **AI-10.3-06**, Kynergy hardened its document parsing layer by implementing the `ParserSandboxService`, configuring strict resource bounds and image/external resource suppression across all format-specific adapters (`PdfParserAdapter`, `DocxParserAdapter`, `MarkdownParserAdapter`, `PlainTextParserAdapter`), and wrapping all document extractions in the unified `CompositeDocumentParserAdapter`.

A comprehensive 12-scenario integration test suite (`apps/api/src/ai/__tests__/ai-parser-isolation.integration.spec.ts`) was executed, verifying 21 passing test assertions across all vulnerability classes with zero regressions.

### Process & Operating System Privileges

- All parsers run within unprivileged Node.js worker/API processes running with reduced non-root permissions (`USER node` in containerized environments).
- No parsers invoke OS shell interpreters (`sh`, `bash`, `cmd.exe`).
- File buffers reside strictly in memory or in isolated temporary directories managed by `TempFileStorageService` (POSIX directory mode `0700`, file mode `0600`).

## 3. Defense Implementation & Architectural Controls

### 3.1. Arbitrary Command Execution Prevention

1. **Zero Shell Execution**: The ingestion pipeline never invokes `child_process.exec`, `eval()`, or unescaped shell strings. File names, MIME types, and document metadata are treated strictly as inert string primitives.
2. **Hardened Subprocess Runner (`executeSafeSubprocess`)**:
   - Implemented in `ParserSandboxService.executeSafeSubprocess`.
   - Uses `child_process.spawn` with `shell: false`.
   - Validates the executable path against shell metacharacters (`[;|&`$><\r\n]`), rejecting malicious paths immediately.
   - Arguments are passed exclusively as a discrete `string[]` array, eliminating argument injection.
   - Environment variables are filtered against a minimal system whitelist (`PATH`, `TEMP`, `SYSTEMROOT`, etc.), strictly stripping application secrets (`DATABASE_URL`, `JWT_SECRET`, AWS credentials).

### 3.2. Resource Exhaustion & Memory Bounds

1. **Wall-Clock Processing Timeouts**:
   - `DEFAULT_PARSER_TIMEOUT_MS = 30000` (30 seconds) enforced via `Promise.race` with guaranteed timer cleanup.
   - `DEFAULT_SUBPROCESS_TIMEOUT_MS = 15000` (15 seconds) for any external converter.
2. **Buffer and Decompression Limits**:
   - Initial input buffer capped at 10 MB.
   - DOCX ZIP archive bounded at 50 MB uncompressed text and 1,000 entry count.
3. **Extracted Character Limit Defense**:
   - `DEFAULT_MAX_EXTRACTED_CHARS = 5000000` (5,000,000 characters).
   - If extracted text across blocks exceeds this limit, an `ExtractionResourceLimitExceededException` is thrown before downstream chunking or embedding can trigger heap exhaustion.

### 3.3. Network & External Resource Isolation (SSRF / LFI / XXE)

1. **SSRF Defense**:
   - In `DocxParserAdapter.executeExtraction`, Mammoth is configured with:
     ```typescript
     convertImage: mammoth.images.imgElement(() => Promise.resolve({ src: '' })),
     ignoreEmptyParagraphs: true,
     externalFileAccess: false,
     ```
   - This prevents Mammoth from making outbound HTTP/HTTPS requests when processing malicious OpenXML relationship targets (e.g. `Target="http://169.254.169.254/latest/meta-data/"`).
2. **XXE & DTD Defense**:
   - XML parsing in Mammoth utilizes `xmldom` with entity expansion disabled. Documents containing external entity definitions (`<!ENTITY xxe SYSTEM "...">`) trigger unparsed entity errors (`xmldom error: entity not found:&xxe;`) and are cleanly rejected with `InvalidFormatExtractionException`.
3. **LFI Defense**:
   - `externalFileAccess: false` ensures the parser cannot access arbitrary local filesystem paths (`file:///etc/passwd`, `file:///C:/Windows/...`).

### 3.4. Process & Secret Isolation

1. **Diagnostic & Error Scrubbing**:
   - `ParserSandboxService.scrubSensitiveDiagnostics` redacts database connection URLs (`postgres://...`), JWT tokens, Bearer tokens, AWS access keys (`AKIA...`), and absolute server filesystem paths from all error messages and stack traces prior to logging.
2. **Temporary File Confinement & Cleanup**:
   - Ephemeral files are managed via `TempFileStorageService.executeWithTempFile`, guaranteeing that files and parent directories are unlinked in a `finally` block even when parsing fails or times out.
3. **Subprocess Termination (Zombie Prevention)**:
   - `executeSafeSubprocess` sends `SIGTERM` upon timeout, followed by `SIGKILL` after a 1,000ms grace period to guarantee no orphaned or zombie processes remain.

### 3.5. Untrusted Output Sanitization

- All extracted text is sanitized via `ParserSandboxService.sanitizeText`:
  - ASCII control characters `[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]` are stripped.
  - ANSI terminal escape sequences (`\x1B[...]`) are stripped.
  - HTML `<script>` tags and their enclosed contents are stripped.
  - Legitimate whitespace (`\t`, `\n`, `\r`) and UTF-8 multi-byte characters (Spanish clinical accents: `á, é, í, ó, ú, ñ, ¿, ¡`) are strictly preserved.
