## 1. Executive Summary

Milestone **AI-10.1-07** enforces fail-closed retrieval-time authorization, knowledge domain isolation, and cross-tenant knowledge boundaries throughout the Kynergy Intelligence retrieval and generation pipelines.

Prior to this remediation, while multi-tenant filters existed in repository SQL queries, subtle operational gaps permitted potential security degradation:

1. **Repository Fail-Closed Invariant on Scopes:** If `allowedVisibilityScopes` was passed as an empty array (`[]`) to `PrismaSemanticRetrievalRepository` or `PrismaLexicalRetrievalRepository`, the SQL condition was bypassed rather than enforcing a zero-result (`1 = 0`) predicate.
2. **Client-Side Scope Broadening:** In `SecureSemanticSearchService`, an attacker passing unauthorized `allowedVisibilityScopes` in command context was not strictly intersected against verified user roles.
3. **Adapter Fallback Scope:** In `RAGTurnPipelineAdapter`, users with no recognizable clinical roles defaulted to `[VisibilityScope.ALL_STAFF]` instead of failing closed (`[]`).
4. **Defense-in-Depth Orchestration Validation:** Before feeding retrieved knowledge chunks into prompt construction, `RAGOrchestratorService` did not perform independent verification that candidate chunk scopes matched the caller's authorized scopes.

These gaps have been completely remediated, hardened, and verified with 100% passing tests and zero TypeScript compiler errors.

## 2. Architecture & Data Flow Isolation

```
[Authenticated Client Request]
            │
            ▼
[AiRAGController / Guard Layer]
    - Derives authContext strictly from AuthenticatedUserPayload
    - tenantId: User's verified organization
    - roles: User's verified RBAC roles
            │
            ▼
[SecureSemanticSearchService]
    - Evaluates role-authorized scopes via RetrievalSecurityPolicyService
    - Scope Narrowing: allowedScopes = clientScopes ∩ roleAuthorizedScopes
    - Fail-Closed: If allowedScopes.length === 0 -> Logs unauthorized event, returns 0 chunks
            │
            ▼
[PrismaSemanticRetrievalRepository / PrismaLexicalRetrievalRepository]
    - Multi-table inner joins on tenant_id:
        ig.tenant_id = $2 AND kd.tenant_id = $2 AND kc.tenant_id = $2
    - Soft-delete boundary: kd.deleted_at IS NULL
    - Active generation boundary: ig.status = 'ACTIVE' (or explicit generationId)
    - Fail-Closed SQL: If scopes.length === 0 -> Appends "AND 1 = 0"
            │
            ▼
[RAGOrchestratorService: Defense-in-Depth]
    - Post-retrieval validation: drops any chunk whose metadata violates authorizedScopes
    - Abstention Policy:
        * 0 chunks -> Abstains without LLM call (INSUFFICIENT_EVIDENCE)
        * All chunks empty -> Abstains without LLM call (EMPTY_CHUNK_CONTENT)
        * Top similarity < 0.60 -> Abstains without LLM call (LOW_SIMILARITY)
            │
            ▼
[RAGContextBuilderService]
    - Encapsulates authorized chunks in XML tags: <chunk id="c1" title="...">...</chunk>
    - Token budget limiter: Drops whole chunks safely if budget exceeded
            │
            ▼
[Grounded LLM Generation] (Ollama / Qwen / Claude)
            │
            ▼
[CitationValidatorService]
    - Enforces citation integrity against includedChunks
    - Strips or flags any hallucinated, unmapped, or foreign chunk ID
```

### 3.1. Fail-Closed SQL Filtering in Repositories

- **Files Modified:**
  - [prisma-semantic-retrieval.repository.ts](file:///c:/Projects/kinergy-platform/packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-semantic-retrieval.repository.ts)
  - [prisma-lexical-retrieval.repository.ts](file:///c:/Projects/kinergy-platform/packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-lexical-retrieval.repository.ts)
- **Changes Applied:**
  ```typescript
  // Visibility scopes authorization filter (Fail-closed: empty array produces 1=0 to guarantee no leaks)
  if (criteria.allowedVisibilityScopes && criteria.allowedVisibilityScopes.length > 0) {
    const scopePlaceholders = criteria.allowedVisibilityScopes.map((scope) => {
      params.push(scope);
      return `$${params.length}`;
    });
    sql += ` AND kd."visibility_scope"::text IN (${scopePlaceholders.join(', ')})`;
  } else if (
    criteria.allowedVisibilityScopes !== undefined &&
    criteria.allowedVisibilityScopes.length === 0
  ) {
    // Empty visibility scopes explicitly provided means caller has no authorized scopes
    sql += ` AND 1 = 0`;
  }
  ```

### 3.2. Scope Broadening Prevention in `SecureSemanticSearchService`

- **File Modified:**
  - [secure-semantic-search.service.ts](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/retrieval/secure-semantic-search.service.ts)
- **Changes Applied:**
  Evaluated server-authoritative role scopes and computed intersection with caller-specified scopes:
  ```typescript
  const roleAuthorizedScopes = this.securityPolicy.resolveAllowedVisibilityScopes(
    command.authContext.roles ?? [],
  );

  let allowedScopes: VisibilityScope[];
  if (
    command.authContext.allowedVisibilityScopes &&
    command.authContext.allowedVisibilityScopes.length > 0
  ) {
    // Narrowing: intersect client-provided scopes with role-authorized scopes
    allowedScopes = command.authContext.allowedVisibilityScopes.filter((scope) =>
      roleAuthorizedScopes.includes(scope),
    );
  } else {
    allowedScopes = roleAuthorizedScopes;
  }
  ```

## 5. Security Invariants Confirmed

1. **Pre-LLM Enforcement:** Authorization and isolation boundaries are applied strictly before prompts are formatted. No unauthorized text ever enters the LLM context window.
2. **Zero-Trust Client Scopes:** Client-supplied scopes can only narrow searches, never broaden beyond the user's verified role scopes.
3. **Multi-Tenant Invariant:** Tenant boundaries are enforced in every repository query via mandatory joins on `tenant_id` for documents, versions, chunks, and index generations.
4. **Deterministic Abstention:** Queries yielding 0 authorized chunks or low relevance scores abstain deterministically without invoking the external LLM provider.
5. **No Cross-User Result Caching:** Search queries are evaluated fresh against database and vector indices per request, preventing cross-principal cache poisoning.
