## 1. Executive Summary

This deliverable reports the implementation and verification of **AI-10.4-04 — Context Construction and Metadata Validation**.

Building upon the prompt isolation boundaries implemented in AI-10.4-03, this milestone establishes deterministic admission gates and provenance validation rules ensuring that **only authorized, valid, correctly attributed, and policy-compliant retrieval results can enter the LLM context**.

The context construction pipeline ([`RAGContextBuilderService`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/rag/rag-context-builder.service.ts) and [`RAGOrchestratorService`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/rag/rag-orchestrator.service.ts)) has been hardened with:

1. **Authoritative Retrieval Provenance Verification:** Validates `documentId`, `chunkId`, `documentVersionNumber`, tenant ownership, and publication status.
2. **Multi-Tenant & RBAC Defense-in-Depth:** Cross-checks tenant identity and visibility scopes at the context assembly layer before XML formatting.
3. **Lifecycle Status & Quarantine Defense:** Filters out chunks belonging to documents in `QUARANTINED`, `FAILED`, `PROCESSING`, `UPLOADED`, `ARCHIVED`, or soft-deleted states.
4. **Version Consistency & Superseding Filter:** Excludes superseded document versions when a newer active version of the same document is retrieved.
5. **Context Diversity & Per-Source Ceilings:** Restricts context to a maximum of 5 distinct document sources and a maximum of 3 chunks per source, preventing prompt monopolization.
6. **Metadata Sanitization & Bounding:** Caps titles (255 chars), bounds section hierarchies (5 levels, 300 chars total), caps individual chunk text (10,000 chars), and neutralizes unprintable control characters and newline injection.

## 2. Context Validation Rules and Pipeline Architecture

The context admission pipeline executes a two-pass deterministic validation process prior to token budgeting and prompt assembly:

```
[Candidate Chunks from Hybrid Retrieval]
                    │
                    ▼
==============================================================================
Pass 1: Provenance Integrity & Security Filtering
==============================================================================
  1. Content Check:
     - Discard empty or whitespace-only content.
     - Reject chunks exceeding maxChunkContentLength (10,000 chars).
  2. Identity & Lineage Assertion:
     - Validate non-empty chunkId string (Fail closed if missing).
     - Validate non-empty documentId string (Fail closed if missing).
     - Validate documentVersionNumber >= 1 integer (Fail closed if invalid).
  3. Tenant Ownership Assertion:
     - If chunk.metadata.tenantId != options.tenantId -> DROP CHUNK (Cross-tenant defense).
  4. Document Lifecycle & Quarantine Check:
     - If status in [QUARANTINED, FAILED, PROCESSING, UPLOADED, ARCHIVED, DELETED] -> DROP CHUNK.
     - If deletedAt is non-null -> DROP CHUNK.
  5. RBAC Clearance Check:
     - If chunk.metadata.visibilityScope not in allowedVisibilityScopes -> DROP CHUNK.
  6. Version Tracking:
     - Record highest documentVersionNumber per documentId.
                    │
                    ▼
==============================================================================
Pass 2: Version Consistency, Deduplication & Diversity Limiting
==============================================================================
  1. Version Superseding Filter:
     - If chunk.version < highestVersionForDoc -> DROP CHUNK (Superseded version defense).
  2. Exact Deduplication:
     - If chunkId already seen -> DROP CHUNK.
  3. Source Diversity Ceiling:
     - If distinct documentId count >= maxSources (5) -> DROP CHUNK.
  4. Per-Source Ceiling:
     - If chunks for this documentId >= maxChunksPerSource (3) -> DROP CHUNK.
                    │
                    ▼
==============================================================================
XML Serialization & Metadata Bounding
==============================================================================
  1. Document Title: Capped at 255 chars (252 + '...'), newlines & control chars stripped.
  2. Section Hierarchy: Capped at 5 levels, max 100 chars/level, max 300 chars total.
  3. Entity Escaping: All XML entities (&, <, >, ", ') encoded into &amp;, &lt;, etc.
  4. Token Budgeting: Complete chunk dropping on total context token overflow.
```

### 3.2 Context Builder Hardening (`rag-context-builder.service.ts`)

File: [`apps/api/src/ai/services/rag/rag-context-builder.service.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/rag/rag-context-builder.service.ts)

- **Strict Provenance Assertion:**
  `normalizeAndDeduplicate` asserts that every admitted chunk has a valid `chunkId`, `documentId`, and integer `documentVersionNumber >= 1`. Missing or malformed identity properties throw explicit exceptions, failing closed.
- **Cross-Tenant & RBAC Defense:**
  Even if low-level retrieval returned an unauthorized chunk due to misconfiguration or persistence flaws, the context builder verifies `meta.tenantId === options.tenantId` and `allowedScopes.includes(meta.visibilityScope)`.
- **Status Quarantine:**
  Checks `meta.status` against `['QUARANTINED', 'FAILED', 'PROCESSING', 'UPLOADED', 'ARCHIVED', 'DELETED']` and asserts `meta.deletedAt == null`.
- **Superseded Version Elimination:**
  Determines the maximum version number for each retrieved document. If both version 1 and version 2 of the same document appear in candidate chunks, version 1 is dropped, guaranteeing that stale or superseded policies do not contaminate LLM reasoning.
- **Context Monopolization Defense:**
  Enforces `maxSources` (default 5 distinct documents) and `maxChunksPerSource` (default 3 chunks per document). A single document cannot flood the context window.
- **Metadata Bounding & Sanitization:**
  - `documentTitle` capped at 255 chars with `...` suffix.
  - `sectionHierarchy` limited to 5 levels, 100 chars per segment, 300 chars overall.
  - Unprintable control characters (`\x00-\x1F\x7F`) and newlines (`\r\n\t`) stripped.
