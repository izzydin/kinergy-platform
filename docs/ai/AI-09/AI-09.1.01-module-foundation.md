## 3. Folder Responsibilities & Architectural Boundaries

### 3.1 `assistant/` (AI Assistant Boundary)

- **Responsibility:** Encapsulates future conversational presentation, message lists, composer, streaming hooks, and client-side conversation thread stores.
- **Milestone AI-09.1 Scope:** Delivered `ChatPage` (`assistant/routes/chat-page.tsx`) as the foundational workspace mounting shell, equipped with RAG badges, active conversation indicator, and responsive containers.
- **Boundary Invariant:** Does not import from `knowledge/` internal components or deep module paths.

### 3.2 `knowledge/` (Knowledge Center Boundary)

- **Responsibility:** Encapsulates future document library tables, drag-and-drop file uploaders, 7-stage ingestion steppers, and version drawers.
- **Milestone AI-09.1 Scope:** Delivered `KnowledgePage` (`knowledge/routes/knowledge-page.tsx`) and `DocumentDetailPage` (`knowledge/routes/document-detail-page.tsx`) as mounting shells.
- **Boundary Invariant:** Operates independently of conversational state; manages document metadata and versioning presentation.

### 3.3 `components/` (Shared Module Components)

- **`IntelligenceLayout`:** Fixed viewport layout (`h-[calc(100vh-theme(spacing.28))]`) preventing global window scroll bouncing, featuring brand green accents (`#68CE39`), live subsystem status pill, and tab links between Chat and Knowledge.
- **`AIHealthPill`:** Status indicator reflecting backend Ollama LLM and pgvector readiness (`healthy` / `degraded` / `unhealthy`).
- **`IntelligenceErrorBoundary`:** Module-level error boundary preventing crashes from propagating to the global application shell.

### 3.4 `navigation/` (Navigation Configuration)

- **Responsibility:** Defines navigation entries adhering to `NavigationItem` contracts.
- **Dynamic Registration:** Calls `navigationRegistry.registerMany(intelligenceNavigationItems)` upon module initialization, adding "Chat Asistente AI" and "Base de Conocimiento" to the primary sidebar.

### 3.5 `routes/` (Routing Configuration)

- **Responsibility:** Encapsulates the sub-router under prefix `/intelligence`.
- **Registration Contract:** Automatically registers with `moduleRegistry.register()` using the `ModuleRouteDefinition` contract:
  ```typescript
  moduleRegistry.register({
    id: 'intelligence',
    prefix: '/intelligence',
    title: 'Kynergy Intelligence',
    isProtected: true,
    component: IntelligenceSubRouter,
  });
  ```
- **App Router Integration:** Imported in `apps/web/src/app/routes/app-router.tsx`.

## 4. Public API & Export Control

The public entry point (`apps/web/src/modules/intelligence/index.ts`) exposes only authorized contracts and components:

```typescript

export * from './routes';
export * from './assistant/types';
```
