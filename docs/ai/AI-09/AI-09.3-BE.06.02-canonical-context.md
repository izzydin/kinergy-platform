## 1. Executive Summary

Milestone **BE.06.02** establishes the connection between AI-08 context construction and the canonical conversation history persisted by AI-09.3 in PostgreSQL.

Every generated answer executed through `ExecuteConversationTurnUseCase` constructs its conversational context exclusively from the verified, persisted messages belonging to the requested conversation and tenant. AI-08 does not maintain an authoritative history or rely on untrusted client-supplied historical messages.

---

## 2. Canonical History Source & Application Boundary

### 2.1. Sole Source of Truth

- **Persistence Store**: Canonical conversation history is persisted exclusively in PostgreSQL through `AiConversation`, `AiConversationTurn`, and `AiConversationMessage`.
- **Query Boundary**: History is loaded strictly via the newly introduced, tenant-scoped application use case:  
  `LoadCanonicalConversationHistoryUseCase` (`packages/core/src/ai/application/use-cases/load-canonical-conversation-history.use-case.ts`).
- **No Secondary Store**: AI-08's `ConversationHistoryManagerService` does not write turns to in-memory tables or secondary stores. When executing a turn, `ExecuteConversationTurnUseCase` coordinates history loading through `LoadCanonicalConversationHistoryUseCase` and forwards canonical `ChatMessage[]` value objects directly to the RAG pipeline.

## 3. Turn Selection & Context Window Rules

### 3.1. Turn Selection Criteria

1. **Preceding Turns Only**: Turns strictly preceding the current turn index (`turnIndex < currentTurn.turnIndex` via `toTurnIndex: currentTurn.turnIndex - 1`).
2. **Terminal Completed Status Only**: Only turns with `status === TurnStatus.COMPLETED` are queried and included.
3. **Exclusion of Non-Terminal and Failed Turns**:
   - Incomplete / `PENDING` / `STREAMING` turns are excluded.
   - `FAILED` and `CANCELLED` turns are strictly excluded from completed conversational context.
4. **Current Turn Isolation**:
   - The current turn's user message is extracted as `currentUserMessage` and passed as the active query prompt. It is strictly excluded from `priorCanonicalMessages` to prevent prompt duplication.
   - The current turn's assistant placeholder attempt is strictly excluded from conversational context.

### 3.2. Context Window Bounding (Up to 10 Completed Canonical Turns)

- In accordance with the approved context-window policy, a maximum of **10 completed canonical turns** are loaded:
  ```typescript
  const totalCompletedTurnsInHistory = validCompletedTurns.length;
  const isContextTruncated = totalCompletedTurnsInHistory > maxCompletedTurns;
  const windowedTurns = isContextTruncated
    ? validCompletedTurns.slice(-maxCompletedTurns)
    : validCompletedTurns;
  ```
- **Chronological Sequence Order**: Messages for the windowed completed turns are sorted deterministically by monotonic sequence number (`sequenceNumber ASC, id ASC`).
- **Observable Telemetry**: Context truncation is explicit and observable:
  - `isContextTruncated: boolean`
  - `completedTurnsCount: number`
  - `totalCompletedTurnsInHistory: number`
    These attributes are propagated into the turn execution result and message metadata.

## 4. Mapping Rules: Domain Messages to AI-08 Context

The mapper `CanonicalChatMessageMapper` (`packages/core/src/ai/application/mappers/canonical-chat-message.mapper.ts`) translates `AiConversationMessage` entities into immutable AI-08 `ChatMessage` value objects.

### 4.1. Mapping Invariants

1. **Role Semantics**:
   - `ConversationRole.USER` $\rightarrow$ `'user'`
   - `ConversationRole.ASSISTANT` $\rightarrow$ `'assistant'`
   - `ConversationRole.SYSTEM` $\rightarrow$ `'system'`
2. **Content Preservation**:
   - Outer whitespace is trimmed.
   - Inner content is preserved without accidental truncation.
   - Message length is bounded safely to `ChatMessage.MAX_MESSAGE_LENGTH = 4000` characters without throwing.
3. **Defensive Invariant Handling**:
   - Empty, missing, or purely whitespace content is safely dropped (`toChatMessageOrNull`) or throws `InvalidMessageOperationError` if mandatory.
4. **Separation of Source Citations & Metadata**:
   - Internal persistence identifiers (`id`, `turnId`, `conversationId`, `sequenceNumber`, `attemptNumber`, `leaseToken`) are strictly stripped and never injected into the raw message content text.
   - Source citations (`sources`) remain decoupled in dedicated metadata/properties and are not concatenated into conversational text.
5. **Zero Second Domain Model**: Reuses existing `ChatMessage` value objects without duplicating entities.

## 5. Error Handling & Inconsistency Protection

| Inconsistency / Edge Case                  | Handled Behavior                                                 | Typed Error / Result                                                       |
| :----------------------------------------- | :--------------------------------------------------------------- | :------------------------------------------------------------------------- |
| **Conversation does not exist**            | Scoped lookup fails                                              | `ConversationNotFoundError(conversationId, tenantId)`                      |
| **Tenant mismatch**                        | Cross-tenant lookup returns null; existence is not leaked        | `ConversationNotFoundError(conversationId, tenantId)`                      |
| **Turn does not belong to conversation**   | Composite check `turn.conversationId === conversationId`         | `TurnNotFoundError(turnId, conversationId, tenantId)`                      |
| **Conversation archived**                  | Active execution rejected on archived conversation               | `InvalidConversationLifecycleError`                                        |
| **Turn already terminal**                  | Rejects execution on completed/failed turns                      | `InvalidConversationLifecycleError`                                        |
| **User message missing**                   | Rejects execution when turn lacks a user prompt                  | `InvalidConversationLifecycleError`                                        |
| **User message duplicated**                | Current query user message isolated; excluded from prior history | Singular prompt inclusion guaranteed                                       |
| **Non-terminal / failed turns in history** | Filtered at query and application level                          | Excluded from `priorCanonicalMessages`                                     |
| **Message unmappable**                     | Malformed / empty message handled defensively                    | Dropped via `toChatMessageOrNull` or throws `InvalidMessageOperationError` |
