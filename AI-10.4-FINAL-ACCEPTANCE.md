## 3. Core Security Invariants Verification

The Kynergy RAG architecture enforces six non-negotiable security invariants. These invariants were independently inspected and proven in code:

### Invariant 1: Structural Separation of Trust Boundaries

- **Rule:** Trusted developer instructions and untrusted third-party data must never occupy the same structural layer or document namespace.
- **Verification:** System prompts are delivered strictly via the system role channel (`<developer_instructions>`). Context evidence is encapsulated in `<retrieved_evidence>` within the user role channel. User queries are isolated inside `<user_query>`. Conversation history is enclosed in `<conversation_turn>` nodes.
- **Result:** **VERIFIED** ([`rag-prompt.template.ts`](file:///c:/Projects/kinergy-platform/packages/core/src/ai/domain/prompts/rag-prompt.template.ts#L45-L95)).

### Invariant 2: Zero Trusted Status for Retrieved Chunks

- **Rule:** Retrieved chunks, regardless of origin, internal index, or user identity, are treated as untrusted third-party reference text.
- **Verification:** The model is instructed under Rule #1 that evidence chunks are passive reference material. Any chunk attempting to issue instructions, override identity, or request actions is ignored or dropped by the pre-LLM screener.
- **Result:** **VERIFIED** ([`suspicious-content-detector.service.ts`](file:///c:/Projects/kinergy-platform/packages/core/src/ai/domain/services/suspicious-content-detector.service.ts#L30-L75)).

### Invariant 3: Zero Tool Capability & Physical Decoupling

- **Rule:** The initial RAG assistant must not have access to mutation or administrative tools. Security cannot rely on asking the model not to call tools.
- **Verification:** `ToolExecutionPolicyGuard.assertToolExecutionAllowed` throws `ToolExecutionProhibitedException` unconditionally. The Ollama provider payload excludes tool definitions. `AIModule` does not inject billing, user management, or EHR mutation services into the RAG pipeline.
- **Result:** **VERIFIED** ([`tool-execution-policy.guard.ts`](file:///c:/Projects/kinergy-platform/packages/core/src/ai/domain/services/tool-execution-policy.guard.ts#L60-L90)).

### Invariant 4: Universal Delimiter Escaping

- **Rule:** All untrusted strings (user queries, evidence content, document metadata attributes) must be strictly escaped before XML prompt interpolation.
- **Verification:** `escapePromptXmlEntities` converts `&`, `<`, `>`, `"`, and `'`. Metadata attributes strip CR/LF newlines and sanitize quotes to prevent tag injection attacks.
- **Result:** **VERIFIED** ([`rag-prompt.template.ts`](file:///c:/Projects/kinergy-platform/packages/core/src/ai/domain/prompts/rag-prompt.template.ts#L25-L35)).

### Invariant 5: Independent Deterministic Authorization

- **Rule:** Retrieval authorization, tenant isolation, and conversation history access are enforced by backend code prior to LLM assembly, never delegated to model discretion.
- **Verification:** `RAGContextBuilderService` verifies `tenantId === expectedTenantId` and publication status (`ACTIVE`). `ConversationHistoryManagerService` verifies user and tenant ownership before loading session turns.
- **Result:** **VERIFIED** ([`rag-context-builder.service.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/rag/rag-context-builder.service.ts#L80-L115)).

### Invariant 6: Post-Generation Output Sanitization

- **Rule:** Model output delivered to users must not contain markdown image exfiltration channels or unescaped executable script blocks.
- **Verification:** `CitationValidatorService` Check 4G scans model answers, replaces image exfiltration links with safe placeholders, strips `<script>` tags, and raises audit warnings.
- **Result:** **VERIFIED** ([`citation-validator.service.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/rag/citation-validator.service.ts#L180-L215)).

## 5. Actual Configured LLM Security Evaluation (`qwen3:4b`)

Evaluation of the actual configured LLM (`qwen3:4b` running under `OllamaLLMAdapter`) confirmed the effectiveness of the multi-layered defense model:

1. **Model Parameter and Setup:**
   - Active Provider: `OllamaLLMAdapter` (`apps/api/src/ai/adapters/ollama-llm.adapter.ts`).
   - Active Model: `qwen3:4b` (temperature: 0.1, max_tokens: 1024, stop sequences: `["</user_query>", "</retrieved_evidence>", "<|im_end|>"]`).
   - Tool Definition Payload: Omitted (`tools: undefined`).

2. **Model Behavior Observations:**
   - When presented with escaped adversarial prompts (`KY-ADV-003`, `KY-ADV-004`), the model treated XML tags as inert literal text and responded strictly to the clinical query.
   - When presented with ungrounded clinical questions without evidence, the model adhered to explicit abstention phrasing ("No dispongo de información suficiente en los documentos autorizados").
   - Under model-level failure or timeout scenarios, the application-level deterministic fallback (`GroundingService` / `CitationValidatorService`) correctly intercepted fabricated chunk citations and ungrounded claims.

3. **Evaluation Conclusion:**
   - While `qwen3:4b` demonstrates good instruction-following capability at low temperature (0.1), **application security is entirely guaranteed by deterministic pre- and post-processing gates** (XML escaping, suspicious content filtering, tenant checking, and citation validation), ensuring safety even if the underlying model hallucinates or fails to follow instructions.

## 6. Read-Only Boundary & Tool Execution Impossibility

A core mandate of AI-10.4 is ensuring that the initial RAG assistant is provably read-only and incapable of modifying business state.

### Proof of Read-Only Invariant:

1. **Zero Provider Tools:** The LLM provider configuration for RAG does not register any tool schemas, function declarations, or action endpoints.
2. **Deterministic Execution Guard:** [`tool-execution-policy.guard.ts`](file:///c:/Projects/kinergy-platform/packages/core/src/ai/domain/services/tool-execution-policy.guard.ts) evaluates all tool requests against an immutable capability inventory:
   ```typescript
   // Deterministic rejection of all tool calls in initial assistant:
   public assertToolExecutionAllowed(toolName: string, args: Record<string, unknown>): void {
     this.inspectPayloadForProhibitedToolInvocation(args);
     this.validateToolArguments(args);
     throw new ToolExecutionProhibitedException(
       `Tool execution is prohibited in the initial RAG assistant. Tool '${toolName}' cannot be invoked.`
     );
   }
   ```
3. **Physical Decoupling:** `AIModule` imports zero mutating business services (`BillingService`, `UserService`, `MembershipService`). There is no code path or dependency injection token through which the RAG pipeline could execute a state-changing database write.

## 9. Production Deployment Prerequisites & Operational Safeguards

To maintain the verified security posture in production environments, the following operational controls must be maintained:

1. **Environment Configuration:**
   - `OLLAMA_BASE_URL` must point to an isolated, network-segmented inference server not reachable from public networks.
   - The LLM temperature parameter must remain at `0.1` or lower for grounded RAG endpoints.
2. **Pre-LLM Screener Maintenance:**
   - The regex patterns in `SuspiciousContentDetector` must be updated periodically as new jailbreak patterns emerge in public corpora.
3. **Strict Maintenance of Read-Only Posture:**
   - Any future milestone proposing model-directed tool execution (e.g. agentic workflows) must implement individual user authorization checks, HMAC transaction tokens, and human-in-the-loop confirmation before tools are unblocked.
4. **Audit Log Monitoring:**
   - Security audit logs emitted by `SuspiciousContentDetector` and `CitationValidatorService` must be forwarded to the centralized SIEM for real-time alerting on potential coordinated injection attacks.
