## 3. Explicit Update Contracts & Persistence DTOs

Rather than accepting entire unvalidated domain entities for partial updates or arbitrary untyped mutation dictionaries, the contracts provide fine-grained, strongly-typed DTOs:

| Contract DTO                        | Target Port                            | Mutable Fields Permitted                                                       | Immutable Invariant Protected                                                                                  |
| :---------------------------------- | :------------------------------------- | :----------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------- |
| **`UpdateConversationMetadataDto`** | `IAiConversationRepositoryPort`        | `title`, `lastActivityAt`, `isArchived`                                        | `id`, `tenantId`, `userId`, `turnCounter`, `messageCounter` cannot be modified via metadata update             |
| **`UpdateTurnStatusDto`**           | `IAiConversationTurnRepositoryPort`    | `status`, `completedAt`, `activeAttemptId`, `activeAttemptNumber`              | `id`, `conversationId`, `tenantId`, `turnIndex`, `clientTurnId`, `idempotencyKey` cannot be mutated            |
| **`UpdateMessageStatusDto`**        | `IAiConversationMessageRepositoryPort` | `status`, `content`, `isCanonical`, `completedAt`, `errorCode`, `errorMessage` | `id`, `turnId`, `conversationId`, `tenantId`, `role`, `sequenceNumber`, `attemptNumber` are strictly immutable |
| **`AcquireMessageLeaseDto`**        | `IAiConversationMessageRepositoryPort` | `leaseToken`, `leaseOwnerInstanceId`, `leaseExpiresAt`                         | Only active generation attempts in non-terminal states can acquire leases                                      |

## 4. Pagination Design & Keyset Semantics

### 4.1 Message History Pagination (Strict Snapshot Consistency)

- **Cursor VO:** [MessageHistoryCursor](file:///c:/Projects/kinergy-platform/packages/core/src/ai/domain/value-objects/message-history-cursor.vo.ts)
- **Ordering:** `(sequenceNumber ASC, id ASC)`
- **Cursor Payload:** `{ s: number, id: string }` encoded to Base64URL.
- **Guarantee:** **Strict Snapshot Consistency**. Because `sequenceNumber` values are monotonic and immutable once written, pagination is deterministic and unaffected by concurrent mutations to active conversation activity.

### 4.2 Conversation Listing Pagination (Deterministic Activity Traversal)

- **Cursor VO:** [ConversationListCursor](file:///c:/Projects/kinergy-platform/packages/core/src/ai/domain/value-objects/conversation-list-cursor.vo.ts)
- **Ordering:** `(lastActivityAt DESC, id DESC)`
- **Tie-Breaker:** UUID `id` guarantees deterministic ordering when two conversations share identical timestamps.
- **Cursor Payload:** `{ a: string (ISO timestamp), id: string }` encoded to Base64URL.
- **Consistency Warning (Documented in Contract):** Activity-based pagination does **NOT** provide snapshot consistency. Because `lastActivityAt` is updated whenever a conversation receives a new prompt or answer, conversations updated during pagination traversal may change positions or reappear on later pages.

### 4.3 Audit History Pagination (Independent Retention)

- **Cursor VO:** [AuditHistoryCursor](file:///c:/Projects/kinergy-platform/packages/core/src/ai/domain/value-objects/audit-history-cursor.vo.ts)
- **Ordering:** `(createdAt DESC, id DESC)`
- **Cursor Payload:** `{ t: string (ISO timestamp), id: string }` encoded to Base64URL.
- **Guarantee:** Independent audit lifecycle without foreign-key dependency on conversation existence.

## 5. Tenant Isolation & Scoping Strategy

1. **Mandatory First-Parameter Tenant Scoping:**
   - Every read and write method across all four ports requires `tenantId: string` as its first parameter (or encapsulates `tenantId` in the root aggregate passed to `save`).
   - Generic or unscoped signatures such as `findById(id: string)` are prohibited by contract.
2. **Compile-Time Contract Enforcement:**
   - Contract test suite enforces type-level assertions:
     ```typescript
     type AssertTenantFirstParam<T> = {
       [K in keyof T]: T[K] extends (...args: never[]) => unknown
         ? Parameters<T[K]>[0] extends string
           ? true
           : Parameters<T[K]>[0] extends object
             ? true
             : false
         : true;
     };
     ```
3. **Database-Level Backing:**
   - Authoritative isolation is backed by PostgreSQL composite foreign keys `(conversation_id, tenant_id)` and `(turn_id, conversation_id, tenant_id)`.

## 6. Transaction Compatibility Strategy

In accordance with Section 6 of the execution rules, repository ports do not leak ORM or database transaction primitives:

1. **Decoupled Signatures:** Method signatures contain zero references to `PrismaClient`, `Prisma.TransactionClient`, or PostgreSQL client pools.
2. **Unit-of-Work Composition:** Repositories are designed for ambient context propagation or UnitOfWork pattern integration in subsequent use-case milestones (e.g. `UnitOfWorkPort` wrapping transaction boundaries).
3. **Audit Log Isolation:** Audit recording contracts support independent transaction execution so that clinical inspection logs can be committed even if the inspected operation encounters an error or rolls back.
