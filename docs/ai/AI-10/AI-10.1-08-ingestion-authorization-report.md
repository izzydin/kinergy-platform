## 1. Executive Summary

Milestone **AI-10.1-08** establishes formal authorization guarantees and provenance preservation across the asynchronous document ingestion pipeline in Kynergy Intelligence.

Background processing is inherently vulnerable to authorization context stripping: when work is offloaded to background threads or queue workers, the original HTTP authentication context (`AuthenticatedUserPayload`) is no longer present on the active execution stack. If workers trust incoming job payloads blindly or execute with unbounded administrative privileges, the system becomes exposed to broken object-level authorization (BOLA), parameter tampering, scope escalation, and cross-tenant knowledge leaks.

Through this remediation:

1. **Worker Authorization Model Defined:** Workers operate strictly under a **Narrowly Scoped System Identity Bound to Authoritative Persistence** (`SystemDocumentWorker`). Workers never act with broad ambient administrator credentials, nor do they trust ownership, tenant, or role attributes from ephemeral job payloads.
2. **Payload Anti-Tampering & Anti-BOLA Enforced:** The worker resolves the document and its ownership strictly from the database using the persistent `IngestionJob` record. If a caller or worker invocation provides a mismatched tenant ID, the execution fails closed with `UnauthorizedDocumentAccessException`.
3. **State Invariants & Revocation Handling:** Before processing begins and at each checkpoint (`VALIDATING`, `PROCESSING`, `INDEXING`), the worker validates that the parent document still exists, has not been soft-deleted (`deleted_at IS NULL`), and maintains an identical tenant boundary.
4. **Retry & Recovery Provenance Preservation:** Both automated watchdog recoveries (`IngestionRecoveryWorker`) and administrative retries (`retryJob`) strictly inherit and enforce the original tenant ID, document version ID, and visibility scope from trusted persistence.

## 2. Ingestion Authorization Architecture & Data Flow

```
[Authenticated User Request] (POST /api/v1/ai/knowledge/documents)
            │
            ├─ 1. Identity & Scope Derivation:
            │     * tenantId derived from AuthenticatedUserPayload.tenantId
            │     * uploadedBy derived from AuthenticatedUserPayload.userId
            │     * visibilityScope validated against actor's role clearance
            │
            ▼
[SecureDocumentUploadService]
            │
            ├─ 2. Storage Partitioning:
            │     * Object key: tenants/{tenantId}/knowledge_base/{timestamp}/{safeFileName}
            │
            ├─ 3. Atomic Database Persistence:
            │     * KnowledgeDocument (uploadedBy, visibilityScope, tenantId)
            │     * DocumentVersion (storageKey, checksum, uploadedBy)
            │     * IngestionJob (tenantId, documentId, documentVersionId, status=UPLOADED)
            │
            ▼
[Asynchronous Queue / Worker Dispatch]
    - Payload contains ONLY: { jobId: string, tenantId: string }
    - STRICT INVARIANT: No JWTs, secrets, or arbitrary role/scope overrides in payload
            │
            ▼
[IngestionOrchestratorService: SystemDocumentWorker Execution]
            │
            ├─ 4. Authoritative Record Resolution:
            │     * Fetches IngestionJob from trusted database
            │     * authoritativeTenant = job.tenantId
            │     * Anti-BOLA Verification: If payload.tenantId !== authoritativeTenant -> ABORT
            │
            ├─ 5. Document State & Ownership Checkpoint:
            │     * Resolves KnowledgeDocument by (authoritativeTenant, job.documentId)
            │     * If document is missing or soft-deleted -> FAIL PERMANENTLY (DOCUMENT_NOT_FOUND)
            │     * Verifies document.tenantId === authoritativeTenant
            │     * Verifies DocumentVersion exists and storageKey is bounded
            │
            ├─ 6. Cooperative Cancellation & Watchdog:
            │     * Refreshes status at each phase (VALIDATING -> PROCESSING -> INDEXING)
            │     * Stalled jobs recovered by IngestionRecoveryWorker with bounded backoff
            │
            ▼
[Downstream Processing & Indexing]
    - Chunking & Text Extraction (DocumentProcessingPipelineService)
    - Vector Indexing (VectorIndexingOrchestratorService)
    - Document reaches READY state only upon complete verification
```

## 3. Worker Authorization Model Decision & Design

### 3.1. Selected Model: Narrowly Scoped System Identity

We evaluated two candidate authorization models for worker execution:

- **Option A (User Impersonation):** Serializing the initiating user's security token or identity into the job payload and executing the worker on behalf of the user.  
  _Verdict:_ **Rejected.** Exposes credentials to queue logs and disk storage, violates zero-trust principles, and breaks if user access is revoked or refreshed during long-running processing.
- **Option B (Narrowly Scoped System Identity):** The worker acts under a dedicated system role (`SystemDocumentWorker`) whose authority is strictly constrained to the specific document ID and tenant ID verified from authoritative persistence.  
  _Verdict:_ **Approved & Implemented.** No credentials are serialized. The worker queries records via tenant-scoped repository interfaces and fails closed if the document state or tenant boundary is invalid.

### 3.2. Trusted Attributes vs. Job Payload Policy

| Attribute           | Queue Payload Source  | Authoritative Source                   | Validation Rule                    |
| ------------------- | --------------------- | -------------------------------------- | ---------------------------------- |
| `jobId`             | Required reference    | `ingestion_jobs.id`                    | Must exist in database             |
| `tenantId`          | Optional routing hint | `ingestion_jobs.tenant_id`             | Must match database record exactly |
| `documentId`        | **Ignored**           | `ingestion_jobs.document_id`           | Read exclusively from database     |
| `documentVersionId` | **Ignored**           | `ingestion_jobs.document_version_id`   | Read exclusively from database     |
| `visibilityScope`   | **Ignored**           | `knowledge_documents.visibility_scope` | Inherited from parent document     |
| `uploadedBy`        | **Ignored**           | `knowledge_documents.uploaded_by`      | Inherited from parent document     |
| User Credentials    | **Forbidden**         | None                                   | Tokens must never enter queue      |

## 4. Key Remediation Evidence

### 4.1. Orchestrator Authoritative Tenant & State Enforcement

- **File Modified:** [ingestion-orchestrator.service.ts](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/ingestion-orchestrator.service.ts)
- **Hardening Applied:**
  ```typescript
  // Authoritative tenant derived strictly from the persisted IngestionJob record
  const authoritativeTenantId = job.tenantId;

  // Fail-closed verification: If caller provided a mismatched tenantId, reject immediately (Anti-BOLA / payload tampering)
  if (tenantId && tenantId.trim() !== authoritativeTenantId) {
    this.logger.error(
      `[SECURITY] Tenant mismatch detected for job '${jobId}'. Supplied: '${tenantId}', Authoritative: '${authoritativeTenantId}'.`,
    );
    throw new UnauthorizedDocumentAccessException(
      `Cross-tenant job execution rejected for job '${jobId}'.`,
    );
  }

  const tId = authoritativeTenantId;

  // Authoritative ownership & state validation: Verify document and version exist in DB under same tenant
  const document = await this.documentRepo.findById(tId, job.documentId);
  if (!document || document.isDeleted()) {
    throw new Error(`Referenced document '${job.documentId}' does not exist or was deleted.`);
  }

  // Invariant: Verify parent document tenant matches job tenant
  if (document.tenantId !== tId) {
    throw new UnauthorizedDocumentAccessException(
      `Document tenant '${document.tenantId}' does not match job tenant '${tId}'.`,
    );
  }
  ```

### 4.2. Permanent Security Failure Classification in Retry Policy

- **File Modified:** [ingestion-retry.policy.ts](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/ingestion-retry.policy.ts)
- **Hardening Applied:**
  Security violations, authorization denials, and missing/deleted document states are classified as **non-retryable permanent failures** (`SECURITY_VIOLATION` or `DOCUMENT_NOT_FOUND`). This prevents runaway infinite retry loops when a document is deleted or an unauthorized payload is submitted.
