## 1. Executive Summary

Milestone **AI-10.1-06** enforces the platform's approved authentication, RBAC permissions, and resource-level authorization policies across all AI endpoints: Knowledge Documents, Document Versions, Ingestion & Observability, Grounded Generation (RAG), and AI Conversations.

Building on the domain-driven policy engine (`AiResourceAuthorizationPolicy`) established in AI-10.1-05 and the canonical RBAC catalog (`PERMISSIONS.AI`) established in AI-10.1-04, this phase guarantees that every externally reachable AI endpoint enforces explicit authentication, role/permission authorization, and object-level ownership checks before executing mutations or returning sensitive data.

### Key Security Achievements:

1. **Server-Side Query Scoping for List Endpoints:**  
   `GET /api/v1/ai/knowledge/documents` no longer relies on client-side filtering. Document queries are scoped at the PostgreSQL/Prisma query planner level using `visibilityScopes: allowedScopes`. Lower-clearance users (e.g. `Trainer`, `Receptionist`) can only discover `ALL_STAFF` documents; `CLINICAL_STAFF` and `MANAGEMENT` documents are physically excluded from result sets and pagination counts.
2. **Anti-Tampering & Classification Guardrails:**  
   Document uploads (`POST /documents`) and version uploads (`POST /documents/:id/versions`) strictly derive `uploadedBy` from the authenticated JWT principal (`actor.actorId`). Attempts by lower-clearance users to classify documents above their role clearance (`visibilityScope: CLINICAL_STAFF`) are rejected with `403 Forbidden`.
3. **Anti-BOLA & Anti-Enumeration (404 Not Found):**  
   Conversations, message histories, and turns reject peer access within the same tenant by returning `404 Not Found` (`ConversationNotFoundError`), indistinguishable from non-existent UUIDs.
4. **Source Preview Integrity & HMAC Signature Binding:**  
   Preview tokens generated for citation document previews cryptographically bind `tenantId`, `userId`, `conversationId`, `messageId`, `citationId`, and `roles`. Direct document streaming verifies live document clearance and non-deleted invariants even when accessed via short-lived tokens.
5. **Comprehensive Automated Verification:**  
   All 10 required security test scenarios (20 dedicated test cases) passed cleanly. In total, 98 API tests and 325 core domain tests passed with 100% success rate, and `tsc --noEmit` verified zero compilation errors.

## 3. Section B: Intentionally Unprotected or Public Routes

Only three routes permit unauthenticated or non-standard token access, each with strict justification:

1. **`GET /api/v1/ai/health`:**
   - _Justification:_ Runtime health, model readiness, and Ollama daemon connectivity probe for container orchestration (Kubernetes / Docker) and uptime monitoring.
   - _Protections:_ Exposes zero tenant data, zero PHI, zero user data, and zero configuration secrets. Marked with `@Public()` and `@SkipThrottle()`.
2. **`GET /api/v1/ai/knowledge/documents/capabilities`:**
   - _Justification:_ Static capabilities metadata describing maximum file size (10 MB), supported extensions (`.pdf`, `.docx`, `.md`, `.txt`), and supported visibility scopes.
   - _Protections:_ Requires valid Bearer JWT authentication. Exposes no document records, storage paths, or sensitive system details.
3. **`GET /api/v1/ai/conversations/:id/messages/:msgId/citations/:citId/content?token=...`:**
   - _Justification:_ Inline citation preview streaming within HTML `<iframe>`, `<embed>`, or `<img>` elements where browsers cannot transmit custom `Authorization: Bearer` headers.
   - _Protections:_ Requires a cryptographically signed HMAC-SHA256 token generated by `PreviewTokenService`. The token is strictly scoped to `{ tenantId, userId, conversationId, messageId, citationId, documentId, roles }` with a 5-minute TTL. Signature comparison uses timing-safe equality (`crypto.timingSafeEqual`) to prevent timing attacks.

## 4. Section C: Document Operations Enforcement & Scoping

1. **Database Pre-Filtering for Lists:**  
   In `PrismaKnowledgeDocumentRepository`, the `buildWhereClause` builder was upgraded to support `visibilityScopes: VisibilityScope[]`. When `listDocuments` executes, the repository query applies `where: { tenantId, visibilityScope: { in: allowedScopes } }`. Lower-tier staff never receive or discover higher-tier documents.
2. **Uploader Invariant & Scope Assignment Verification:**  
   In `uploadDocument`, `uploadedBy` is populated exclusively from `user.id` (`extractAuthContext`). If a client passes `visibilityScope = CLINICAL_STAFF`, the controller verifies `allowedScopes.includes(dto.visibilityScope)`. Users lacking clinical role clearance cannot classify documents into clinical scopes (`403 Forbidden`).
3. **Soft Deletion & Anti-Enumeration:**  
   `DELETE /documents/:id` marks `deletedAt = new Date()`, updates status to `DELETED`, and triggers vector cleanup via `VectorCleanupService`. Normal retrieval endpoints return `404 Not Found` for soft-deleted documents unless requested by a user with `ai.documents.manage`.

## 5. Section D: Conversation & Source Preview Operations

1. **Backend-Assigned Ownership:**  
   `CreateConversationWithInitialTurnUseCase` and `AiConversationController` bind `conversation.userId = actor.actorId`. Client-supplied user identifiers are ignored.
2. **Anti-BOLA Indistinguishability:**  
   Probing a colleague's conversation returns `404 Not Found` (`ConversationNotFoundError`). An attacker cannot determine whether a probed UUID exists or belongs to another user.
3. **Dynamic Revocation:**  
   Citation preview generation and content streaming dynamically check `document.deletedAt` and `allowedScopes.includes(doc.visibilityScope)` at request time. If a document is deleted or a user's role is downgraded after conversation generation, subsequent previews are immediately blocked (`404` or `403`).

## 8. Section G: Remaining Gaps & Architecture Recommendations

1. **Multi-User Collaborative Ownership:**  
   Currently, document management authority rests with the individual uploader (`uploadedBy`) or users with broad administrative privileges (`ai.documents.manage`). As clinical teams expand, introducing department-level or care-team co-ownership will allow collaborative document management without granting full administrative rights.
2. **Clinical Delegation & Handoff:**  
   Conversations remain strictly private to the original creator (`conv.userId === actor.actorId`). During shift changes or clinician vacations, patient care workflows may benefit from an explicit delegation model where a clinician can temporarily share conversation sessions with a designated colleague under mandatory audit logging.
3. **Database-Level Row Security (RLS):**  
   While application-layer tenant isolation and repository WHERE clauses are thoroughly enforced, configuring PostgreSQL Row-Level Security (RLS) on `ai_conversations` and `knowledge_documents` would provide defense-in-depth against accidental omission of tenant filters in future raw queries.
