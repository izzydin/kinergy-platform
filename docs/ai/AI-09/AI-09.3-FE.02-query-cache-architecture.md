## 3. Query Key Architecture & Cache Partitioning

Query keys are defined in [`conversation-query-keys.ts`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/api/conversation-query-keys.ts):

```ts
export const conversationQueryKeys = {
  all: ['ai-conversations'] as const,

  // Tenant- and user-scoped partition
  userScope: (scope?: ConversationQueryScope) =>
    [
      ...conversationQueryKeys.all,
      scope?.tenantId ?? 'default_tenant',
      scope?.userId ?? 'anonymous',
    ] as const,

  // Collections (lists)
  lists: (scope?: ConversationQueryScope) =>
    [...conversationQueryKeys.userScope(scope), 'list'] as const,

  list: (params?: ListConversationsQueryParams, scope?: ConversationQueryScope) =>
    [...conversationQueryKeys.lists(scope), sanitizeConversationQueryParams(params)] as const,

  // Details
  details: (scope?: ConversationQueryScope) =>
    [...conversationQueryKeys.userScope(scope), 'detail'] as const,

  detail: (conversationId: string, scope?: ConversationQueryScope) =>
    [...conversationQueryKeys.details(scope), conversationId] as const,

  // Messages
  messagesRoot: (scope?: ConversationQueryScope) =>
    [...conversationQueryKeys.userScope(scope), 'messages'] as const,

  messages: (conversationId: string, scope?: ConversationQueryScope) =>
    [...conversationQueryKeys.messagesRoot(scope), conversationId] as const,

  paginatedMessages: (
    conversationId: string,
    params?: GetMessageHistoryQueryParams,
    scope?: ConversationQueryScope,
  ) =>
    [
      ...conversationQueryKeys.messages(conversationId, scope),
      sanitizeConversationQueryParams(params),
    ] as const,
};
```

### Deterministic Parameter Sanitization

`sanitizeConversationQueryParams(params)` normalizes query parameters:

- Strips `undefined`, `null`, and empty string (`""`) values.
- Alphabetically sorts property keys so that `{ limit: 20, cursor: undefined }` and `{ limit: 20 }` produce identical query keys regardless of object key order.

## 4. Cache Consistency & Invalidation Policies

Implemented in [`conversation-cache-policies.ts`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/api/conversation-cache-policies.ts):

| Cache Scope             | Stale Time              | Garbage Collection (gcTime) | Invalidation Trigger                                            | Action Taken                                                                             |
| :---------------------- | :---------------------- | :-------------------------- | :-------------------------------------------------------------- | :--------------------------------------------------------------------------------------- |
| **Conversation List**   | 30 seconds (`30_000ms`) | 10 minutes (`600_000ms`)    | New conversation created, title renamed, conversation archived. | `invalidateQueries({ queryKey: conversationQueryKeys.lists(scope) })`                    |
| **Conversation Detail** | 15 seconds (`15_000ms`) | 10 minutes (`600_000ms`)    | Turn reserved, turn completed, title renamed.                   | `setQueryData` for immediate optimistic update; `invalidateQueries` on completion.       |
| **Message History**     | 10 seconds (`10_000ms`) | 10 minutes (`600_000ms`)    | Subsequent turn reservation or assistant generation finalized.  | `invalidateQueries({ queryKey: conversationQueryKeys.messages(conversationId, scope) })` |
| **User Scope Clearing** | N/A                     | Immediate                   | User logout, token refresh failure, or tenant switch.           | `cancelQueries` and `removeQueries` targeting `userScope(scope)` or `all`.               |

## 5. Reusable Query & Mutation Hooks

### 5.1 Query Hooks ([`use-conversation-queries.ts`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/hooks/use-conversation-queries.ts))

- `useConversations(params?, options?)`: Single page of keyset-paginated conversations. Supports `keepPreviousData` and `refetchOnWindowFocus: false`.
- `useInfiniteConversations(params?, options?)`: Multi-page keyset infinite query consuming `nextCursor` for seamless sidebar scrolling.
- `useConversation(conversationId, options?)`: Single conversation detail aggregate. Automatically disabled when `conversationId` is empty or undefined.
- `useConversationMessages(conversationId, params?, options?)`: Message history ordered by `sequenceNumber ASC`. Disabled when `conversationId` is empty.
- `useInfiniteConversationMessages(conversationId, limit?, options?)`: Sequence-based infinite scrolling for message thread browsing.

### 5.2 Mutation Hooks ([`use-conversation-mutations.ts`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/hooks/use-conversation-mutations.ts))

- `useCreatePersistentConversationMutation(options?)`: Creates a new conversation aggregate with initial turn, invalidates conversation lists on success.
- `useRenameConversationMutation(options?)`: Updates title, updates detail cache directly, and invalidates list caches.
- `useArchiveConversationMutation(options?)`: Soft-deletes conversation, removes detail/message caches, and invalidates list caches.
- `useReserveTurnMutation(options?)`: Submits subsequent prompt with client idempotency key, invalidating entire conversation cache.

## 7. Future Mutation Integration Guidelines (For FE.03+)

When integrating UI components and mutations in FE.03:

1. **Always Use `conversationQueryKeys`:** Never construct raw string query keys (e.g. `['conversations']`).
2. **Preserve User/Tenant Scope:** Rely on `useResolvedConversationScope()` or pass explicit scope to prevent cross-account cache collisions.
3. **Use Centralized Invalidation Primitives:** Call `conversationCachePolicies.*` rather than manually invalidating raw keys in components.
4. **No Browser Storage:** Never mirror persistent conversation records or message history to `localStorage` or `sessionStorage`.
5. **Handle 409 Generation Conflicts:** Catch `isTurnInProgressConflict(err)` to display in-flight generation banners and respect `getRetryAfterSeconds(err)`.
