## Executive Summary

This assessment evaluated data protection, conversation ownership boundaries, credential management, logging sanitization, and deletion propagation across the **Kynergy Intelligence** ecosystem.

The audit verified key enterprise defense-in-depth controls:

1. **Multi-Tenant Scoping by Default:** All conversation entities (`AiConversation`, `AiConversationTurn`, `AiConversationMessage`, `AiConversationCitation`, `AiMessageFeedback`) enforce compound unique constraints and foreign keys bound to `[id, tenant_id]`.
2. **Zero In-Memory Token Exposure on Web:** [auth-token-store.ts](file:///c:/Projects/kinergy-platform/apps/web/src/shared/auth/auth-token-store.ts) holds JWT access tokens strictly in memory, never persisting them to `localStorage`, `sessionStorage`, or cookies, mitigating token harvesting via XSS.
3. **Privacy-Preserving Telemetry & Observability:** [GenerationObservabilityService](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/rag/generation-observability.service.ts) and [RetrievalObservabilityService](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/retrieval/retrieval-observability.service.ts) anonymize user IDs using keyed HMAC-SHA256 pseudonyms (`usr_...`) and query texts using SHA-256 hashes (`queryHash`). Raw query text, chunk contents, vector floats, and secrets are strictly excluded from logs.
4. **Isolated Local Provider Boundary:** LLM inference and embedding vectorization run locally via loopback (`http://127.0.0.1:11434`), ensuring that patient inquiries, clinical documents, and conversation histories are never transmitted to external third-party cloud AI vendors.
5. **Decoupled Clinical Audit Retention:** [AiConversationAuditLog](file:///c:/Projects/kinergy-platform/prisma/schema.prisma#L1311-L1328) preserves a tamper-resistant record of privileged Owner inspections that survives conversation deletion, satisfying clinical and regulatory auditability requirements.

### Key Security Findings & Identified Risks

- **SEC06-F01 (Medium — CVSS 5.4): Same-Tenant Broken Object Level Authorization (BOLA/IDOR) on Title & Archive.** [ai-conversation.controller.ts](file:///c:/Projects/kinergy-platform/apps/api/src/ai/conversation/ai-conversation.controller.ts#L603-L647) verifies `tenantId`, but omits `conv.userId === actor.userId` in `PATCH :id/title` and `DELETE :id`. Any authenticated user in a tenant can rename or soft-delete peer users' conversations within the same tenant.
- **SEC06-F02 (Medium — CVSS 6.5): Hardcoded Fallback Secret in `PreviewTokenService`.** [preview-token.service.ts](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/preview-token.service.ts#L44-L48) falls back to `'kinergy-secure-document-preview-secret-salt-2026'` if `AI_PREVIEW_TOKEN_SECRET` and `JWT_SECRET` are unset, allowing signature forgery. Furthermore, `AI_PREVIEW_TOKEN_SECRET` is undocumented in [.env.example](file:///c:/Projects/kinergy-platform/.env.example).
- **SEC06-F03 (Low/Medium — CVSS 3.8): Persistent Unencrypted Conversation Cache in Browser `localStorage` on Shared Workstations.** [assistant-storage.service.ts](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/services/assistant-storage.service.ts#L12-L16) partitions cached conversations by `kinergy_conv_${tenantId}_${userId}`, but does not purge them upon logout, leaving clinical messages unencrypted on shared clinical terminals.

## 4. Provider Data-Flow Assessment

```
[ User Prompt & Preceding Turns ] ──┐
                                     ├──> Combined Prompt ──> HTTP POST ──> Ollama Service (127.0.0.1:11434)
[ Retrieved Knowledge Chunks ]    ──┘
```

1. **Data In Transit to Model:**
   - Preceding conversation turns (budgeted to max 10 turns, 500 tokens).
   - Retrieved evidence chunks (budgeted, whole-chunk dropped, wrapped in `<evidence_chunk>`).
   - User inquiry text.
2. **Data Excluded from Model Invocations:**
   - User database IDs, emails, patient names, gym membership IDs, and tenant IDs are **never** included in the prompt payload.
   - Authentication tokens, API keys, database connection strings, and storage credentials are never passed to Ollama.
3. **Local Deployment Isolation:**
   - Inference executes on-premise/locally via Ollama (`http://127.0.0.1:11434`).
   - Zero outbound requests are dispatched to external cloud LLMs (OpenAI, Anthropic, Google Cloud).
   - Zero training retention risk: local Ollama runtime does not retain or train on incoming inference prompts.

## 5. Logging and Auditability Assessment

### 5.1 Telemetry Privacy & Data Minimization

Both [GenerationObservabilityService](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/rag/generation-observability.service.ts) and [RetrievalObservabilityService](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/retrieval/retrieval-observability.service.ts) implement strict privacy-by-design guarantees:

- **HMAC-SHA256 User Pseudonymization:** User IDs are converted to irreversible pseudonyms:
  ```ts
  const userPseudonym = crypto
    .createHmac('sha256', tenantId)
    .update(userId)
    .digest('hex')
    .slice(0, 16);
  ```
- **Query Hashing:** Raw clinical text is never logged; logs record only `queryHash` (SHA-256) and `queryLength`.
- **Zero Raw Document Text:** Chunk content, document bodies, and vector arrays are completely absent from log events.
- **Trace Correlation:** Every generation and retrieval event stamps `requestId` and `correlationId` for end-to-end distributed tracing.

### 5.2 Clinical Audit Log Immutability

Privileged inspection of conversation history via `POST :id/audit-inspect` creates an immutable record in [AiConversationAuditLog](file:///c:/Projects/kinergy-platform/prisma/schema.prisma#L1311-L1328):

- Stamped with `inspectorUserId`, `inspectorRole`, `conversationOwnerUserId`, `reason`, `ipAddress`, and `userAgent`.
- Decoupled from `AiConversation` cascade deletion: records are preserved even if the conversation is subsequently soft-deleted or purged.

## 7. Cache and Session Isolation Findings

1. **Server-Side Cache Isolation:**
   - Kynergy Intelligence implements **zero** shared Redis or in-memory caches for query embeddings, retrieval results, or conversation turns.
   - Every semantic and lexical search executes directly against PostgreSQL.
   - Deletion of a document or conversation takes effect immediately on subsequent queries without cache invalidation delays.
2. **Client-Side Session Token Isolation:**
   - Access tokens reside exclusively in memory via [AuthTokenStore](file:///c:/Projects/kinergy-platform/apps/web/src/shared/auth/auth-token-store.ts).
   - Invoking `clearSession()` immediately invalidates all browser memory state.
3. **Client-Side `localStorage` Conversation Cache:**
   - [assistant-storage.service.ts](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/services/assistant-storage.service.ts) caches conversation history in `localStorage` keyed by `kinergy_conv_${tenantId}_${userId}`.
   - When a user logs out, the in-memory token is cleared, but the cached conversation data in `localStorage` remains intact.
   - On shared clinic terminals, an unauthorized individual with access to the browser's developer console can inspect `localStorage` and view cached clinical messages.
