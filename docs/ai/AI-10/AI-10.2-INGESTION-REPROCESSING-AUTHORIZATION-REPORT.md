## 1. Executive Summary

Milestone **AI-10.2-07** establishes formal guarantees ensuring that background document ingestion, chunk generation, embedding creation, reprocessing, and vector deletion jobs always execute against the authoritative ownership and tenant partition of the source document.

Background workers and queue listeners run decoupled from the initiating HTTP request context (`AuthenticatedUserPayload`). If background jobs trust payload parameters or execute with ambient administrative authority, malicious actors or stale workers could cross tenant boundaries, write chunks or vectors under forged scopes, or restore deleted knowledge artifacts.

During this milestone:

1. **Worker Execution Model Bound to Authoritative Persistence:** Verified that workers operate under a narrowly scoped system identity (`SystemDocumentWorker`). The worker never trusts incoming queue payloads for tenant, document, version, or user identity; all authorization parameters are loaded directly from the database `IngestionJob` and verified against the parent `KnowledgeDocument`.
2. **Multi-Stage Checkpoint Re-Validation:** Hardened [IngestionOrchestratorService](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/ingestion-orchestrator.service.ts) to re-evaluate parent document existence, non-deletion (`deletedAt IS NULL`), and tenant matching at every pipeline transition:
   - Prior to Stage 1 (`VALIDATING`)
   - Prior to Stage 2 (`PROCESSING` / text extraction & chunk persistence)
   - Prior to Stage 3 (`INDEXING` / embedding generation & vector persistence)
   - Prior to Stage 4 (`READY` / completion)
     If a document is soft-deleted out-of-band while a job is running or queued, the worker aborts immediately and fails closed, preventing stray chunks or vectors from being published.
3. **Tenant-Isolated Vector Cleanup:** Hardened [VectorCleanupService](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/indexing/vector-cleanup.service.ts), [PrismaVectorStoreRepository](file:///c:/Projects/kinergy-platform/packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-vector-store.repository.ts), and [PrismaVectorIndexingJobRepository](file:///c:/Projects/kinergy-platform/packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-vector-indexing-job.repository.ts) to enforce `tenantId` filtering during vector deletion and job cancellation. A cleanup job in Tenant Alpha can never mutate, cancel, or delete embeddings belonging to Tenant Beta.
4. **Reprocessing & Concurrency Protections:** Verified that `reprocessDocument` verifies manager clearance, enforces tenant boundaries, purges previous vectors under tenant scope, and blocks duplicate concurrent jobs. An in-memory execution guard (`inFlightJobs: Set<string>`) prevents concurrent duplicate execution of the same job on a single worker node.
5. **Comprehensive 10-Scenario Security Suite:** Implemented [ai-ingestion-tenant-safety.integration.spec.ts](file:///c:/Projects/kinergy-platform/apps/api/src/ai/__tests__/ai-ingestion-tenant-safety.integration.spec.ts) covering all required security scenarios with a 100% pass rate (11/11 tests passing in 8.6s). All regression test suites and base monorepo typecheck passed cleanly with zero errors.

## 2. Worker Execution Model & Invariant Architecture

```
+---------------------------------------------------------------------------------------------------+
|                                    WORKER AUTHORIZATION MODEL                                     |
+---------------------------------------------------------------------------------------------------+
| Queue Payload:  { jobId: string, tenantId?: string }                                              |
|                                                                                                   |
| Step 1: Database Lookup                                                                           |
|   - Fetch IngestionJob from DB: job = jobRepo.findById(tenantId, jobId)                           |
|   - authoritativeTenantId = job.tenantId                                                          |
|                                                                                                   |
| Step 2: Anti-BOLA / Payload Tampering Verification                                                |
|   - IF payload.tenantId != authoritativeTenantId -> ABORT with UnauthorizedDocumentAccessException |
|                                                                                                   |
| Step 3: Document State & Ownership Verification (Checked at EACH stage transition)               |
|   - document = documentRepo.findById(authoritativeTenantId, job.documentId)                       |
|   - IF !document OR document.isDeleted() -> ABORT permanently (DOCUMENT_NOT_FOUND)                 |
|   - IF document.tenantId != authoritativeTenantId -> ABORT (UnauthorizedDocumentAccessException)  |
|   - version = document.getVersionById(job.documentVersionId)                                      |
|   - IF !version -> ABORT permanently (DOCUMENT_NOT_FOUND)                                         |
|                                                                                                   |
| Step 4: Chunk & Vector Provenance Invariants                                                      |
|   - DocumentProcessingPipelineService: chunkRepo.saveChunks(authoritativeTenantId, ...)           |
|   - Composite Foreign Key: knowledge_chunks (document_id, tenant_id) -> knowledge_documents       |
|   - VectorIndexingOrchestratorService: vectorStore.saveBatch(authoritativeTenantId, ...)          |
|   - Composite Integrity: verifies chunk existence, document existence, and tenant match          |
+---------------------------------------------------------------------------------------------------+
```

### Authorization Invariants Matrix

| Invariant                    | Description                                                                          | Enforcement Mechanism                                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| **Authoritative Derivation** | Job tenant and document ownership are never read from queue payloads.                | Read strictly from the database `ingestion_jobs` row and parent `knowledge_documents` aggregate root.                                |
| **Payload Anti-Tampering**   | Forged tenant routing hints cannot override or cross tenant scope.                   | Orchestrator verifies `suppliedTenant === job.tenantId`; fails closed with `UnauthorizedDocumentAccessException`.                    |
| **Multi-Stage Checkpoints**  | Out-of-band deletion aborts processing before chunk or vector generation.            | Document lookup and `!doc.isDeleted()` check executed at `VALIDATING`, `PROCESSING`, `INDEXING`, and `READY`.                        |
| **Relational Cascade & FK**  | Chunks and vectors cannot exist under mismatched documents or tenants.               | PostgreSQL composite foreign key `[documentId, tenantId]` on `knowledge_chunks` and `document_embeddings`.                           |
| **Reprocessing Safety**      | Reprocess jobs inherit the original document's tenant context and purge old vectors. | `reprocessDocument` validates caller management clearance, calls `cleanupDocumentVectors(tenantId, docId)`, and creates a clean job. |
| **Deletion Isolation**       | Deleting vectors in Tenant Alpha cannot affect vectors in Tenant Beta.               | `VectorCleanupService` passes `tenantId` to `deleteByDocumentId` and `cancelJobsForDocument`, scoped at the database level.          |
| **Concurrency Guard**        | Concurrent executions cannot corrupt in-flight state.                                | `inFlightJobs` memory set prevents duplicate concurrent job execution; database version lock prevents race conditions.               |
| **No Credential Exposure**   | Worker logs never leak document content, chunk text, or credentials.                 | Log statements output only IDs, formats, token counts, and error codes.                                                              |

## 3. Implementation Hardening Walkthrough

### 3.1. Stage Checkpoint Re-Validation in `IngestionOrchestratorService`

**Location:** `apps/api/src/ai/services/ingestion-orchestrator.service.ts`

**Changes Applied:**
Added authoritative document state and tenant boundary checks before Stage 2 (`PROCESSING`), Stage 3 (`INDEXING`), and Stage 4 (`READY`):

```typescript
// Stage 2: PROCESSING checkpoint
const docProcessing = await this.documentRepo.findById(tId, job.documentId);
if (!docProcessing || docProcessing.isDeleted()) {
  throw new Error(`Referenced document '${job.documentId}' does not exist or was deleted.`);
}
if (docProcessing.tenantId !== tId) {
  throw new UnauthorizedDocumentAccessException(
    `Document tenant '${docProcessing.tenantId}' does not match job tenant '${tId}'.`,
  );
}

// Stage 3: INDEXING checkpoint
const docIndexing = await this.documentRepo.findById(tId, job.documentId);
if (!docIndexing || docIndexing.isDeleted()) {
  throw new Error(`Referenced document '${job.documentId}' does not exist or was deleted.`);
}
if (docIndexing.tenantId !== tId) {
  throw new UnauthorizedDocumentAccessException(
    `Document tenant '${docIndexing.tenantId}' does not match job tenant '${tId}'.`,
  );
}

// Stage 4: READY checkpoint
const docReady = await this.documentRepo.findById(tId, job.documentId);
if (!docReady || docReady.isDeleted()) {
  throw new Error(`Referenced document '${job.documentId}' was deleted before completion.`);
}
```

## 6. Operational Rollout Considerations

1. **Watchdog Backoff & Limits:** `IngestionRecoveryWorker` runs with a 15-second poll interval and a 5-minute stale threshold. Stalled jobs are scheduled with exponential backoff up to `maxAttempts = 3`. When max attempts are exhausted, jobs enter `MAX_ATTEMPTS_EXCEEDED` without retrying infinitely.
2. **Database Transactions vs External API Calls:** Vector generation via external embedding providers occurs outside relational transactions to avoid holding PostgreSQL connection pools open during network I/O. Vector insertions in `saveBatch` execute atomically within an isolated transaction.
3. **Audit Log Sanitization:** Ingestion error messages log only error codes and system reasons; raw extracted text, user prompts, and storage credentials are never included in worker log messages.
