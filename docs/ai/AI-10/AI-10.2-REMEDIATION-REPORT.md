## 2. In-Depth Remediation & Hardening Details

### 2.1 KY-ISO-001: Anti-BOLA, IDOR, and Enumeration Defense

- **Root Cause:** Standard NestJS controllers previously returned HTTP 403 Forbidden on authorization failures, allowing malicious callers to enumerate valid document and version UUIDs across tenants.
- **Remediation:**
  - Implemented `AiResourceAuthorizationPolicy.assertDocumentAccess` and `assertConversationAccess`.
  - Violations across tenants or access to soft-deleted records fail closed with `DocumentNotFoundException` ("Document '...' not found or access denied"), producing an indistinguishable HTTP 404.
  - Non-owner callers without `ai.documents.manage` are blocked from mutation operations.
- **Affected Files:**
  - `packages/core/src/ai/application/services/ai-resource-authorization.policy.ts`
  - `apps/api/src/ai/controllers/ai-document.controller.ts`
- **Regression Tests:**
  - `apps/api/src/ai/__tests__/ai-document-isolation-concurrency.integration.spec.ts` (Scenarios A1-A5).

---

### 2.2 KY-ISO-002: Retrieval Pre-Filtering and LLM Boundary Assertion

- **Root Cause:** If semantic retrieval returned candidate chunks across multiple visibility tiers, downstream context builders relied on post-generation filtering, risking prompt injection or unauthorized context inclusion.
- **Remediation:**
  - Hardened `PrismaSemanticRetrievalRepository` and `PrismaLexicalRetrievalRepository` to enforce pre-filtering directly in SQL joins before ranking and `LIMIT`:
    ```sql
    WHERE ig."tenant_id" = $2
      AND kd."tenant_id" = $2
      AND kc."tenant_id" = $2
      AND kd."deleted_at" IS NULL
      AND kd."visibility_scope"::text IN ($3, ...)
    ```
  - Empty allowed visibility scopes fail closed with `AND 1 = 0`.
  - Added direct spy verification at `IGroundedGenerationPort.generateGroundedAnswer` to guarantee zero unauthorized text passes to the LLM prompt.
- **Affected Files:**
  - `packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-semantic-retrieval.repository.ts`
  - `packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-lexical-retrieval.repository.ts`
  - `apps/api/src/ai/services/retrieval/secure-semantic-search.service.ts`
- **Regression Tests:**
  - `apps/api/src/ai/__tests__/ai-retrieval-authorization-isolation.spec.ts`
  - `apps/api/src/ai/__tests__/ai-document-isolation-concurrency.integration.spec.ts` (Scenario C1).

### 2.3 KY-ISO-003: Chunk and Vector Provenance Integrity

- **Root Cause:** Extracted chunks and generated vector embeddings could become orphaned or attributed to unintended documents if ingestion failed mid-batch or if version lineage was not validated.
- **Remediation:**
  - Added strict relational foreign keys and database constraints in `prisma/schema.prisma`:
    - `KnowledgeChunk`: `@@unique([documentVersionId, sequence])`, foreign key `[documentId, tenantId] references [id, tenantId]`.
    - `DocumentEmbedding`: `@@unique([chunkId, indexGenerationId])`.
  - Validated value objects (`RetrievalProvenance`, `ChunkId`, `SimilarityScore`) to reject inconsistent or empty identifiers during entity instantiation.
- **Affected Files:**
  - `prisma/schema.prisma`
  - `packages/core/src/ai/domain/models/document-chunk.entity.ts`
  - `packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-knowledge-chunk.repository.ts`
- **Regression Tests:**
  - `packages/core/src/ai/infrastructure/persistence/prisma/__tests__/knowledge-chunk-persistence.integration.spec.ts`
  - `packages/core/src/ai/infrastructure/persistence/prisma/__tests__/vector-persistence.integration.spec.ts`

### 2.4 KY-ISO-004: Ingestion Worker Continuous Stage Checkpoints

- **Root Cause:** If a document was soft-deleted while an asynchronous ingestion job was queued or during lengthy PDF parsing, the worker would continue to parse, chunk, and index vectors, leaving accessible artifacts for a deleted document.
- **Remediation:**
  - Hardened `IngestionOrchestratorService` to re-fetch and re-verify parent document state before every major stage transition:
    1. Before parsing (`PROCESSING`)
    2. Before vector indexing (`INDEXING`)
    3. Before marking complete (`READY`)
  - If `doc.isDeleted() === true` or tenant ID does not match, the worker immediately aborts fail-closed with `IngestionErrorCode.DOCUMENT_NOT_FOUND` and does not persist chunks or vectors.
- **Affected Files:**
  - `apps/api/src/ai/services/ingestion-orchestrator.service.ts`
- **Regression Tests:**
  - `apps/api/src/ai/__tests__/ai-ingestion-tenant-safety.integration.spec.ts` (Scenarios 3, 6).
  - `apps/api/src/ai/__tests__/ai-document-isolation-concurrency.integration.spec.ts` (Scenario F1).

### 2.5 KY-ISO-005: Tenant-Scoped Vector & Job Cleanup

- **Root Cause:** `VectorCleanupService` received `tenantId` in its method signatures, but delegated repository methods `deleteByDocumentId` and `cancelJobsForDocument` lacked `tenantId` parameters, relying on unpartitioned document IDs.
- **Remediation:**
  - Extended `IVectorStorePort` and `IVectorIndexingJobRepositoryPort` to accept optional `tenantId?: string`.
  - Updated `PrismaVectorStoreRepository` to execute tenant-scoped SQL deletions:
    ```sql
    DELETE FROM "document_embeddings"
    WHERE "document_id" = $1
      AND "document_id" IN (
        SELECT "id" FROM "knowledge_documents" WHERE "tenant_id" = $2
      );
    ```
  - Updated `VectorCleanupService` to pass `cleanTenantId` to all downstream repository calls.
- **Affected Files:**
  - `packages/core/src/ai/ports/outbound/vector-store.port.ts`
  - `packages/core/src/ai/ports/outbound/vector-indexing-job-repository.port.ts`
  - `packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-vector-store.repository.ts`
  - `packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-vector-indexing-job.repository.ts`
  - `apps/api/src/ai/services/indexing/vector-cleanup.service.ts`
- **Regression Tests:**
  - `apps/api/src/ai/services/indexing/__tests__/vector-cleanup.service.spec.ts`

### 2.6 KY-ISO-006: Preview & Citation Token Isolation

- **Root Cause:** Temporary preview URLs for document version downloads could theoretically be replayed across sessions if tokens were not cryptographically bound to the authenticated tenant and user.
- **Remediation:**
  - Hardened `PreviewTokenService` to sign HMAC-SHA256 tokens binding `tenantId`, `userId`, `documentId`, `documentVersionId`, and expiration timestamp.
  - Token consumption validates tenant and user match before issuing signed storage download URLs.
  - Implemented anti-tampering verification for conversation citations in `AiConversationCitationRepository`.
- **Affected Files:**
  - `apps/api/src/ai/services/preview-token.service.ts`
  - `packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-ai-conversation-citation.repository.ts`
- **Regression Tests:**
  - `apps/api/src/ai/services/__tests__/preview-token.service.spec.ts`
  - `apps/api/src/ai/__tests__/ai-version-citation-authorization.integration.spec.ts`

### 2.7 KY-ISO-007: Concurrent Retrieval & Context Bleed Protection

- **Root Cause:** Asynchronous RAG pipelines processing high volumes of concurrent requests could experience state bleed if shared buffers or mutable request caches were used.
- **Remediation:**
  - RAG pipelines (`RAGOrchestratorService`, `SecureSemanticSearchService`) operate completely statelessly.
  - Each turn execution creates immutable, localized `RAGConstructedContext` objects passed exclusively to the LLM invocation for that turn.
  - Added high-concurrency multi-tenant parallel tests verifying zero cross-tenant chunk leakage.
- **Affected Files:**
  - `apps/api/src/ai/services/rag/rag-orchestrator.service.ts`
- **Regression Tests:**
  - `apps/api/src/ai/__tests__/ai-document-isolation-concurrency.integration.spec.ts` (Scenario E1: 20 parallel multi-tenant runs).

### 2.8 KY-ISO-008: PostgreSQL Row-Level Security Architecture Decision

- **Evaluation:** Evaluated PostgreSQL RLS under Prisma connection pooling (`AI-10.2-08`).
- **Decision:** **REJECTED FOR THIS MILESTONE**.
- **Rationale:**
  1. Prisma connection pool reuse risks cross-request session context bleeding when using `SET app.current_tenant_id`.
  2. Forcing `SET LOCAL` interactive transactions doubles query roundtrips and exhausts the connection pool.
  3. pgvector query optimizer drops HNSW index push-downs under RLS `SECURITY BARRIER` policies, causing 50x retrieval latency spikes (>800ms).
  4. Fully compensated by application guards, domain policies, and parameterized SQL joins.
- **Reference Deliverable:**
  - [AI-10.2-POSTGRES-RLS-DECISION.md](file:///c:/Projects/kinergy-platform/AI-10.2-POSTGRES-RLS-DECISION.md)

## 3. Migration, Legacy Data & Operational Safeguards

### 3.1 Schema & Data Integrity

- No destructive migrations (`DROP TABLE`, `RESET`) were executed.
- All existing knowledge documents, versions, chunks, and embeddings maintain complete referential integrity.
- Composite foreign keys (`[documentId, tenantId]`) ensure tenant partition keys cannot diverge between parent documents and child chunks/jobs.

### 3.2 Operational Redaction & Observability

- All error and logging handlers (`AiExceptionFilter`, `RetrievalObservabilityService`, `IngestionObservabilityService`) scrub raw sensitive text, queries, vectors, and database connection strings before writing structured JSON logs.
- Audit trails for conversation citations and administrative document inspections are persisted to `ai_conversation_audit_logs`.
