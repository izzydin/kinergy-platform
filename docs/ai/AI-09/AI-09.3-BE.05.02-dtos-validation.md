## 1. Executive Summary

Task `AI-09.3-BE.05.02` establishes strongly typed, validated request and response contracts for the AI conversation REST API in `apps/api`. It ensures external payloads are strictly validated before entering the application use cases, connects custom validators with the NestJS global validation pipeline (`GlobalSanitizationValidationPipe`), implements pure response mappers, strictly enforces internal field exclusion policies (preventing information leakage), and verifies all edge cases through comprehensive test suites.

### Key Guarantees Implemented:

1. **Strict Input Validation & Non-Bypassability:** All incoming payloads undergo strict validation via `class-validator`, custom decorators (`@IsNotBlank`, `@IsValidConversationListCursor`, `@IsValidMessageHistoryCursor`), and NestJS `ValidationPipe` (`whitelist: true, forbidNonWhitelisted: true`).
2. **Zero Trust for Client-Supplied Identifiers:** Tenant ID and actor ID cannot be passed or overridden in request DTOs. Identity is authoritatively extracted from verified JWT/session claims by `@TrustedAi()`.
3. **Idempotency Semantic Preservation:** Prompts and turn identifiers are neither silently transformed nor trimmed in a manner that obscures payload changes. Hashing remains canonical in the application layer.
4. **Information Leakage Prevention:** Pure response mappers strip internal hashes (`idempotencyPayloadHash`), lease tokens, database transaction IDs, raw persistence records, and internal metadata from all API responses.
5. **Cursor Integrity:** Message history pagination strictly enforces immutable sequence-based cursors (`MessageHistoryCursor`), rejecting mutable activity-timestamp cursors (`ConversationListCursor`) or malformed strings.

## 3. Transformation & Sanitization Behavior

Validation and transformation occur through the enterprise global pipeline:

- **Sanitization:** [GlobalSanitizationValidationPipe](file:///c:/Projects/kinergy-platform/apps/api/src/common/pipes/global-sanitization-validation.pipe.ts) strips dangerous ASCII control characters (`\u0000-\u0008`, `\u000B-\u000C`, `\u000E-\u001F`, `\u007F-\u009F`) to prevent injection attacks while preserving valid newlines (`\n`) and tabs (`\t`) in user prompts.
- **Strict Typing:** Query parameters (`limit`, `includeArchived`) use explicit `@Type` decorators (`@Type(() => Number)`, `@Type(() => Boolean)`) to avoid permissive type coersion.
- **Forbid Non-Whitelisted:** Unrecognized properties (such as client-supplied `tenantId`, `role`, or `status`) trigger an immediate `400 Bad Request` rejection (`property <x> should not exist`).

## 4. Cursor Validation & Pagination Rules

1. **Conversation List Pagination:**
   - Evaluated by `@IsValidConversationListCursor()`.
   - Cursor must decode via `ConversationListCursor.decode(cursor)` into `{ a: string, id: string }`.
   - Rejects non-base64url strings, non-JSON payloads, or missing ISO activity timestamps.
2. **Message History Pagination:**
   - Evaluated by `@IsValidMessageHistoryCursor()`.
   - Cursor must decode via `MessageHistoryCursor.decode(cursor)` into `{ s: number, id: string }` where `s` is a positive integer.
   - **Crucial Rule:** If a client passes an activity-timestamp cursor (`a`) to the message history endpoint, validation immediately rejects it, maintaining sequence-based immutability.
   - Limit is capped strictly between `1` and `100`.
