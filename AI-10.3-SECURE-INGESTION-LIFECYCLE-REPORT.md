## 1. Executive Summary

Milestone **AI-10.3-07** unifies and enforces all upstream security defenses—including upload admission validation, storage isolation, malware threat scanning, ZIP-bomb defense, parser sandbox execution, and strict provenance binding—into Kynergy's end-to-end ingestion and knowledge publication lifecycle.

Prior to this milestone, ingestion orchestrations could theoretically attempt parsing or chunking on storage objects without re-verifying binary integrity or checking for background quarantine events, and retries could inadvertently attempt reprocessing on terminal security violations.

Under the hardened architecture:

1. **Strict Admission Gatekeeper:** `IngestionOrchestratorService` acts as the authoritative gatekeeper. Before any parser or extractor executes, the system validates storage existence, recalculates and asserts cryptographic SHA-256 integrity against the authoritative document version record, validates format magic bytes, and executes malware threat analysis.
2. **Fail-Closed Malware Quarantine:** Any document identified as infected or suspicious during orchestration triggers immediate document quarantine via soft-deletion (`SYSTEM_MALWARE_QUARANTINE`) and emits an unretryable `SECURITY_VIOLATION`. This immediately revokes retrieval eligibility from candidate pools in PostgreSQL (`kd.deleted_at IS NULL`) and `RetrievalSecurityPolicyService`.
3. **Safe Extraction & Sanitization:** Text extraction runs in a memory-bounded sandbox (`ParserSandboxService`) with a 30-second timeout, 5,000,000-character truncation ceiling, control character/ANSI stripping, zero external network fetching (SSRF prevention), and safe synthetic storage paths (`knowledge_base/{uuid}.ext`).
4. **Authoritative Chunk Provenance & Anti-Forging:** Extracted text is treated as purely untrusted data. Any metadata embedded in document content (such as forged tenant claims, mock owner IDs, or false visibility markers) is strictly ignored. Every chunk persisted to PostgreSQL binds immutably to the authoritative backend context (`tenantId`, `documentId`, `documentVersionId`, `sequenceNumber`).
5. **Atomic Publication & Non-Retryable Security Violations:** Retrieval clearance requires `IngestionStatus.READY`, active document status (`deleted_at IS NULL`), and matching visibility scope clearance. Failures during vector indexing or chunk persistence fail the job without transitioning to `READY`. Security violations, checksum tampering, and corrupt content are classified as terminal non-retryable errors, prohibiting automated retries.

## 2. Ingestion Lifecycle Architecture & Security Checkpoints

```
[ Upload Admission ]
       │
       ▼ (Passes size, MIME, magic bytes, initial scan)
[ Object Storage: knowledge_base/{uuid}.ext ]
       │
       ▼ (IngestionJob UPLOADED -> VALIDATING)
[ Ingestion Orchestrator Admission Gate ]
   ├─► 1. Assert Tenant Authorization (Anti-BOLA)
   ├─► 2. Verify Document & Version exist and are Active (!isDeleted)
   ├─► 3. Download Buffer & Compute Cryptographic SHA-256 Checksum
   │      └─► Tampered / Mismatched? ──► Fail [CHECKSUM_MISMATCH] (Terminal)
   ├─► 4. Deep Content Format & Magic Byte Validation
   │      └─► Invalid format? ─────────► Fail [UNSUPPORTED_FORMAT] (Terminal)
   └─► 5. Malware & Threat Scanner Execution
          ├─► Infected / Suspicious? ──► Soft-Delete Document (QUARANTINE)
          │                              Fail [SECURITY_VIOLATION] (Terminal)
          └─► Unscannable / Error? ────► Fail closed [SECURITY_VIOLATION] (Terminal)
       │
       ▼ (Transition to PROCESSING)
[ Parser Sandbox & Document Pipeline ]
   ├─► Bounded Subprocess / Native Memory (30s timeout, 5M char limit)
   ├─► Zero External Network Fetching (SSRF-immune)
   ├─► Output Sanitization (Control characters, ANSI codes, script tags stripped)
   ├─► Normalization & Structure-Aware Chunking
   └─► Enforce Provenance Invariants (authoritative tenantId, documentId, versionId)
       │
       ▼ (Transition to INDEXING)
[ Knowledge Publication & Vector Indexing ]
   ├─► Downstream Vector Indexing (indexDocument)
   │      └─► Vector persistence failure? ──► Fail [STORAGE_TIMEOUT / UNKNOWN] (Never READY)
   └─► Complete Ingestion ──► IngestionStatus.READY
       │
       ▼
[ Retrieval Security & Citation Authorization ]
   ├─► SQL Filtering: kd.deleted_at IS NULL AND kd.tenant_id = :tenantId
   ├─► Status Verification: doc.status !== 'QUARANTINED' && doc.status !== 'FAILED'
   └─► Scope Resolution: User visibility scopes intersect document visibility scope
```

## 3. Detailed Security Invariants & Implementations

### 3.1 Authoritative Admission Points & Checksum Verification

- **Location:** [`apps/api/src/ai/services/ingestion-orchestrator.service.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/ingestion-orchestrator.service.ts)
- **Mechanisms:**
  - Before transitioning from `VALIDATING` to `PROCESSING`, the orchestrator downloads the stored binary stream into memory and recalculates the SHA-256 digest using `crypto.createHash('sha256')`.
  - If the computed digest does not match `version.checksum`, the orchestrator immediately logs `[SECURITY] Checksum mismatch` and aborts with `IngestionErrorCode.CHECKSUM_MISMATCH`.
  - Next, `contentValidator.validate(...)` inspects magic bytes, validating that the binary payload has not been swapped or corrupted after upload.
  - Finally, `malwareScanner.scanBuffer(...)` executes. If any threat or suspicious signature is detected, `document.softDelete('SYSTEM_MALWARE_QUARANTINE')` is executed immediately in the database, the document is quarantined, and the job transitions to `FAILED` with `IngestionErrorCode.SECURITY_VIOLATION`.

### 3.2 Terminal Security Errors and Non-Retryable Policy

- **Location:** [`apps/api/src/ai/services/ingestion-retry.policy.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/ingestion-retry.policy.ts) and [`apps/api/src/ai/controllers/ai-document.controller.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/controllers/ai-document.controller.ts)
- **Mechanisms:**
  - `IngestionRetryPolicy.classifyError` places security violations (`DocumentSecurityRiskException`, `malware`, `quarantine`, `infected`, `unauthorized`, `forbidden`, `deleted`) at highest precedence, tagging them with `isRetryable: false`.
  - Checksum mismatches (`CHECKSUM_MISMATCH`) and content format mismatches (`UNSUPPORTED_FORMAT`, `MALFORMED_CONTENT`) are strictly non-retryable.
  - In `AiDocumentController.retryCurrentIngestion` and `retryVersionIngestion`, API callers attempting to retry jobs whose `lastErrorCode` is `SECURITY_VIOLATION`, `CHECKSUM_MISMATCH`, or `MALFORMED_CONTENT` are rejected with `400 Bad Request`.

### 3.3 Provenance Invariants & Resistance to Forged Metadata

- **Location:** [`apps/api/src/ai/services/document-processing-pipeline.service.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/document-processing-pipeline.service.ts)
- **Mechanisms:**
  - Chunks generated during structure-aware chunking receive metadata exclusively derived from the authoritative `ProcessDocumentOptions` passed by the backend caller.
  - A post-chunking provenance verification check asserts that every chunk's `documentId` and `documentVersionId` exactly match the authoritative version.
  - Persisted chunks stored in PostgreSQL via `IKnowledgeChunkRepositoryPort.saveChunks` use the authoritative `tenantId` from the authenticated job context. Malicious strings or JSON snippets in document bodies claiming different tenant or owner identities are treated as inert plaintext and have zero effect on chunk tenancy or database partitioning.

### 3.4 Atomic Publication & Immediate Retrieval Revocation

- **Location:** [`packages/core/src/ai/application/services/ai-resource-authorization.policy.ts`](file:///c:/Projects/kinergy-platform/packages/core/src/ai/application/services/ai-resource-authorization.policy.ts) and [`apps/api/src/ai/services/retrieval/retrieval-security-policy.service.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/retrieval/retrieval-security-policy.service.ts)
- **Mechanisms:**
  - A document only becomes eligible as a knowledge source if all pipeline stages succeed and its status reaches `READY`.
  - Partial pipeline execution (such as chunk generation succeeding but vector indexing timing out) aborts without marking the job `READY`, leaving the document unretrievable.
  - If a document is soft-deleted or quarantined at any point in time, `RetrievalSecurityPolicyService.resolveAuthorizedDocumentIds` drops it from candidate pools immediately, returning `isDenied: true` and an empty authorization list.

## 6. Milestone Conclusion

Milestone **AI-10.3-07** establishes an impenetrable, fail-closed ingestion lifecycle for Kynergy. Content entering the RAG system must pass cryptographic checksum verification, deep format structure validation, and malware scanning before parser execution. Extracted text is isolated from application privileges, chunks strictly preserve backend tenant and document provenance, and soft-deletion or quarantine revokes retrieval clearance instantaneously across the platform.
