## 1. Executive Summary

Milestone **FE.03** delivers reliable, server-authoritative conversation creation and seamless integration with the existing Kynergy Intelligence chat interface.

Building directly upon the verified HTTP API persistence layer (FE.01) and the TanStack Query cache architecture (FE.02), FE.03 establishes:

1. **Server-Authoritative Creation:** Conversations are created and persisted by the backend in PostgreSQL via `POST /api/v1/ai/conversations`, deriving ownership exclusively from the trusted server-side authentication context (`TrustedAiContext`).
2. **Preservation of Established Creation Lifecycle:** The existing AI-09.2 flow (lazy conversation creation on first message submission) is preserved and connected to the backend persistence layer. Clicking "New Conversation" places the UI into a clean draft state at `/intelligence/chat` without generating empty database records.
3. **Atomic First-Turn Integration:** The first user prompt atomically creates the conversation aggregate, initial turn, user message, and assistant attempt in PostgreSQL.
4. **Authoritative Identification & Route Transition:** The browser never generates authoritative conversation IDs. Upon receiving the backend's persistent UUID, the frontend reconciles the query cache and transitions the browser URL to `/intelligence/chat/${conversationId}` via `navigate(..., { replace: true })`.
5. **Duplicate-Submission Protection & Idempotent Retries:** Single-flight mutex locking prevents concurrent duplicate submissions from rapid clicks. The client-managed `clientTurnId` remains stable across retries, enabling the backend's BE.04/BE.05 idempotency mechanism to safely recover existing turns without re-generating duplicates.
6. **Graceful Error Handling & Draft Retention:** If creation fails (e.g., network error or 400 validation error), the user's prompt is preserved in the composer (never discarded), and the mutex lock is released to allow an immediate retry.
7. **100% Quality Gates Cleared:** All 17 assistant test suites pass (188/188 tests, 100% pass rate), TypeScript typecheck passes with 0 errors, ESLint passes with 0 warnings, Vite production build succeeds (11.94s), and Prettier code style checks pass cleanly.

## 2. Repository Investigation & Creation Lifecycle Architecture

### 2.1 Investigation Findings

- **Creation Timing:** In the Kynergy Intelligence subsystem, conversations start lazily on the first message submission.
- **Why Lazy Creation is Authoritative:** The backend use case (`CreateConversationWithInitialTurnUseCase`) requires an initial prompt and `clientTurnId`. This prevents abandoned, zero-message conversations from polluting PostgreSQL or the sidebar.
- **New Conversation Action:** Clicking "Nueva Conversación" in [`conversation-sidebar.tsx`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/components/conversation-sidebar.tsx) or [`chat-workspace.tsx`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/components/chat-workspace.tsx) routes to `/intelligence/chat`, resetting the active conversation state to the clean draft workspace.
- **First Message Execution:** Submitting a prompt while at `/intelligence/chat` initiates `POST /api/v1/ai/conversations`.

### 4.1 Dedicated Creation Hook ([`use-conversation-creation.ts`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/hooks/use-conversation-creation.ts))

The `useConversationCreation` hook encapsulates:

- **State Machine:** Explicit states `idle` $\to$ `creating` $\to$ `success` / `error`.
- **Single-Flight Mutex:** `isCreatingMutexRef` blocks concurrent calls, throwing `"Ya existe una creación de conversación en curso."` on rapid duplicate clicks.
- **Authoritative Reconciliation:** Dispatches to `conversationApi.createConversation(request)`, invalidates `conversationQueryKeys.lists(scope)`, and sets the created conversation in hook state.
- **Stable Idempotent Retry:** `retry()` re-executes with the exact same `clientTurnId`, recovering the turn if already received by the server.
