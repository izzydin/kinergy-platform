## 4. Consolidated End-to-End Workflows (BE.07.07 Execution)

Suite `apps/api/src/ai/__tests__/ai-be07-final-acceptance.spec.ts` exercises the complete integrated system through realistic, multi-layered workflows:

### Workflow A: Full Multiturn Generation Lifecycle

- **Turn 1**: An authenticated principal initiates a conversation with an initial user turn. The controller creates the conversation and reserves the turn atomically in PostgreSQL (`status: PENDING`). Asynchronous dispatch triggers the execution use case, loads canonical context, invokes AI-08 RAG retrieval, generates a grounded answer, validates citations, deduplicates sources via `AiSourceAttributionService`, and atomically finalizes the assistant message (`status: SUCCESS`) and turn (`status: COMPLETED`).
- **Turn 2**: A subsequent turn is reserved on the same conversation. Preceding history loading in PostgreSQL retrieves Turn 1 as canonical context. Turn 2 generates and finalizes with `sequenceNumber: 2` and strictly isolated source attributions.
- **Verification**: Zero direct persistence bypass; sequences strictly increment (1, 2); exactly one canonical assistant message per turn.

### Workflow B: Stalled Worker Lease Expiry & Autonomous Recovery

- **Failure Simulation**: An active generation attempt is created with `status: STREAMING` and lease expiration set in the past (`leaseExpiresAt = now - 10s`). The in-flight worker is terminated.
- **Autonomous Recovery**: The background recovery worker (`AiTurnGenerationWorker`) polls PostgreSQL, identifies the expired lease, reclaims ownership with a fresh lease token, and increments `activeAttemptNumber` to 2.
- **Fencing**: The recovered attempt is dispatched to `ExecuteConversationTurnUseCase` and completes successfully. Database check constraints confirm lease fields are cleared upon completion.

### Workflow C: Concurrent Conflicting Operations & Fencing

- **Race Condition**: A turn is executing when a client issues a cancellation request (`POST /turns/:turnId/cancel`).
- **Resolution**: The cancellation commits atomically to PostgreSQL, marking the turn `CANCELLED` and attempt `CANCELLED`. When the simulated in-flight worker attempts to finalize its generation result, the finalization transaction detects the terminal turn status and rejects the stale write.
- **Fencing Invariant**: The cancelled turn is never overwritten by late LLM responses.

### Workflow D: Idempotent Retries & Cross-Tenant Rejection

- **Exact Replay**: Submitting the identical `clientTurnId` and payload returns the existing turn and conversation with `isIdempotentReplay: true`, without creating new database rows or re-dispatching LLM generation.
- **Conflict Rejection**: Submitting the same `clientTurnId` with altered prompt content returns HTTP 409 Conflict with code `IDEMPOTENCY_CONFLICT`.
- **Tenant Isolation**: A user belonging to Tenant B submitting a turn reservation targeting Tenant A's conversation receives HTTP 404 `ConversationNotFoundError`.

### Task 6: PostgreSQL Database Invariant Verification

Direct SQL queries on PostgreSQL validated:

- `chk_terminal_attempt_no_active_lease`: Terminal messages (`SUCCESS`, `FAILED`, `CANCELLED`, `INTERRUPTED`) strictly require `lease_token IS NULL`, `lease_owner_instance_id IS NULL`, `lease_expires_at IS NULL`.
- `chk_canonical_requires_success`: Messages with `is_canonical = true` strictly require `status = 'SUCCESS'`.
- `uq_turn_single_canonical_assistant`: At most one canonical assistant message exists per turn.
- `ai_conversation_active_generation_idx`: At most one active generation attempt (`PENDING` or `STREAMING`) exists per conversation.
- Cascade integrity: Deleting a conversation cleanly deletes all turns, messages, and audit logs.

## 7. Operational Limits, Deferred Considerations & Risks

1. **In-Memory Worker Registry on Single Nodes**:
   - `AiTurnDispatcherService` deduplicates in-flight dispatches in memory for efficiency on a given node.
   - _Cross-Node Guarantee:_ In distributed deployments, cross-instance deduplication and fencing are authoritatively enforced by PostgreSQL partial unique index `ai_conversation_active_generation_idx` and attempt number checks.
2. **Lease Expiry Duration**:
   - The default lease timeout is 5 minutes. Operations taking longer than 5 minutes without heartbeat updates will be marked stale and subject to recovery. Fencing prevents split-brain writes.
3. **Audit Log Persistence Dependency**:
   - Privileged audit inspection strictly requires a functioning database connection to write the audit trail. If the database cannot write the log, inspection aborts and returns no data.
