## 1. Executive Summary

Task `AI-09.3-BE.05.01` establishes the NestJS REST API foundation for AI conversation management in `apps/api`. It integrates the completed `BE.04` application use cases into NestJS dependency injection, guarantees trusted authentication and tenant context extraction, provides clean exception filtering mapping application errors to standard HTTP responses, and exposes OpenAPI-documented route structures without compromising Clean Architecture boundaries.

### Key Architectural Boundaries Preserved:

1. **Zero Database / Prisma Coupling in Controllers:** Controllers consume only use-case interfaces and domain types exported from `@kinergy-platform/core`. No database entities, query parameters, or Prisma classes leak into the presentation layer.
2. **Strict Server-Only Persistence Providers:** Prisma repositories and transaction runners from `@kinergy-platform/core/server` are instantiated exclusively within [ai-conversation.providers.ts](file:///c:/Projects/kinergy-platform/apps/api/src/ai/conversation/providers/ai-conversation.providers.ts) using NestJS factory providers.
3. **No Business Logic in Controllers:** Controllers act solely as HTTP dispatchers: extracting trusted claims via `@TrustedAi()`, passing validated inputs to use cases, and mapping results to strongly typed response DTOs.
4. **Trusted Authentication Context:** Tenant ID and Actor ID are never accepted from request query parameters or request body for authorization/scoping. The `@TrustedAi()` decorator asserts identity from the verified session or JWT (`request.user` or `RequestContext`).
5. **No Token Leaks or Internal Stacks:** All exceptions are filtered through [ai-conversation-exception.filter.ts](file:///c:/Projects/kinergy-platform/apps/api/src/ai/conversation/filters/ai-conversation-exception.filter.ts), redacting internal database stacks, SQL statements, and prompt content.

## 3. Trusted Authentication Context & Tenant Isolation

Identity claims extraction is handled by [@TrustedAi()](file:///c:/Projects/kinergy-platform/apps/api/src/ai/conversation/decorators/trusted-ai-context.decorator.ts):

```typescript
export interface TrustedAiContext {
  readonly actorId: string;
  readonly tenantId: string;
  readonly roles: readonly string[];
  readonly permissions: readonly string[];
  readonly email?: string;
}
```

### Invariants Enforced:

- If `request.user` is undefined or missing, throws `UnauthorizedException('AI conversation operations require an authenticated user context')`.
- If `actorId` or `sub` is missing or whitespace-only, throws `UnauthorizedException('User identity missing from authenticated principal')`.
- If `tenantId` is missing or whitespace-only, throws `ForbiddenException('Tenant context missing from authenticated principal')`.
- Strips any leading/trailing whitespace to guarantee clean tenant isolation across queries.

## 4. Error Mapping & Exception Filter

The [AiConversationExceptionFilter](file:///c:/Projects/kinergy-platform/apps/api/src/ai/conversation/filters/ai-conversation-exception.filter.ts) traps domain and application exceptions, mapping them to standard RFC-compliant HTTP error payloads:

| Domain / Application Exception            | HTTP Status                 | Error Code                           | Description / Client Guidance                                                       |
| :---------------------------------------- | :-------------------------- | :----------------------------------- | :---------------------------------------------------------------------------------- |
| `ConversationNotFoundError`               | `404 Not Found`             | `AI_CONVERSATION_NOT_FOUND`          | Conversation does not exist or does not belong to the tenant                        |
| `TurnNotFoundError`                       | `404 Not Found`             | `AI_TURN_NOT_FOUND`                  | Specified turn does not exist in the conversation                                   |
| `MessageNotFoundError`                    | `404 Not Found`             | `AI_MESSAGE_NOT_FOUND`               | Specified message was not found                                                     |
| `InvalidTurnInputError`                   | `400 Bad Request`           | `AI_INVALID_TURN_INPUT`              | Input payload validation failure (empty message, invalid parameters)                |
| `DuplicateClientTurnPayloadMismatchError` | `409 Conflict`              | `AI_IDEMPOTENCY_PAYLOAD_MISMATCH`    | Idempotency key reused with different parameters                                    |
| `TurnAlreadyInProgressError`              | `409 Conflict`              | `AI_TURN_ALREADY_IN_PROGRESS`        | Another generation or turn is currently active on this conversation                 |
| `TenantOwnershipViolationError`           | `403 Forbidden`             | `AI_TENANT_ACCESS_DENIED`            | Attempted cross-tenant access                                                       |
| `TransientTransactionFailureError`        | `503 Service Unavailable`   | `AI_SERVICE_TEMPORARILY_UNAVAILABLE` | Transient lock contention after exhausted retries; client should retry with backoff |
| `TransactionFailureError`                 | `500 Internal Server Error` | `AI_PERSISTENCE_TRANSACTION_FAILURE` | Non-transient persistence failure; stack trace redacted                             |

### Information Leak Prevention

- Internal PostgreSQL error codes (e.g., `23505`, `40P01`), raw SQL statements, and Prisma call sites are **never** returned to the HTTP client.
- Redaction service ensures zero prompt or context content leaks into error responses or server logs.
