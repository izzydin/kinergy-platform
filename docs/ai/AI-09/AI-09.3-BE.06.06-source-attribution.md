## 1. Executive Summary

Milestone **BE.06.06** establishes the authoritative provenance, sanitization, persistence, and API exposure boundary between the AI-08 RAG retrieval evidence pipeline and the AI-09.3 conversation persistence architecture.

A core clinical safety requirement is that an assistant response must **never claim a source that was not actually retrieved and verified** through authorized document access. Furthermore, source attribution must remain associated with the exact tenant, turn, generation attempt, and canonical assistant message without leaking internal infrastructure paths, vector embeddings, database credentials, or cross-tenant records.

### Core Architectural Guarantees

1. **Strict Provenance Integrity**:
   - Citations originate exclusively from authorized `RAGEvidenceChunk` instances vetted by the AI-08 retrieval engine and validated by `CitationValidatorService`.
   - Textual claims, bracket numbers (e.g. `[Ref-1]`), or hallucinations in LLM prose are never treated as authoritative provenance and are never promoted to structured citations.
2. **Deterministic Validation & Sanitization**:
   - `AiSourceAttributionService` validates all candidate citations. Malformed references missing `documentId`, `documentTitle`, or `chunkId` are discarded without corrupting execution or database state.
   - Relevance scores are strictly clamped and bounded to `[0.0, 1.0]`. Page numbers are validated as positive integers. Section heading hierarchies are cleansed of empty tokens.
3. **Internal Storage & Infrastructure Redaction**:
   - Internal storage paths (`storagePath`, `filePath`, absolute paths e.g. `C:\...` or `/var/...`), vector embeddings, raw tokens, and database connection strings are stripped before persistence and API exposure.
4. **Tenant Isolation & Access Scoping**:
   - When execution is constrained to authorized document IDs (`executionConfig.documentIds`), citations pointing to unlisted or foreign tenant documents are discarded.
5. **Exact Message & Turn Association**:
   - Source citations are persisted strictly on the canonical `role === 'ASSISTANT'` message created for that turn.
   - User messages (`role === 'USER'`) always maintain `sources = null`.
   - Incomplete, failed, or cancelled generation attempts never retain or expose source attribution.
6. **Deduplication & Idempotent Replay**:
   - Multiple references to the same `documentId::chunkId` within a response are deduplicated, deterministically retaining the reference with the highest relevance score.
   - Idempotent turn retries recover the persisted canonical citations directly from PostgreSQL without re-executing AI-08 or duplicating rows.
7. **Backward-Compatible OpenAPI Response Mapping**:
   - `ConversationSourceCitationDto` is introduced and mapped by `AiConversationResponseMapper.toMessageHistoryResponse` without breaking existing frontend or API consumers.

## 2. Provenance Contract & Component Architecture

```
[AI-08 Retrieval Pipeline]
          │
          ▼ RetrievedChunk[] (Authorized Tenant Scope)
[RAG Context Builder]
          │
          ▼ RAGConstructedContext (includedChunks: RAGEvidenceChunk[])
[Grounded Answer Generator] (LLM Inference)
          │
          ▼ StructuredGenerationResult (answer, citedChunkIds)
[CitationValidatorService]
          │
          ├─► Validates citedChunkIds against includedChunks Map
          ├─► Drops fabricated or excluded chunk IDs
          └─► verifiedCitations: RAGSourceCitation[]
                    │
                    ▼
[RAGTurnPipelineAdapter] (AI-08 -> AI-09 Integration Boundary)
          │
          ▼ RAGTurnExecutionResult (outcome, content, sources)
[ExecuteConversationTurnUseCase]
          │
          ├─► AiSourceAttributionService.validateAndSanitize(sources, { allowedDocumentIds })
          │         ├─ Validate documentId, documentTitle, chunkId
          │         ├─ Deduplicate by documentId::chunkId (highest score wins)
          │         ├─ Bound relevanceScore in [0.0, 1.0]
          │         ├─ Strip storagePath, embeddings, secrets, internal IDs
          │         └─ Filter unauthorized / cross-tenant documents
          │
          ├─► AiSourceAttributionService.serializeForPersistence(citations)
          │
          ▼ PersistMessageStateUseCase.execute()
[PostgreSQL: ai_conversation_messages]
          │
          ▼ sources: jsonb (Associated exclusively with canonical assistant message)
[AiConversationController / Response Mapper]
          │
          ▼ AiSourceAttributionService.mapToResponseDto(sources)
[REST Client / Frontend DTO]
          └── MessageResponseDto.sources: ConversationSourceCitationDto[]
```

## 3. Mapping and Validation Rules

### Canonical Source Citation Schema (`CanonicalSourceCitation`)

| Field            | Type               | Validation Rule                                            | Purpose                                       |
| ---------------- | ------------------ | ---------------------------------------------------------- | --------------------------------------------- |
| `documentId`     | `string`           | Required, non-empty, trimmed                               | Unique document identifier providing evidence |
| `documentTitle`  | `string`           | Required, non-empty, no absolute filesystem paths          | Human-readable document title for UI display  |
| `chunkId`        | `string`           | Required, non-empty, trimmed                               | Exact evidence chunk supporting the claim     |
| `pageNumber`     | `number \| null`   | Optional positive integer (`Number.isInteger(p) && p > 0`) | Physical document page reference              |
| `headingPath`    | `string[] \| null` | Optional array of non-empty strings                        | Section breadcrumb navigation path            |
| `relevanceScore` | `number`           | Required finite float bounded to `[0.0, 1.0]`              | Retrieval similarity / fused ranking score    |
| `sourceStrategy` | `string \| null`   | Optional string (e.g. `HYBRID`, `SEMANTIC`)                | Multi-arm retrieval strategy telemetry        |

### Stripped / Unsafe Properties

The following properties are forbidden from persistence or client exposure:

- `storagePath`, `filePath`, `absolutePath`, `relativepath`, `file_path`, `uri`, `url`
- `embedding`, `embeddings`, `vector`, `vectors`
- `databaseUrl`, `connectionString`, `dbUri`
- `token`, `secret`, `apiKey`, `credentials`, `password`
- `internalId`, `prismaId`, `txId`

## 4. Persistence Association Rules

1. **Terminal Success Only**:
   - `PersistMessageStateUseCase` guarantees that `sources` is persisted if and only if `status === GenerationStatus.SUCCESS`.
   - When status is `FAILED` or `CANCELLED`, `sources` is sanitized to `null`.
2. **USER Message Protection**:
   - `role === ConversationRole.USER` messages never accept citations (`sources = null`).
3. **Idempotent Retry**:
   - When a completed turn is re-executed, `ExecuteConversationTurnUseCase` fast-paths the response:
     `const sources = AiSourceAttributionService.deserializeFromPersistence(canonicalMsg.sources)`
     Zero duplicate message records, zero database mutation.
4. **PostgreSQL jsonb Representation**:
   - When sources are present, they are serialized as an array of JSON objects adhering to the canonical citation schema.
   - When no sources exist (abstention or general conversational query), `null` is persisted in the PostgreSQL column.

## 5. API Response Representation

### `ConversationSourceCitationDto`

```typescript
export class ConversationSourceCitationDto {
  @ApiProperty({
    description: 'Unique document identifier providing the evidence',
    example: 'd09a2b5e-4b72-4b21-8288-466fa1d9f8c1',
  })
  documentId!: string;

  @ApiProperty({
    description: 'Title of the referenced knowledge document',
    example: 'Manual de Kinesiología y Vendaje Funcional',
  })
  documentTitle!: string;

  @ApiProperty({
    description: 'Exact knowledge chunk identifier supporting the generation',
    example: 'kc_018f3a5e-b5c6-7a1b-9f0e-1a2b3c4d5e6f',
  })
  chunkId!: string;

  @ApiPropertyOptional({
    description: 'Page number within the source document where chunk originates',
    example: 14,
    nullable: true,
  })
  pageNumber?: number | null;

  @ApiPropertyOptional({
    description: 'Hierarchical section path of headings containing the chunk',
    example: ['Capítulo 2: Técnicas de Vendaje'],
    type: [String],
    nullable: true,
  })
  headingPath?: string[] | null;

  @ApiProperty({ description: 'Similarity or fused relevance score in [0.0, 1.0]', example: 0.942 })
  relevanceScore!: number;

  @ApiPropertyOptional({
    description: 'Strategy that surfaced this chunk (SEMANTIC, KEYWORD, HYBRID, RERANKED)',
    example: 'HYBRID',
    nullable: true,
  })
  sourceStrategy?: string | null;
}
```

### Integration in Message DTOs

`MessageResponseDto` exposes `sources?: readonly ConversationSourceCitationDto[] | null`.  
All message retrieval endpoints (`GET /api/v1/ai/conversations/:id/history` and `POST /:id/audit-inspect`) map through `AiConversationResponseMapper.toMessageHistoryResponse`, applying `AiSourceAttributionService.mapToResponseDto(m.sources)` to guarantee safe client-facing serialization.

## 6. Security Considerations

1. **Cross-Tenant Isolation**:
   - If an attacker or corrupted component injects citations with a document ID from another tenant, `AiSourceAttributionService.validateAndSanitize` filters it out against the authorized document pool (`allowedDocumentIds`).
2. **Credential & Infrastructure Leakage Prevention**:
   - Cloud storage buckets (e.g. `s3://...`), local filesystem paths (e.g. `C:\...`), and connection strings are stripped at two distinct defensive layers: before PostgreSQL write and during API response mapping.
3. **No LLM Provenance Spoofing**:
   - Model claims such as `[Doc 10: Secret Policy]` are not promoted to structured citations. Only citations matched against authorized evidence chunks in the pipeline context boundary are admitted.
