## 4. Documented Scope Exclusions & Backend Recommendations

### 1. Database-Level Concurrent Booking Race Condition

- **Root Cause**: `Appointment` aggregate creation uses optimistic concurrency versioning for updates/reschedules, but initial creation relies on an in-memory specification engine (`ConflictDetectionService`). The Prisma/PostgreSQL schema lacks a GiST exclusion constraint (`btree_gist` extension).
- **Impact**: Two concurrent bookings submitted within milliseconds for the exact same therapist or room could both pass in-memory evaluation and create overlapping records.
- **Resolution Step Required for Backend Team**:
  Add a Prisma migration with raw SQL adding a PostgreSQL exclusion constraint:
  ```sql
  CREATE EXTENSION IF NOT EXISTS btree_gist;
  ALTER TABLE "appointments"
  ADD CONSTRAINT "no_overlapping_therapist_appointments"
  EXCLUDE USING gist (
    therapist_id WITH =,
    tstzrange(start_time, end_time) WITH &&
  ) WHERE (status NOT IN ('CANCELLED', 'NO_SHOW'));
  ```

### 2. Client Self-Service Scheduling

- Client-facing portal booking is intentionally excluded from Milestone 4 per ADR-0043 and project specifications (Milestone 4 is strictly the Staff Scheduling Experience).
