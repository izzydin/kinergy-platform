## 4. Grounding Invariants & Source Attribution

1. **Structured Separation**:
   - The user prompt constructed in `GroundedGenerationService` strictly isolates `<retrieved_evidence>` from `<conversation_history>` and `<user_question>` using secure XML delimiters.
   - Prevents prompt injection breakouts and keeps system instructions authoritative.
2. **Authoritative Citation Verification**:
   - All source references returned by the LLM are cross-checked against the `constructedContext.includedChunks`.
   - Hallucinated or non-existent chunk citations are stripped by `CitationValidatorService`.
   - If claims are ungrounded or unsupported, the answer is flagged with `isGrounded: false` and mapped to `outcome: ABSTAINED`.
3. **No Direct LLM Persistence**:
   - The LLM provider and RAG services have zero access to the persistence layer.
   - Persistence is managed exclusively by AI-09.3's `ExecuteConversationTurnUseCase` through `PersistMessageStateUseCase`.

## 5. Timeout Enforcement & Error Handling

Established timeouts from approved configuration (`DEFAULT_AI_CONFIG`):

- **Retrieval Timeout**: 5,000 ms (5s)
- **Context Builder Timeout**: 1,000 ms (1s)
- **Generation Timeout**: 20,000 ms (20s)
- **Overall Pipeline Timeout**: 30,000 ms (30s)

### Typed Outcome Mapping:

| Trigger / Error                        | Internal Exception                                           | Adapter Outcome                          | Assistant Message Status                       | Turn Status            |
| :------------------------------------- | :----------------------------------------------------------- | :--------------------------------------- | :--------------------------------------------- | :--------------------- |
| **Pipeline or Component Timeout**      | `ProviderTimeoutException` / `TimeoutError`                  | `FAILED` (`PROVIDER_TIMEOUT`)            | `GenerationStatus.FAILED`                      | `TurnStatus.FAILED`    |
| **User or Client Cancellation**        | `GenerationCancelledException` / `AbortError`                | `CANCELLED`                              | `GenerationStatus.CANCELLED`                   | `TurnStatus.CANCELLED` |
| **Zero Chunks / Out-of-Domain (<0.6)** | Abstention returned by RAG orchestrator                      | `ABSTAINED`                              | `GenerationStatus.SUCCESS` (isCanonical: true) | `TurnStatus.COMPLETED` |
| **Model Not Found / Runtime Down**     | `ModelNotFoundException` / `LLMProviderUnavailableException` | `FAILED` (`MODEL_NOT_FOUND`)             | `GenerationStatus.FAILED`                      | `TurnStatus.FAILED`    |
| **Database Connection Failure**        | `RetrievalDatabaseException`                                 | `FAILED` (`RETRIEVAL_PERSISTENCE_ERROR`) | `GenerationStatus.FAILED`                      | `TurnStatus.FAILED`    |

All timeout and error conditions are persisted cleanly as structured failure metadata without crashing HTTP processes or leaving dangling generation leases.
