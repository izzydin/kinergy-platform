# AI-05.6 — Model Versioning, Change Detection & Profile Lifecycle

## 1. Executive Summary

Embedding vectors are strictly dependent on the underlying neural network weights, tokenization scheme, dimension, and preprocessing policies. Vectors generated by different models or configurations are **mathematically incommensurable** (cosine similarity across heterogeneous profiles yields nonsensical results).

To guarantee semantic integrity:

1. **Immutable Embedding Profiles:** Historical profiles (`EmbeddingProfile`) are never mutated in place.
2. **Automated Change Detection:** The `ModelChangeDetectorService` compares runtime configurations against active profiles.
3. **Deterministic Profile Derivation:** Any change in model name, digest, dimension, provider, normalization, or pooling produces a deterministic new `EmbeddingProfile` ID.
4. **Audit Trail Retention:** Retired profiles and generations remain preserved in PostgreSQL for compliance, reproducibility, and rollback safety.

---

## 2. Model Change Detection Rules

The `ModelChangeDetectorService` checks for material differences between the active baseline profile and incoming configuration:

| Attribute                 | Change Impact                                                           | Material Change? | Action Required                                                      |
| :------------------------ | :---------------------------------------------------------------------- | :--------------- | :------------------------------------------------------------------- |
| **`modelDigest`**         | Weights updated (e.g., fine-tuned or re-quantized checkpoint)           | **YES**          | Create new profile, trigger tenant re-indexing                       |
| **`dimensions`**          | Dimension reduction or expansion (e.g., 1024 $\rightarrow$ 512 via MRL) | **YES**          | Create new profile, requires matching pgvector column or new table   |
| **`modelName`**           | Provider model switched (e.g., `bge-m3` $\rightarrow$ `bge-large-en`)   | **YES**          | Create new profile, trigger re-indexing                              |
| **`provider`**            | Backend provider switched (e.g., `ollama` $\rightarrow$ `openai`)       | **YES**          | Create new profile, re-index                                         |
| **`normalizationPolicy`** | Vector normalization changed (e.g., `L2` $\leftrightarrow$ `NONE`)      | **YES**          | Invalidates dot-product/cosine index consistency; create new profile |
| **`poolingStrategy`**     | Token pooling changed (e.g., `CLS` $\leftrightarrow$ `MEAN`)            | **YES**          | Vector semantics altered; create new profile                         |
| **`tokenizerIdentity`**   | Vocabulary or subword segmentation altered                              | **YES**          | Token alignment altered; create new profile                          |

---

## 3. Immutable Profile Derivation

When a material change is detected:

1. The detector constructs a `CandidateProfileParams` object.
2. It generates a deterministic profile identifier:
   ```
   prof_{modelName}_{dimensions}_{sha256(canonicalAttributes).slice(0, 12)}
   ```
   _Example:_ `prof_bge-m3_1024_8e3c70eedcd3`
3. A new `EmbeddingProfile` domain value object is created.
4. Historical profiles are never updated or overwritten. They remain associated with historical `IndexGeneration` records.

---

## 4. Model Retirement & Audit Policy

1. **Active Profile:** The single profile currently serving live similarity queries for active generations.
2. **Retired Profile:** A profile whose generations have been retired. Associated vectors are protected for the retention duration (default: $N=2$ retired generations).
3. **Audit Immutability:** Historical profile identifiers stamped on `document_embeddings` and `index_generations` remain permanent audit records. Even after physical vector deletion, the `index_generations` and `embedding_profiles` metadata records are preserved indefinitely.
