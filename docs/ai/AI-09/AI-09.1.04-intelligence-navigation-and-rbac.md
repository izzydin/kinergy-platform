## 1. Executive Summary

Milestone **AI-09.1.04** delivers the permission-aware navigation infrastructure for Kynergy Intelligence. It integrates **AI Assistant** and **Knowledge Center** into both the global navigation sidebar (`Sidebar`) and the module subnavigation tab bar (`IntelligenceLayout`), adhering strictly to the approved architectural decisions (specifically **ADR-AI-09-04: Role-Based Intelligence Feature Gating**).

Key architectural achievements in this milestone:

1. **Zero Duplicated Navigation Infrastructure:** Reused the platform's configuration-driven `navigationRegistry`, `NavigationBuilder`, and `NavigationProvider`. No secondary navigation system was introduced.
2. **Dedicated Intelligence Grouping:** Registered items under section `'intelligence'` (displayed with section title `"Intelligence"` and prioritized order weight `30`).
3. **Role-Based Permission-Aware Filtering:**
   - **AI Assistant** (`/intelligence/chat`): Visible and accessible to all authenticated staff (`SUPER_ADMIN`, `ADMIN`, `OWNER`, `ENERGY_MANAGER`, `OPERATOR`, `COLLABORATOR`).
   - **Knowledge Center** (`/intelligence/knowledge`): Gated dynamically by `requiredRoles: KNOWLEDGE_ALLOWED_ROLES` (`['SUPER_ADMIN', 'ADMIN', 'OWNER', 'ENERGY_MANAGER']`). Non-administrative roles (e.g., `OPERATOR`, `COLLABORATOR`) have the item filtered out of both the Sidebar and `IntelligenceLayout` tabs.
4. **Defense in Depth (No Authorization Inference from Navigation):** Navigation visibility is strictly cosmetic and usability-oriented. Route-level security is independently enforced by `IntelligenceKnowledgeGuard` and `ProtectedRoute`. Unauthorized direct access yields an HTTP 403 `ForbiddenView`; unauthenticated requests redirect to `/auth/login?redirect=...`.
5. **Deterministic Nested Active Route Resolution:** Supports exact match and prefix matching (`${item.path}/`). Deep conversational routes (`/intelligence/chat/:conversationId`) and nested document routes (`/intelligence/knowledge/documents/:documentId`) activate their parent navigation entries in both the sidebar and layout tabs.
6. **Responsive & Accessible Presentation:** Complete support for 256px expanded mode, 80px collapsed mode with centered icons and `sr-only` labels, accessible non-clipped portal tooltips, `Ctrl+B` toggle, mobile slide-over drawer, and `Escape` key dismissal.

## 3. Active Route Resolution & Nested Matching

Navigation active-state detection uses robust prefix matching without fragile hardcoded paths:

```typescript
const isItemActive = (item: NavigationItem): boolean => {
  if (item.path === '/') return location.pathname === '/';
  if (item.path === '/dashboard')
    return location.pathname === '/dashboard' || location.pathname === '/dashboard/';
  return location.pathname === item.path || location.pathname.startsWith(`${item.path}/`);
};
```

### Verified Active State Behaviors

- **`/intelligence`** redirects to `/intelligence/chat`, activating the **AI Assistant** navigation item and tab.
- **`/intelligence/chat`** activates **AI Assistant** (`aria-current="page"`, `border-primary`).
- **`/intelligence/chat/conv-09a8b7c6`** activates **AI Assistant** via prefix matching.
- **`/intelligence/knowledge`** activates **Knowledge Center** (`aria-current="page"`, `border-primary`).
- **`/intelligence/knowledge/documents/doc-550e8400`** activates **Knowledge Center** via prefix matching.

## 4. Security Invariants & Permission Dependencies

### 4.1 Zero Hardcoded Assumptions

- Navigation components (`Sidebar`, `IntelligenceLayout`) contain **zero hardcoded role strings** (`'ADMIN'`, `'OPERATOR'`).
- The authorization policy is centralized in `KNOWLEDGE_ALLOWED_ROLES` and `canAccessKnowledgeCenter()` in `apps/web/src/modules/intelligence/routes/intelligence-knowledge-guard.tsx`.
- `NavigationItem` was cleanly extended with `readonly requiredRoles?: string[]`.
- `NavigationBuilder` dynamically invokes `options.hasRole(role)` provided by `useAuth()`.

### 4.2 Outstanding Permission Dependencies

- **Finding:** The backend and core identity package (`@kinergy/core` / `packages/core/src/identity`) currently lack granular AI permissions in the `PERMISSIONS` enum (e.g., `ai.chat.query`, `ai.knowledge.upload`, `ai.knowledge.manage`).
- **Policy Enforcement:** Per **ADR-AI-09-04**, the frontend enforces access based on verified user roles rather than inventing speculative permission strings.
- **Future Migration Path:** Once the backend identity service introduces granular permissions in PostgreSQL and JWT claims, `intelligenceNavigationItems` and `IntelligenceKnowledgeGuard` can transition from `requiredRoles` to `requiredPermissions: ['ai.knowledge.manage']` without altering layout or navigation components.

## 5. Responsive & Accessible Navigation

1. **Desktop Expanded (256px):**
   - Renders section header `"Intelligence"` in `Sidebar`.
   - Links render `Bot` and `BookOpen` Lucide icons, full text labels, and active visual indicator bars (`bg-brand-green`, WCAG 1.4.1).
2. **Desktop Collapsed (80px):**
   - Triggered via header button or `Ctrl+B` / `Cmd+B`.
   - Text labels are visually hidden using `.sr-only` to preserve screen-reader semantics.
   - Non-clipped portal tooltips render on hover and `Tab` focus into `document.body`.
3. **Mobile (< md):**
   - Persistent trigger button (`Menu` / `X`) with `aria-expanded` and `aria-controls`.
   - Slide-over drawer with backdrop blur and body scroll locking (`overflow: hidden`).
   - `Escape` key dismisses mobile drawer and restores focus to trigger.
