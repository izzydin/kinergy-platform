Milestone **FE.06** implements persistent, consistent, and server-authoritative conversation renaming and metadata management across the backend and frontend of Kynergy Platform. The system enables users to rename persistent conversation threads directly from the conversation history sidebar and active chat header, with accessible form controls, client and server validation (1–255 characters, non-empty, trimmed), keyboard navigation (Enter saves, Escape cancels), concurrent submission prevention, and optimistic cache reconciliation with automatic snapshot rollback upon network or validation failures.

## 2. Backend Contract & Persistence Invariants

The backend rename endpoint was verified and hardened against real PostgreSQL transactions:

- **Route & HTTP Method**: `PATCH /api/v1/ai/conversations/:id/title`
- **Request DTO**: `UpdateConversationTitleRequestDto`
  - `title`: string, `@IsString()`, `@IsNotBlank()`, `@MaxLength(255)`.
- **Response DTO**: `UpdateTitleResponseDto`
  - `conversationId`: string (UUID)
  - `title`: string (trimmed canonical title)
  - `updatedAt`: string (ISO 8601 UTC timestamp)
- **Use Case Rules (`UpdateConversationTitleUseCase`)**:
  1. **Authentication & Ownership**: Evaluates `@TrustedAi() auth: TrustedAiContext`. Conversations are accessed exclusively within the caller's tenant boundary (`convRepo.findById(tenantId, conversationId)`). Unauthorized or cross-tenant access immediately throws `ConversationNotFoundError` (HTTP 404), eliminating resource enumeration risks.
  2. **Title Invariants**: Evaluates `ConversationTitle.create(input.title.trim())`. Empty, whitespace-only, or strings $> 255$ characters throw `InvalidTurnInputError` (HTTP 400).
  3. **Lifecycle Guard**: Archival state check (`conv.isArchived()`). Archived or soft-deleted conversations cannot be renamed, throwing `InvalidConversationLifecycleError` (HTTP 400).
  4. **Persistence & Timestamps**: Invokes `convRepo.updateMetadata` or entity update, advancing `updatedAt` deterministically in PostgreSQL.

## 3. Frontend Experience & Accessible UI

### 3.1 Inline History Editing (`ConversationSidebar`)

- **Activation**: Hovering or focusing a conversation item in `ConversationSidebar` reveals an accessible `Pencil` icon button (`aria-label="Renombrar conversación <title>"`).
- **Inline Editor**:
  - Focus is transferred automatically to the text `<input>` (`data-testid="rename-input"`, `maxLength={255}`).
  - Pre-filled with current title without loss of cursor context.
  - Action buttons: Save (`Check` icon, `data-testid="save-rename-button"`) and Cancel (`X` icon, `data-testid="cancel-rename-button"`).
- **Keyboard Shortcuts**:
  - `Enter`: Submits the form and initiates the mutation.
  - `Escape`: Reverts changes, exits edit mode, and restores original title without submitting.
- **Client Validation & Feedback**:
  - Validates trimmed input length between 1 and 255 characters.
  - Displays localized error text (`role="alert"`, `data-testid="rename-error"`) if empty or invalid.
- **Concurrency & Pending States**:
  - Disables input and action controls while mutation is pending.
  - Replaces save icon with an animated spinner (`Loader2 className="animate-spin"`).
  - Blocks duplicate concurrent submissions.

### 3.2 Workspace Header Editing & Metadata Display (`ChatWorkspaceHeader`)

- **In-Place Header Rename**:
  - Supports clicking the edit button next to the title or double-clicking the heading.
  - In-place accessible input with keyboard shortcuts (`Enter` / `Escape`) and validation.
- **Metadata Display Precision**:
  - **Message Count**: Displays exact total turn count (`<N> mensajes`).
  - **Creation Timestamp**: Formatted localized timestamp (`Creado: <date> <time>`, with full ISO localized tooltip).
  - **Last Activity Timestamp**: Formatted localized timestamp (`Actividad: <date> <time>`, with full ISO localized tooltip).
  - **No Fabrication**: If `createdAt` or `lastActivityAt` are missing (e.g. legacy data), timestamp elements are omitted completely rather than fabricated.

## 4. Safe Optimistic Updates & Cache Rollback

The TanStack Query mutation hook `useRenameConversationMutation` provides full optimistic updates with snapshot rollback:

```typescript
// use-conversation-mutations.ts
export function useRenameConversationMutation(...) {
  return useMutation({
    mutationFn: ({ conversationId, request }) => conversationApi.updateTitle(conversationId, request),
    onMutate: async ({ conversationId, request }) => {
      // 1. Cancel in-flight queries
      await queryClient.cancelQueries({ queryKey: conversationQueryKeys.detail(conversationId, scope) });
      await queryClient.cancelQueries({ queryKey: conversationQueryKeys.lists(scope) });

      // 2. Snapshot current caches for rollback
      const previousDetail = queryClient.getQueryData(conversationQueryKeys.detail(conversationId, scope));
      const previousLists = queryClient.getQueriesData({ queryKey: conversationQueryKeys.lists(scope) });

      // 3. Optimistically update detail and list caches
      const optimisticTitle = request.title.trim();
      if (previousDetail) {
        queryClient.setQueryData(conversationQueryKeys.detail(conversationId, scope), {
          ...previousDetail,
          title: optimisticTitle,
        });
      }
      queryClient.setQueriesData({ queryKey: conversationQueryKeys.lists(scope) }, (prev) => {
        if (!prev?.items) return prev;
        return {
          ...prev,
          items: prev.items.map((item) =>
            item.id === conversationId ? { ...item, title: optimisticTitle } : item,
          ),
        };
      });

      return { previousDetail, previousLists };
    },
    onError: (error, variables, context) => {
      // Rollback detail and lists to captured snapshots
      if (context?.previousDetail !== undefined) {
        queryClient.setQueryData(conversationQueryKeys.detail(variables.conversationId, scope), context.previousDetail);
      }
      if (context?.previousLists) {
        for (const [key, data] of context.previousLists) {
          queryClient.setQueryData(key, data);
        }
      }
    },
    onSuccess: async (data, variables) => {
      // Reconcile with authoritative backend response
      conversationCachePolicies.updateConversationTitleInCache(
        queryClient,
        variables.conversationId,
        data.title,
        scope,
        data.updatedAt,
      );
    },
    onSettled: async (data, error, variables) => {
      // Re-validate affected queries to guarantee canonical consistency
      await Promise.all([
        conversationCachePolicies.invalidateConversationLists(queryClient, scope),
        conversationCachePolicies.invalidateConversationDetail(queryClient, variables.conversationId, scope),
      ]);
    },
  });
}
```
