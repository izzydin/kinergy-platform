## 1. Executive Summary

Milestone **BE.06.04** integrates the AI-08 grounded generation output with the canonical AI-09.3 persistence and generation lifecycle layer.

Key guarantees established:

1. **Atomic Finalization Unit of Work**:
   Assistant message persistence (`PersistMessageStateUseCase`), turn terminal status mutation (`turnRepo.updateStatus`), and conversation activity touch (`convRepo.updateMetadata`) are committed within a single interactive database transaction via `IAiConversationTransactionRunner`.
2. **Transactional Fencing & Race Safety**:
   Generation finalization checks the live turn status and attempt identity inside the transaction boundary. A late or stale LLM worker cannot overwrite a concurrent cancellation, interruption, or superseded generation attempt. Exactly one terminal transition wins.
3. **Strict Idempotency on Retry**:
   Calling `ExecuteConversationTurnUseCase` on an already `COMPLETED` turn immediately resolves and reuses the persisted canonical assistant message and citations without re-invoking the RAG pipeline and without creating duplicate message records.
4. **Canonical Single-Answer Invariant**:
   Enforces exactly one canonical assistant message per turn. Only generation attempts with `status: SUCCESS` can carry `isCanonical: true`. Failed, cancelled, and interrupted attempts carry `isCanonical: false`.
5. **No Direct Prisma Access from AI-08**:
   All database operations occur through AI-09.3 outbound repository ports and application use cases. Zero database primitives leak into the AI-08 RAG orchestrator or LLM adapters.

## 3. Terminal State Machine & Transition Semantics

### Vocabulary Invariants

- **Turn Statuses**: `PENDING`, `STREAMING`, `COMPLETED`, `FAILED`, `CANCELLED`, `INTERRUPTED`.
- **Message / Attempt Statuses**: `PENDING`, `STREAMING`, `SUCCESS`, `FAILED`, `CANCELLED`, `INTERRUPTED`.
- _Note:_ No `RECOVERING` state is introduced; failure recovery is handled cleanly by allocating a subsequent attempt number on a new turn reservation.

## 4. Concurrency & Fencing Guarantees

### Cancellation-Versus-Finalization Race Condition

When a client issues a cancellation while an LLM inference call is in flight:

1. The cancellation request marks the turn and message attempt as `CANCELLED` in PostgreSQL.
2. The in-flight LLM worker completes seconds later and enters `finalizeWork`.
3. Inside the transaction runner (`runInTransaction`):
   - The worker executes `turnRepo.findById(tenantId, conversationId, turnId)`.
   - The worker inspects `inTxTurn.status`. Since the turn status is `CANCELLED` (terminal), the worker detects that cancellation won the race.
   - The worker cleanly aborts without mutating the database (`txMsgRepo.updateStatus` and `txTurnRepo.updateStatus` are skipped).
   - The return contract indicates `{ turnStatus: 'CANCELLED', outcome: 'CANCELLED', isCanonical: false }`.
   - Result: The database maintains strict integrity; terminal `CANCELLED` state is never overwritten by a late LLM response.

### Superseded Attempt Fencing

If a generation attempt is superseded (e.g. timeout worker allocated attempt 2 with a new `activeAttemptId`):

1. Worker 1 enters `finalizeWork` carrying attempt 1 tokens.
2. Inside the transaction, `inTxTurn.activeAttemptId` and `inTxTurn.activeAttemptNumber` are checked against attempt 1.
3. The worker detects a mismatch (`activeAttemptNumber !== attemptNumber`).
4. Finalization aborts with `errorCode: 'ATTEMPT_SUPERSEDED'`, preventing the stale worker from committing.

## 5. Idempotency on Completed Turns

When `ExecuteConversationTurnUseCase.execute` is invoked on a turn that has already reached `TurnStatus.COMPLETED`:

1. **Pre-flight Fast Path**:
   - `turn.status === TurnStatus.COMPLETED` is detected immediately after turn retrieval.
   - The existing canonical assistant message is resolved using `messageRepo.findCanonicalAssistantMessage(tenantId, conversationId, turnId)`.
2. **Deterministic Response**:
   - Returns the existing canonical content, source citations, grounding flag, and metadata.
   - The RAG pipeline (`ragPipeline.executeTurn`) is **not** called.
   - Zero new database records are written (zero duplicate messages, zero duplicate turns).
