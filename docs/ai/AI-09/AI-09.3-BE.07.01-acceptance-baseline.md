## 2. Security & Access Policy Baseline (Source of Truth)

The access policies below are extracted directly from the canonical implementation in `packages/core` and `apps/api/src/ai/conversation`:

### 2.1 Tenant Isolation vs. User-Level Ownership

The platform implements a two-tier boundary model:

```
┌────────────────────────────────────────────────────────────────────────┐
│ Tenant Boundary (Hard Isolation Boundary - Mandatory on ALL queries)   │
│                                                                        │
│  ┌──────────────────────────────┐    ┌──────────────────────────────┐  │
│  │ User A1 Conversations        │    │ User A2 Conversations        │  │
│  │  - Created by User A1        │    │  - Created by User A2        │  │
│  │  - Listed only by User A1    │    │  - Listed only by User A2    │  │
│  │  - Turns reserved by User A1 │    │  - Turns reserved by User A2 │  │
│  └──────────────────────────────┘    └──────────────────────────────┘  │
│                 ▲                                   ▲                  │
│                 └─────────────────┬─────────────────┘                  │
│                                   │                                    │
│                 ┌─────────────────────────────────┐                    │
│                 │ Privileged Inspection (Audit)   │                    │
│                 │ - Role: 'Owner' ONLY            │                    │
│                 │ - Permission: 'ai.convs.audit'  │                    │
│                 │ - Justification: >= 10 chars    │                    │
│                 │ - Fail-Closed Audit Logging     │                    │
│                 └─────────────────────────────────┘                    │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Tenant Isolation (Hard Isolation Boundary)**:
   - Every database query, repository lookup, and transaction is strictly scoped by `tenantId`.
   - Cross-tenant requests for conversations, turns, or messages return `404 Not Found` (`ConversationNotFoundError`) to avoid leaking the existence of resources across tenant boundaries.
   - RAG knowledge retrieval and document vector filtering only query chunks belonging to `tenantId`.
   - `AiSourceAttributionService` rejects and strips citations referencing documents outside the caller's tenant.

2. **User Ownership (Workspace & Turn Ownership Boundary)**:
   - **Conversation Listing (`ListConversationsUseCase`)**: User-scoped. A user query lists only conversations created by that user (`userId === auth.actorId`). Users cannot browse other users' conversation histories in their listing.
   - **Turn Reservation (`ReserveConversationTurnUseCase`)**: Strictly creator-bound. The use case enforces:
     ```typescript
     if (conversation.tenantId !== tenantId || conversation.userId !== userId) {
       throw new TenantOwnershipViolationError('AiConversation', conversationId, tenantId);
     }
     ```
     A user cannot append turns or execute generations on another user's conversation thread.
   - **Turn Cancellation (`CancelConversationTurnUseCase`)**: Creator-bound. A user can only cancel active generation turns on their own conversation.
   - **Direct Read Access (`GetConversationUseCase`, `GetMessageHistoryUseCase`)**: Tenant-scoped. Allows authorized clinical collaborators within the same tenant to inspect conversation state when provided a direct conversation ID, while listing remains partitioned by user.

3. **Privileged Inspection (`PrivilegedInspectConversationUseCase`)**:
   - Allows compliance officers and clinical supervisors to audit any conversation within their tenant.
   - **Role Requirement**: Strictly `@Roles('Owner')`.
   - **Permission Requirement**: Strictly `@RequirePermissions(PERMISSIONS.AI.CONVERSATIONS_AUDIT)` (`ai.conversations.audit`).
   - **Justification Mandate**: Requires a mandatory clinical/compliance justification reason (minimum 10 characters).
   - **Fail-Closed Persistence**: If the `AiConversationAuditLog` record cannot be committed to PostgreSQL, the operation aborts immediately (`TransactionFailureError`), and zero conversation or message data is returned.

## 5. Test Infrastructure & Tooling Baseline

### 5.1 Real PostgreSQL Target

- **Prisma Schema**: Real PostgreSQL database running at `DATABASE_URL` (`postgresql://kinergy:kinergy_dev@localhost:5432/kinergy_platform`).
- **Transactional Consistency**: Multi-turn and multi-user concurrency tests execute against PostgreSQL using `PrismaAiConversationTransactionRunner` with transaction isolation.
- **Fixture Cleanup**: Clean teardown scoped to test tenant IDs (`tenant_sec_alpha`, `tenant_sec_beta`), wiping dependent messages, turns, conversations, and audit logs.

### 5.2 Test Helpers & Mock Providers

- **`RAGTurnPipelineAdapter` / `IRAGTurnPipelinePort`**: Controllable execution adapter supporting configurable latency, artificial cancellation pauses, and controlled failure modes to simulate real LLM generation latencies during concurrency races.
- **`AiTurnDispatcherService`**: In-memory task tracker and non-blocking dispatcher with `setImmediate` execution.
- **`AiTurnGenerationWorker`**: Background recovery worker configured with short polling intervals for recovery scenario verification.
