## 1. Executive Summary

Task `AI-09.3-BE.05.04` implements the production REST endpoints for subsequent conversation turn reservation and canonical message history pagination in `apps/api`. It connects validated DTOs to the `ReserveConversationTurnUseCase` and `GetMessageHistoryUseCase` application workflows implemented in `BE.04`. It strictly enforces persistence-only contracts (excluding LLM generation or streaming), maintains client-stable idempotency semantics, guarantees single-generation concurrency protection per conversation, injects bounded `Retry-After` throttling/conflict headers, and verifies all persistence invariants against real PostgreSQL.

### Key Architectural Invariants Enforced:

1. **Zero Database / Prisma Leakage in Presentation:** [AiConversationController](file:///c:/Projects/kinergy-platform/apps/api/src/ai/conversation/ai-conversation.controller.ts) invokes application use cases directly. No Prisma models, transactions, or repositories are imported or exposed.
2. **Single Active Generation per Conversation:** Reserving a turn while an assistant message is pending generation triggers an immediate `TurnAlreadyInProgressError` mapped to `409 Conflict` with a bounded `Retry-After: 2` response header.
3. **Client-Stable Idempotency Preservation:** Submitting the exact same `clientTurnId` and payload recovers the existing turn with `isIdempotentReplay: true` and `idempotencyOutcome: 'EXISTING_RECOVERED'`. Submitting a duplicate `clientTurnId` with a conflicting payload raises `DuplicateClientTurnPayloadMismatchError` mapped to `409 Conflict`.
4. **Immutable Sequence Ordering for Message History:** Message history uses keyset pagination via immutable sequence cursors (`MessageHistoryCursor`). Rejection of mutable activity-timestamp cursors prevents pagination drifting.
5. **Canonical Message Read Model:** `listCanonicalHistory` returns user messages and canonical assistant messages (`OR: [{ role: 'USER' }, { isCanonical: true }]`), ensuring in-progress assistant placeholders are never leaked before completion.
6. **Rate-Limiting Integration:** Leverages the global [RateLimitingModule](file:///c:/Projects/kinergy-platform/apps/api/src/platform/rate-limiting/rate-limiting.module.ts) and `CustomThrottlerGuard` to prevent turn abuse while ensuring idempotency recovery succeeds transparently.

  - `metadata`: `object?` (optional turn metadata).

- **Route Param:** `id` (Conversation unique identifier).

    - `content`: `string`
    - `sources`: `Record<string, unknown>[] | null`
    - `createdAt`: `string` (ISO 8601)
    - `completedAt`: `string | null` (ISO 8601)
  - `nextCursor`: `string | null`

## 4. Idempotency, Concurrency & Conflict Outcomes

| Scenario                             | HTTP Status               | Response Payload / Header                                                                         | Persistence State                               |
| :----------------------------------- | :------------------------ | :------------------------------------------------------------------------------------------------ | :---------------------------------------------- |
| **New Turn Request**                 | `201 Created`             | `ReserveTurnResponseDto` (`isIdempotentReplay: false`, `idempotencyOutcome: 'CREATED'`)           | Turn and messages persisted atomically          |
| **Matching Idempotent Retry**        | `201 Created`             | `ReserveTurnResponseDto` (`isIdempotentReplay: true`, `idempotencyOutcome: 'EXISTING_RECOVERED'`) | Zero duplicate records inserted                 |
| **Payload Mismatch Conflict**        | `409 Conflict`            | `code: 'AI_CLIENT_TURN_PAYLOAD_MISMATCH'`, description of conflicting hash                        | Existing turn untouched; request rejected       |
| **Active Turn In-Progress Conflict** | `409 Conflict`            | `code: 'AI_TURN_ALREADY_IN_PROGRESS'`, **`Retry-After: 2`** header                                | Existing generation protected; request rejected |
| **Cross-Tenant Conversation**        | `404 Not Found`           | `code: 'AI_CONVERSATION_NOT_FOUND'`                                                               | Rejection without revealing resource existence  |
| **Transient DB Lock Conflict**       | `503 Service Unavailable` | `code: 'AI_TRANSIENT_TRANSACTION_FAILURE'`, **`Retry-After: 1`** header                           | Transaction rolled back; retry advised          |

## 5. Rate-Limiting Behavior

Rate-limiting operates via NestJS global `APP_GUARD` ([CustomThrottlerGuard](file:///c:/Projects/kinergy-platform/apps/api/src/platform/rate-limiting/guards/custom-throttler.guard.ts)) registered in [RateLimitingModule](file:///c:/Projects/kinergy-platform/apps/api/src/platform/rate-limiting/rate-limiting.module.ts):

- **Default Window:** 60 seconds (`apiDefaultWindowSeconds`).
- **Default Limit:** 120 requests per client/tenant (`apiDefaultLimit`).
- **Idempotency Compatibility:** Idempotent retries are tracked per standard HTTP request; clients respecting `Retry-After: 2` on `409 Conflict` will avoid triggering HTTP 429 throttling limits.
- **Throttling Response:** Returns standard `429 Too Many Requests` with retry headers.
