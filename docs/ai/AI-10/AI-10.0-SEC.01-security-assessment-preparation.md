## Executive Summary

This working document establishes the authoritative, evidence-based security baseline and architectural audit for **Kynergy Intelligence** ahead of the comprehensive security verification milestone (**AI-10.0**). All findings and inventories herein are derived directly from source inspection of the monorepo codebase (`apps/api`, `apps/web`, `packages/core`), real PostgreSQL database schemas (`prisma/schema.prisma`), runtime configurations, and executed test suites.

**Assessment Readiness Verdict:** **`READY WITH RISKS`**

- **Architecture & Boundaries:** Clean Architecture separation with domain ports/adapters, strict multi-tenant schema constraints, and defense-in-depth isolation layers are fully implemented.
- **Identified Risks & Discrepancies:**
  1. _Preview Token Fallback Key:_ `PreviewTokenService` contains a hardcoded fallback HMAC key (`'kinergy-secure-document-preview-secret-salt-2026'`) if neither `AI_PREVIEW_TOKEN_SECRET` nor `JWT_SECRET` is defined in the environment.
  2. _Unauthenticated Citation Content Stream Role Context:_ The public `/citations/:citationId/content?token=...` endpoint evaluates caller roles as empty `[]` when called without a Bearer header. If a document's visibility scope is `CLINICAL_STAFF` or `MANAGEMENT`, it fails closed (`DocumentAccessRestrictedError`) even with a valid signed token, unless the caller also supplies an active Bearer JWT.
  3. _Role Naming Semantic Drift:_ Frontend route guards (`intelligence-knowledge-guard.tsx`) check roles `['SUPER_ADMIN', 'ADMIN', 'OWNER', 'ENERGY_MANAGER']`, whereas backend domain security policy (`retrieval-security-policy.service.ts` and `get-citation-document-stream.use-case.ts`) checks clinical/gym roles (`'owner'`, `'admin'`, `'director'`, `'doctor'`, `'physiotherapist'`, `'kinesiologist'`).
  4. _Ollama Inference Isolation:_ The backend connects to an Ollama instance over plaintext HTTP (`AI_OLLAMA_BASE_URL`, default `http://127.0.0.1:11434`) without mutual TLS or bearer token authentication.

5. **Retrieval & RAG Generation Pipeline (`apps/api/src/ai/services`)**:
   - Query & Retrieval: `QueryEmbeddingService`, `SecureSemanticSearchService`, `PrismaSemanticRetrievalRepository`, `PrismaLexicalRetrievalRepository`.
   - Access Control: `RetrievalSecurityPolicyService` (pre-retrieval filtering by role visibility scope and tenant ID).
   - Reranking: `LocalCrossEncoderRerankingAdapter` (BGE reranker).
   - Prompt & Context Construction: `RAGContextBuilderService` (token budgeting, XML tag escaping, negation preservation).
   - Generation & Citations: `GroundedGenerationService` (JSON structure enforcement, citation cross-checking), `CitationValidatorService`.
6. **Conversation Persistence & Worker Execution (`apps/api/src/ai/conversation`)**:
   - Lifecycle Management: `AiConversationController`, `ExecuteConversationTurnUseCase`, `ReserveConversationTurnUseCase`.
   - Dispatcher & Worker: `AiTurnDispatcherService` (in-memory deduplication, cancellation signaling), `AiTurnGenerationWorker` (background polling).
   - Preview Token Generation: `PreviewTokenService` (HMAC SHA-256 signed URLs for citation content preview).
   - Audit Logging: `PrivilegedInspectConversationUseCase`, `AiConversationAuditLog` table.

## 2. Trust Boundaries & Enforcement Mechanisms

| Boundary ID | Boundary Description                                              | Threat Model / Exposure                                     | Enforcement Mechanism & Responsible Component                                                                                                                                                                                                        |
| :---------- | :---------------------------------------------------------------- | :---------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TB-01**   | Browser $\leftrightarrow$ Backend API                             | Man-in-the-Middle, XSS, CSRF, Parameter Tampering           | TLS Termination, Helmet HTTP Security Headers, CORS Policy (`ConfigCorsConfiguration`), `GlobalSanitizationValidationPipe`.                                                                                                                          |
| **TB-02**   | Authenticated $\leftrightarrow$ Unauthenticated                   | Unauthorized Access, Resource Harvesting                    | `AuthenticationGuard` on controllers. Specific endpoints explicitly marked `@Public()` (`/health`, `/citations/.../content`).                                                                                                                        |
| **TB-03**   | Multi-Tenant Data Boundary                                        | Cross-Tenant Data Leakage (IDOR), Existence Enumeration     | `TrustedAiContext` (derives `tenantId` strictly from JWT, ignores payload injection); PostgreSQL composite keys `(id, tenantId)` on all models; repositories enforce `WHERE tenantId = :tenantId`. Non-matching IDs return HTTP 404 (Fail-Closed).   |
| **TB-04**   | User $\leftrightarrow$ User Boundary                              | Cross-User Conversation Tampering, Private History Snooping | `GetConversationUseCase`, `ReserveConversationTurnUseCase` enforce `conversation.userId === actorId`. Peer clinicians receive 404 on attempt to mutate or view private threads.                                                                      |
| **TB-05**   | Standard Staff $\leftrightarrow$ Privileged Oversight             | Unauthorized Clinical Audit Inspection                      | `@Roles('Owner')`, `@RequirePermissions('ai.conversations.audit')`, and `PrivilegedInspectConversationUseCase`. Requires minimum 10-char justification; commits immutable audit record (`AiConversationAuditLog`). Fail-closed if audit write fails. |
| **TB-06**   | API Transport $\leftrightarrow$ Background Execution Worker       | Worker Spoofing, In-flight Poisoning                        | Worker runs in-process within same trusted NestJS boundary; reads queued tasks strictly through tenant-scoped repository queries; locks turns via `leaseToken` and `leaseOwnerInstanceId`.                                                           |
| **TB-07**   | Backend Application $\leftrightarrow$ Object Storage              | Path Traversal, Bucket Traversal, Foreign Key Injection     | `StorageKeyUtil.generateObjectKey` prefixes all keys with `tenants/{tenantId}/`; `StorageKeyUtil.assertTenantOwnsKey` validates prefix and prevents `../` path traversal. Storage keys are internal and never exposed to the client.                 |
| **TB-08**   | Backend Application $\leftrightarrow$ Vector Database             | Unauthorized Vector Leakage, Similarity Spoofing            | `PrismaSemanticRetrievalRepository` and `PrismaLexicalRetrievalRepository` enforce SQL joins with `knowledge_documents` table filtering by `tenant_id` and authorized `document_id IN (...)`.                                                        |
| **TB-09**   | Backend Application $\leftrightarrow$ Ollama LLM Service          | LLM Hijacking, Unauthorized Prompt Probing                  | Local private loopback connection (`http://127.0.0.1:11434`); connection timeouts (`AI_OLLAMA_REQUEST_TIMEOUT_MS`); circuit breaker (`OllamaLLMAdapter`). Note: network boundary is unencrypted HTTP.                                                |
| **TB-10**   | Trusted Instructions $\leftrightarrow$ Untrusted Knowledge Chunks | Indirect Prompt Injection, Instruction Jailbreak            | `RAGContextBuilderService` wraps chunks in `<retrieved_evidence>` XML boundaries, escapes closing/breakout tags (`</evidence_chunk>`, `<system>`, `<instruction>`), and enforces strict JSON output schema (`format: 'json'`).                       |
| **TB-11**   | Internal Data $\leftrightarrow$ External API Responses            | Stack Trace Leaks, Connection String Exposure, PII Leakage  | `AiExceptionFilter` and `AiConversationExceptionFilter` catch domain/Prisma errors, scrub sensitive tokens/URIs, and map to standardized error DTOs. Response mappers omit hashes and lease tokens.                                                  |

## 4. Existing Security Controls Inventory & Classification

Each security control has been inspected and classified into one of five categories:

- **VERIFIED:** Directly supported by implementation and passing automated tests.
- **PARTIALLY VERIFIED:** Some implementation exists, but coverage or enforcement is incomplete.
- **DOCUMENTED ONLY:** Described in specifications/ADRs but lacking code verification.
- **MISSING:** No implementation identified.
- **UNKNOWN:** Insufficient evidence.

| :------------------- | :----------------------------------------------------------------------------- | :--------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

### 5.2 Identified Gaps in Security Test Coverage (Unexecuted or Missing)

- **Live Ollama Inference Security:** No test suite executes against a live untrusted model to test prompt injection payloads (current tests use mocked adapters).
- **DOCX / ZIP Bomb Extreme Boundary Tests:** While zip-bomb limits are implemented in code, dynamic unit tests feeding actual nested zip structures or multi-gigabyte decompression bombs were not observed in the test run.
- **SSRF Validation on Ollama URL:** No test asserts that an attacker with configuration access cannot point `AI_OLLAMA_BASE_URL` to internal cloud metadata endpoints (`169.254.169.254`).

## 6. Threat Modeling & Assessment Methodology

The assessment is conducted using industry standards:

1. **OWASP Top 10 for LLM Applications (2025):**
   - _LLM01: Prompt Injection:_ Assessed in `RAGContextBuilderService` and `GroundedGenerationService`.
   - _LLM02: Sensitive Information Disclosure:_ Assessed in error filters and excerpt streaming.
   - _LLM03: Supply Chain Vulnerabilities:_ Assessed in model digest pinning and embedding profile immutability.
   - _LLM06: Excessive Agency / Autonomy:_ Assessed in RAG generation scope (system only generates text/citations, executes no tool actions).
   - _LLM08: Vector and Embedding Weaknesses:_ Assessed in `PrismaSemanticRetrievalRepository` tenant boundaries.
2. **OWASP API Security Top 10 (2023):**
   - _API1: Broken Object Level Authorization (BOLA/IDOR):_ Assessed on all `/documents/:id`, `/conversations/:id`, and `/citations/:id` endpoints.
   - _API2: Broken Authentication:_ Assessed in JWT validation, token version revocation, and HMAC preview tokens.
   - _API3: Broken Object Property Level Authorization:_ Assessed in DTO validation and input sanitization pipes.
   - _API4: Unrestricted Resource Consumption:_ Assessed in file upload limits (10 MB), chunk limits, and throttler guards.
   - _API5: Broken Function Level Authorization:_ Assessed on `/audit-inspect` and `/ingestion/jobs`.
3. **STRIDE Threat Modeling:**
   - _Spoofing:_ Client turn ID and tenant injection attempts neutralized by server-side identity derivation.
   - _Tampering:_ HMAC SHA-256 signatures on preview tokens; SHA-256 checksums on documents and chunks.
   - _Repudiation:_ Immutable `AiConversationAuditLog` for privileged inspections.
   - _Information Disclosure:_ 404 returned for cross-tenant targets to avoid existence enumeration; stack traces stripped.
   - _Denial of Service:_ Zip bomb protection in DOCX parser; file size limits; lease timeouts for stalled turns.
   - _Elevation of Privilege:_ Pre-retrieval role-based scoping in `RetrievalSecurityPolicyService`.
