## 1. Executive Summary

Milestone **AI-10.2-03** implements and formally verifies the database referential integrity, domain entity invariants, repository provenance enforcement, and metadata sanitization boundaries governing knowledge documents, document versions, and generated chunks.

Every chunk stored in the Kynergy RAG system is now strictly and immutably bound to its authoritative parent document and document version, within an immutable tenant scope. Furthermore, client-controlled document content (such as Markdown frontmatter or PDF metadata) is actively sanitized at the domain model boundary to ensure that client-submitted metadata can never inject or override authorization keys (`tenantId`, `visibilityScope`, `roles`, `permissions`, etc.).

All 10 required integrity and adversarial verification test scenarios passed with 100% success, confirming end-to-end provenance integrity without regression across the core and API layers.

## 2. Invariants & Architecture Enforcement

### 2.1 Database Referential Integrity (`prisma/schema.prisma`)

Composite foreign keys enforce that chunks and ingestion jobs can never exist for a foreign tenant or become orphaned:

- **`KnowledgeDocument`**: Introduced composite unique constraint:
  ```prisma
  @@unique([id, tenantId], name: "unique_document_tenant")
  ```
- **`KnowledgeChunk`**: Strengthened document relation to bind on `[documentId, tenantId]`:
  ```prisma
  document KnowledgeDocument @relation(fields: [documentId, tenantId], references: [id, tenantId], onDelete: Cascade)
  ```
- **`IngestionJob`**: Strengthened document relation to bind on `[documentId, tenantId]`:
  ```prisma
  document KnowledgeDocument @relation(fields: [documentId, tenantId], references: [id, tenantId], onDelete: Cascade)
  ```

### 2.2 Domain Boundary & Metadata Sanitization (`DocumentChunk`)

In `packages/core/src/ai/domain/models/document-chunk.entity.ts`, the entity factory method `DocumentChunk.create()` strips all reserved security/authorization keys from incoming chunk metadata:

```typescript
const FORBIDDEN_METADATA_KEYS = new Set([
  'tenantid',
  'tenant_id',
  'visibilityscope',
  'visibility_scope',
  'uploadedby',
  'uploaded_by',
  'deletedat',
  'deleted_at',
  'roles',
  'permissions',
]);
```

Any client attempt to forge access clearance, tenant assignment, or visibility scopes via document metadata is eradicated before persistence or retrieval.

### 2.3 Repository Provenance Enforcement (`PrismaKnowledgeChunkRepository`)

In `packages/core/src/ai/infrastructure/persistence/prisma/repositories/prisma-knowledge-chunk.repository.ts`, chunk persistence is executed inside an atomic transaction with strict validation:

1. **Input Sanitization**: Rejects blank or whitespace-only `tenantId`, `documentId`, or `versionId` with `DocumentValidationException`.
2. **Document Existence & Soft-Delete Check**: Queries `knowledgeDocument` by `id`. If missing or if `deletedAt IS NOT NULL`, fails closed with `DocumentNotFoundException`.
3. **Tenant Ownership Match**: Verifies `doc.tenantId === cleanTenantId`. Any cross-tenant attempt throws `UnauthorizedDocumentAccessException`.
4. **Version Lineage Match**: Queries `documentVersion` by `id`. Confirms `ver.documentId === cleanDocId`; otherwise throws `DocumentNotFoundException`.
5. **Chunk Provenance Invariant Assertion**: Iterates through all chunks in the batch and verifies that `c.documentId === cleanDocId` and `c.documentVersionId === cleanVersionId`. Any mismatch immediately throws `DocumentValidationException`.
6. **Transactional Chunk Replacement**: Executes `deleteMany({ where: { documentVersionId: cleanVersionId } })` followed by `createMany(...)`, ensuring zero orphan chunks remain upon reprocessing.
7. **Tenant-Isolated Chunk Retrieval**: Implemented `findById(tenantId, chunkId)`, enforcing `where: { id: cleanChunkId, tenantId: cleanTenantId }` to prevent cross-tenant chunk exposure.
