## 2. Implemented Remediations Detail

### KY-UPLOAD-001: Antivirus & Malware Scanning Integration

- **Root Cause:** Original ingestion pipeline directly accepted files into storage without evaluating them for known malware signatures, EICAR test vectors, or macro payloads.
- **Authoritative Policy:** AI-10.3-05 Malware Scanning and Decompression Bomb Protection Decision.
- **Implemented Correction:**
  - Introduced `IMalwareScannerPort` and dual-tier `StreamMalwareScannerAdapter`.
  - **Tier 1 (In-Process Fast Heuristics):** Real-time pattern evaluation for standard EICAR antivirus test signatures, executable PE/ELF headers, and embedded VBA macros.
  - **Tier 2 (Private ClamAV Sidecar):** TCP streaming over `zINSTREAM` socket (64 KB chunks). Fails closed if scanner daemon is offline or returns an error.
  - Integrated scanning gate into `SecureDocumentUploadService` and `IngestionOrchestratorService`.
  - Quarantined documents are marked `status: DELETED`, job marked `FAILED` with `SECURITY_VIOLATION`, and excluded from retrieval.
- **Affected Files:**

### KY-UPLOAD-002: Ingress Limits & Multipart Denial-of-Service Defense

- **Root Cause:** Default Multer interceptor allowed unbounded form fields and unconstrained file sizes into heap memory before controller validation.
- **Authoritative Policy:** AI-10.3-02 Secure File Validation and Processing Policy, Section 3.
- **Implemented Correction:**
  - Defined `KNOWLEDGE_DOCUMENT_UPLOAD_MULTER_OPTIONS` in `AiDocumentController`:
    - `fileSize: 10 * 1024 * 1024` (10 MB maximum upload bound).
    - `files: 1` (strictly single file per request).
    - `fields: 10` (bounded form metadata).
    - `parts: 15` (bounded multipart envelope components).
  - Configured translation of `DocumentSizeLimitExceededException` to HTTP 413 `HttpStatus.PAYLOAD_TOO_LARGE`.
- **Affected Files:**
  - [`apps/api/src/ai/controllers/ai-document.controller.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/controllers/ai-document.controller.ts)

### KY-UPLOAD-003: Parser Isolation, Timeouts, and Character Bounds

- **Root Cause:** In-process parsing using `unpdf`, `mammoth`, and `marked` ran without processing timeouts or extracted text ceilings, risking thread starvation or OOM on complex documents.
- **Authoritative Policy:** AI-10.3-06 Secure Document Parser Isolation and Resource Controls Report.
- **Implemented Correction:**
  - Implemented `ParserSandboxService`:
    - Enforces 30-second processing timeout via `Promise.race` (`DEFAULT_PARSER_TIMEOUT_MS = 30000`).
    - Enforces 5,000,000 character maximum extraction limit (`DEFAULT_MAX_EXTRACTED_CHARS = 5000000`).
    - Implemented hardened `executeSafeSubprocess` using `child_process.spawn` with `shell: false`, discrete argument arrays, environment variable stripping (scrubbing `DATABASE_URL`, `JWT_SECRET`), and SIGTERM/SIGKILL process-group reaping.
    - Sanitizes extracted text: strips ASCII control characters (`\x00-\x08`, `\x0B-\x1F`), ANSI terminal escape sequences, and HTML `<script>` tags, while strictly preserving legitimate whitespace (`\t`, `\n`, `\r`) and Spanish clinical accents (`á, é, í, ó, ú, ñ`).
- **Affected Files:**
  - [`apps/api/src/ai/services/parser-sandbox.service.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/parser-sandbox.service.ts)

### KY-UPLOAD-004: Opaque Storage Identifiers and Path Sanitization

- **Root Cause:** Client-provided filenames could manipulate storage paths if used directly, exposing directory traversal (`../`) and Windows reserved device collisions (`CON`, `PRN`, `AUX`).
- **Authoritative Policy:** AI-10.3-04 Private Document Storage and Temporary File Security Report.
- **Implemented Correction:**
  - Complete decoupling of user-provided filenames from physical storage keys.
  - Internal storage keys are generated using purely synthetic UUIDs:
    `tenants/{tenantId}/knowledge_base/{year}/{month}/{randomUuid12}-{uuid}.{ext}`
  - Original filename is sanitized (`StorageKeyUtil.sanitizeFilename`) and stored strictly as inert display metadata (`originalFileName`) for citations and UI.
  - Ephemeral scratch directories created via `TempFileStorageService` enforce POSIX permissions `0700` (directories) and `0600` (files) and guaranteed cleanup in `finally` blocks.
- **Affected Files:**
  - [`apps/api/src/platform/storage/utils/storage-key.util.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/platform/storage/utils/storage-key.util.ts)

### KY-UPLOAD-005: Ingestion Admission & Premature Retrieval Elimination

- **Root Cause:** Ingestion jobs that fail during parsing or background scanning could leave chunks or document metadata partially queryable.
- **Authoritative Policy:** AI-10.3-07 Secure Extraction and RAG Ingestion Lifecycle Integration Report.
- **Implemented Correction:**
  - Strict sequential state machine: `UPLOADED` -> `VALIDATING` -> `PROCESSING` -> `INDEXING` -> `READY`.
  - Cryptographic checksum of stored object is re-verified at every stage and retry; discrepancy halts pipeline immediately with `CHECKSUM_MISMATCH`.
  - Semantic and lexical retrieval repositories strictly filter on `ig.status = 'ACTIVE'`, `kd.deleted_at IS NULL`, and `kd.status = 'READY'`.
  - Quarantined or failed documents yield 0 retrievable chunks.
- **Affected Files:**
  - [`apps/api/src/ai/services/ingestion-orchestrator.service.ts`](file:///c:/Projects/kinergy-platform/apps/api/src/ai/services/ingestion-orchestrator.service.ts)

### KY-UPLOAD-006: Diagnostic Privacy & Error Scrubbing

- **Authoritative Policy:** AI-10.3-08 Secure File Processing Failures and Operational Resilience Report.

## 3. Dependency and Infrastructure Management

### A. Runtime Dependencies

- **No unnecessary external dependencies introduced:**
  - Parser libraries are pure JavaScript: `unpdf` (^2.2.1), `mammoth` (^1.13.0), `marked` (^16.4.1), and native `TextDecoder`.
  - Cryptographic operations use native Node.js `crypto` (`crypto.createHash`, `crypto.randomUUID`).
  - Antivirus scanning uses streaming TCP client socket (`net.Socket`) for ClamAV daemon communication; zero third-party agent binaries or SaaS SDKs added to Node dependencies.

### B. Infrastructure Configuration & Deployment Requirements

1. **ClamAV Sidecar Container:**
   - Production deployments run `clamav/clamav:latest` as an isolated container sidecar on the private network (`CLAMAV_HOST=clamav-daemon`, `CLAMAV_PORT=3310`).
   - Signature updates run automatically via `freshclam` on a 2-hour cron inside the sidecar.
   - For local development and test environments, `StreamMalwareScannerAdapter` automatically falls back to in-process fast heuristic scanning when `CLAMAV_HOST` is unset.
2. **Container Privilege Model:**
   - Worker and API containers run strictly as unprivileged user (`USER node` in Dockerfile).
   - Shell execution is disabled (`shell: false`).
3. **Storage Security:**
   - S3/MinIO bucket access is private by default; zero public read or write policies.
   - Presigned URLs for temporary downloads have a maximum lifespan of 15 minutes.

## 4. Migration & Existing-File Handling Strategy

To ensure that legacy files previously uploaded under earlier versions comply with AI-10.3 standards without compromising data availability:

1. **Identification Without Content Exposure:**
   - Identify legacy documents via database metadata query:
     ```sql
     SELECT id, tenant_id, title, status, created_at
     FROM knowledge_documents
     WHERE deleted_at IS NULL AND created_at < '2026-11-27T00:00:00Z';
     ```
   - Content buffers and raw text are never logged or exposed during audit queries.

2. **No Unvalidated Reprocessing:**
   - In accordance with AI-10.3-07, any re-indexing, re-chunking, or retry of existing documents **strictly re-executes full validation and malware scanning**:
     - `IngestionOrchestratorService.processJob` downloads the physical buffer from storage, re-computes the SHA-256 checksum, asserts signature match, and passes the buffer through `StreamMalwareScannerAdapter`.
     - Legacy documents containing unverified bytes or corrupted checksums cannot bypass security gates upon re-processing.

3. **Retention & Recovery Policy:**
   - No documents are deleted without approval. If a legacy document fails scanning during scheduled backfill, it is placed in `QUARANTINE` state (`status: DELETED`) preserving the original file in storage for forensic analysis while immediately revoking retrieval eligibility.

## 6. Residual Risks & Deferred Items

### Residual Risks

1. **Zero-Day Exploit Payloads in Valid PDF Syntax:** While active content (`/Launch`, `/JavaScript`) is statically detected and stripped, weaponized font or complex PostScript interpreter exploits remain an industry-wide challenge. This is mitigated through pure JavaScript parsing (`unpdf`) with no native binary bindings (no Ghostscript/Poppler) and 30s execution timeouts.
2. **Subprocess Isolation on Windows Dev Environments:** `executeSafeSubprocess` executes within Node on Windows development workstations. Full container seccomp/AppArmor isolation is enforced at the Linux container deployment boundary.

### Deferred Items

- **Dedicated ICAP Appliance Integration:** Offloading ClamAV scanning to dedicated enterprise ICAP servers (e.g., Symantec, Trend Micro) is deferred to enterprise on-premise deployment tiers. The `IMalwareScannerPort` abstraction is already decoupled and ready to support an `IcapMalwareScannerAdapter`.
