### 3.1 Tables

- `ai_conversations`: Top-level conversation session entity.
- `ai_conversation_turns`: Bounded turn exchange entity (Turn $N$).
- `ai_conversation_messages`: Individual user prompts and assistant attempts.
- `ai_conversation_audit_logs`: Independently retained clinical inspection audit record.

## 4. Foreign Keys, Constraints, and Index Definitions

### 4.1 Composite Foreign Keys (Tenant & Conversation Boundary)

1. **Turn $\to$ Conversation:**
   ```sql
   ALTER TABLE "ai_conversation_turns"
     ADD CONSTRAINT "ai_conversation_turns_conversation_id_tenant_id_fkey"
     FOREIGN KEY ("conversation_id", "tenant_id")
     REFERENCES "ai_conversations"("id", "tenant_id")
     ON DELETE CASCADE ON UPDATE CASCADE;
   ```
2. **Message $\to$ Conversation:**
   ```sql
   ALTER TABLE "ai_conversation_messages"
     ADD CONSTRAINT "ai_conversation_messages_conversation_id_tenant_id_fkey"
     FOREIGN KEY ("conversation_id", "tenant_id")
     REFERENCES "ai_conversations"("id", "tenant_id")
     ON DELETE CASCADE ON UPDATE CASCADE;
   ```
3. **Message $\to$ Turn:**
   ```sql
   ALTER TABLE "ai_conversation_messages"
     ADD CONSTRAINT "ai_conversation_messages_turn_id_conversation_id_tenant_id_fkey"
     FOREIGN KEY ("turn_id", "conversation_id", "tenant_id")
     REFERENCES "ai_conversation_turns"("id", "conversation_id", "tenant_id")
     ON DELETE CASCADE ON UPDATE CASCADE;
   ```
4. **Turn $\to$ Active Assistant Attempt Message (Controlled Single-Column FK):**
   ```sql
   ALTER TABLE "ai_conversation_turns"
     ADD CONSTRAINT "ai_conversation_turns_active_attempt_id_fkey"
     FOREIGN KEY ("active_attempt_id")
     REFERENCES "ai_conversation_messages"("id")
     ON DELETE SET NULL ON UPDATE CASCADE;
   ```

---

### 4.2 Partial Unique Indexes

1. **Single Active Assistant Generation Attempt per Conversation:**
   ```sql
   CREATE UNIQUE INDEX "ai_conversation_active_generation_idx"
     ON "ai_conversation_messages"("conversation_id")
     WHERE "role" = 'ASSISTANT' AND "status" IN ('PENDING', 'STREAMING');
   ```
   _Guarantees:_ Mathematically impossible for two generation workers to concurrently stream or hold active status in the same conversation.
2. **Single User Message per Turn:**
   ```sql
   CREATE UNIQUE INDEX "uq_turn_single_user_message"
     ON "ai_conversation_messages"("turn_id")
     WHERE "role" = 'USER';
   ```
   _Guarantees:_ A turn can never possess more than one initiating user question.
3. **Single Canonical Assistant Message per Turn:**
   ```sql
   CREATE UNIQUE INDEX "uq_turn_single_canonical_assistant"
     ON "ai_conversation_messages"("turn_id")
     WHERE "role" = 'ASSISTANT' AND "is_canonical" = TRUE;
   ```
   _Guarantees:_ Only one assistant message per turn can ever be designated as the canonical response.

---

### 4.3 Check Constraints

1. **Canonical Message Requires SUCCESS (`chk_canonical_requires_success`):**
   ```sql
   CHECK ("is_canonical" = FALSE OR ("role" = 'ASSISTANT' AND "status" = 'SUCCESS'))
   ```
2. **Terminal Attempts Cannot Retain Active Leases (`chk_terminal_attempt_no_active_lease`):**
   ```sql
   CHECK (
     "status" IN ('PENDING', 'STREAMING')
     OR ("lease_token" IS NULL AND "lease_owner_instance_id" IS NULL AND "lease_expires_at" IS NULL)
   )
   ```
3. **Positive Indices and Numbers:**
   - `chk_turn_index_positive`: `CHECK ("turn_index" >= 1)`
   - `chk_active_attempt_number_positive`: `CHECK ("active_attempt_number" >= 1)`
   - `chk_sequence_number_positive`: `CHECK ("sequence_number" >= 1)`
   - `chk_attempt_number_positive`: `CHECK ("attempt_number" >= 1)`

---

### 4.4 PostgreSQL Triggers

1. **Deferred Active Attempt Validation Trigger (`trg_validate_turn_active_attempt`):**
   - Fires `AFTER INSERT OR UPDATE OF active_attempt_id ON ai_conversation_turns DEFERRABLE INITIALLY DEFERRED`.
   - Validates that `active_attempt_id` belongs to the exact same `turn_id`, `conversation_id`, and `tenant_id` with `role = 'ASSISTANT'`.
   - Allows safe two-step insertion while guaranteeing relational consistency at transaction commit.
2. **Message Immutability Trigger (`trg_protect_message_immutability`):**
   - Fires `BEFORE UPDATE ON ai_conversation_messages`.
   - Enforces that `role`, `turn_id`, `conversation_id`, and `tenant_id` are strictly immutable once inserted.

## 7. Known Limitations & Deviations

### Deviations from AI-09.3-BE.01.8:

- **Zero substantive deviations.** The implementation adhered 100% to the schema, constraints, indexes, triggers, and permission registrations approved in `AI-09.3-BE.01.8`.
- In raw SQL queries executed inside integration tests, `updated_at` timestamps were explicitly supplied (`NOW()`) because PostgreSQL does not auto-populate Prisma's `@updatedAt` directive on manual raw `INSERT` statements.

### Known Limitations (Milestone Boundaries):

- **Audit Deletion:** Hard-deleting `ai_conversations` drops turns and messages while preserving `ai_conversation_audit_logs`. Formal legal/regulatory retention policies (e.g. 7-year medical audit retention vs GDPR Article 17 Right to Erasure) require organizational policy definition before production deployment.
- **Application Services Pending:** This milestone established database-level constraints only. Use cases, repository adapters, and controllers will be implemented in subsequent sub-phases.
