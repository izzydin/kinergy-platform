## 1. Executive Summary

Milestone **FE.05** delivers reliable, server-authoritative retrieval of individual conversations and their persisted message histories in the Kynergy Intelligence assistant. Authenticated users can open previous conversations and view persisted canonical messages in deterministic chronological order with grounded RAG citations, execution telemetry, and lifecycle status indicators.

Building upon the persistent API client ([FE.01](file:///c:/Projects/kinergy-platform/docs/ai/AI-09/AI-09.3-FE.01.04-acceptance.md)), TanStack Query cache architecture ([FE.02](file:///c:/Projects/kinergy-platform/docs/ai/AI-09/AI-09.3-FE.02-query-cache-architecture.md)), creation flow ([FE.03](file:///c:/Projects/kinergy-platform/docs/ai/AI-09/AI-09.3-FE.03-conversation-creation.md)), and conversation history sidebar ([FE.04](file:///c:/Projects/kinergy-platform/docs/ai/AI-09/AI-09.3-FE.04-conversation-listing.md)), FE.05 accomplishes:

1. **Server-Authoritative Detail & History Retrieval:** Integrated `GET /api/v1/ai/conversations/:id` and `GET /api/v1/ai/conversations/:id/messages` into [`chat-workspace.tsx`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/components/chat-workspace.tsx) via the typed `useConversation` and `useConversationMessages` TanStack Query hooks, scoped strictly by authenticated `tenantId` and `userId`.
2. **Deterministic Sequence Ordering:** Reconstructed messages adhere strictly to PostgreSQL monotonic sequence ordering `(sequenceNumber ASC, id ASC)`. Database insertion order is never relied upon as an ordering guarantee.
3. **Canonical Message Reconstruction:** Adapts canonical backend `MessageResponse` payloads to domain `ChatMessage` models via [`toDomainChatMessage`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/adapters/conversation-status.adapter.ts). Non-canonical superseded attempts are excluded by backend query filters, ensuring only accepted canonical responses appear in the conversation thread.
4. **Preservation of Rich Content, RAG Citations & Telemetry:**
   - User messages render right-aligned with full multiline pre-wrap formatting.
   - Assistant messages render formatted Markdown, verifiable source citations tray with document title, chunk index, page number, and relevance score, and telemetry footer (model name, latency in milliseconds, grounded indicator).
   - Incomplete and terminal message statuses (`pending`, `success`, `error`, `cancelled`, `interrupted`) are preserved without loss of partial content.
5. **Elimination of Stale-Message Leakage Across Conversation Switches:**
   - Removed `placeholderData: keepPreviousData` from `useConversationMessages` to prevent cross-conversation data retention during route parameter transitions.
   - Added `key={conversationId ?? 'new'}` to [`chat-message-feed.tsx`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/components/chat-message-feed.tsx) to force clean unmounting and scroll reset when switching threads.
   - Guarded active conversation selection to immediately return `null` while fetching a newly selected conversation ID.
6. **Robust Error Distinguishability:**
   - 404 responses (`NotFoundError`, cross-tenant access, or nonexistent conversation) render the contextual "Conversación no encontrada" screen with an "Iniciar nueva conversación" call to action.
   - 500 / network transport failures render the "Error al cargar conversación" screen with a functional "Reintentar" button.
   - The UI never silently interprets a failed request as an empty conversation.
7. **100% Quality Gates Cleared:**

## 2. Repository Investigation & Authoritative Ordering Contract

### 2.1 Backend Contract & Sequence Mechanism

Investigation of `apps/api/src/ai/conversation/ai-conversation.controller.ts`, `packages/core/src/ai/application/use-cases/get-message-history.use-case.ts`, and `prisma/schema.prisma` revealed:

1. **Monotonic Sequence Enforcement:**
   - In Prisma schema, `AiConversationMessage` enforces `@@unique([conversationId, sequenceNumber], name: "uq_conversation_sequence_number")`.
   - Every user message and assistant placeholder is assigned a strictly increasing integer sequence number during turn reservation.
2. **Canonical Query Ordering:**
   - `PrismaAiConversationMessageRepository.listCanonicalHistory` queries messages with:
     ```prisma
     where: {
       tenantId,
       conversationId: convIdStr,
       AND: [
         { OR: [{ role: 'USER' }, { isCanonical: true }] },
         ...
       ]
     },
     orderBy: [{ sequenceNumber: 'asc' }, { id: 'asc' }]
     ```
   - This eliminates superseded generation attempts and guarantees deterministic sequence ordering across all requests.
3. **Tenant & Owner Isolation:**
   - Both `getConversation` and `getMessageHistory` perform preflight tenant boundary checks. Cross-tenant or nonexistent requests throw `ConversationNotFoundError`, which the global exception filter maps to HTTP 404 to prevent resource enumeration attacks.

### 3.2 Active Conversation Reconciliation

```tsx
const activeConversation = useMemo(() => {
  if (!conversationId) return null;

  if (persistentConversation && persistentConversation.id === conversationId) {
    const messages = (persistentMessagesData?.messages ?? []).map(toDomainChatMessage);
    return {
      id: persistentConversation.id,
      title: persistentConversation.title,
      createdAt: persistentConversation.createdAt,
      updatedAt: persistentConversation.updatedAt,
      messages,
      tenantId,
      userId,
    };
  }

  if (localConversation && localConversation.id === conversationId) {
    return localConversation;
  }

  return null;
}, [
  conversationId,
  persistentConversation,
  persistentMessagesData,
  localConversation,
  tenantId,
  userId,
]);
```

### 3.3 Elimination of Stale Messages During Conversation Switching

To prevent message leakage when switching from `conv-A` to `conv-B`:

1. **Cache Policy:** Removed `placeholderData: keepPreviousData` from `useConversationMessages` in [`use-conversation-queries.ts`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/hooks/use-conversation-queries.ts#L171-L187). When the query key changes to a new `conversationId`, message state immediately resets to `undefined`.
2. **Identity Verification:** The `activeConversation` memo checks `persistentConversation.id === conversationId`. If the route ID changes, `activeConversation` immediately evaluates to `null`.
3. **Feed Keying:** `<ChatMessageFeed key={conversationId ?? 'new'} ... />` guarantees React completely unmounts the previous message feed instance, clearing previous scroll position, DOM items, and internal UI state.
4. **Loading Gate:** `isLoadingConversation` activates immediately if either query is fetching and current conversation data is not yet in hand:
   ```tsx
   const isLoadingConversation = Boolean(
     conversationId && !activeConversation && (isFetchingPersistent || isFetchingLocal),
   );
   ```

### 3.4 Message Reconstruction Adapter ([`conversation-status.adapter.ts`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/adapters/conversation-status.adapter.ts))

The pure adapter `toDomainChatMessage` translates backend `MessageResponse` DTOs into domain `ChatMessage` objects:

```ts
export function toDomainChatMessage(msg: MessageResponse): ChatMessage {
  const legacyRole = mapBackendRoleToLegacy(msg.role);
  const legacyStatus = mapBackendMessageStatusToLegacy(msg.status);

  return {
    id: msg.id,
    role: legacyRole,
    content: msg.content,
    createdAt: msg.createdAt,
    status: legacyStatus,
    grounded: Boolean(msg.sources && msg.sources.length > 0),
    sources: msg.sources?.map((s) => ({
      documentId: s.documentId,
      documentTitle: s.documentTitle,
      chunkId: s.chunkId,
      pageNumber: s.pageNumber ?? undefined,
      headingPath: s.headingPath ?? undefined,
      relevanceScore: s.relevanceScore,
      sourceStrategy: s.sourceStrategy ?? undefined,
    })),
    metadata:
      legacyRole === 'assistant'
        ? {
            model: 'assistant',
            retrievalCount: msg.sources?.length ?? 0,
            latencyMs:
              msg.completedAt && msg.createdAt
                ? Math.max(
                    0,
                    new Date(msg.completedAt).getTime() - new Date(msg.createdAt).getTime(),
                  )
                : 0,
          }
        : undefined,
    error: legacyStatus === 'error' ? 'Error al generar la respuesta.' : undefined,
  };
}
```
