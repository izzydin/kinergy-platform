## 2. Authorization Results

1. **Authentication Boundary:** Unauthenticated requests (`user = null`) to `@Post('documents')` throw `UnauthorizedException` (`401`).
2. **Tenant Clearance:** Authenticated users missing a tenant identifier (`tenantId = ''`) are blocked by `extractAuthContext` with `ForbiddenException` (`403`).
3. **Role-Based Clearance:** Users with `Physiotherapist` role attempting to upload documents with `VisibilityScope.MANAGEMENT` are rejected by `RetrievalSecurityPolicyService.resolveAllowedVisibilityScopes` with `ForbiddenException` (`403`).
4. **Identity Binding:** Client attempts to forge `uploadedBy` in request bodies are ignored. The backend derives the author identity exclusively from `user.id` / `user.userId` of the verified token.
5. **Anti-Enumeration 404s:** Cross-tenant access attempts to `/documents/:id/content` or `/documents/:id` return uniform `404 Not Found` responses, preventing attackers from mapping valid resource identifiers in other tenants.
6. **Quarantine Inaccessibility:** Quarantined documents (`status: DELETED`) return `404 Not Found` for content download and preview requests.

---

## 3. File Validation Results

1. **True Content Sniffing:** Validation does not rely on request `Content-Type` headers. Magic bytes (`%PDF-`, `PK\x03\x04`, UTF-8 text headers) are inspected directly from buffer headers.
2. **Disallowed Formats:** Executables (`.exe`, `.sh`, `.php`), system libraries, ELF binaries, and non-supported archives are rejected with `UnsupportedDocumentFormatException` (`415 Unsupported Media Type`).
3. **MIME/Signature Mismatch:** Declaring `application/pdf` for an audio RIFF container or an executable payload is caught by `assertExtensionMatchesFormat` and rejected with `DocumentContentMismatchException` (`400 Bad Request`).
4. **Structural Container Inspection:** Truncated PDF files, corrupted central directories in DOCX packages, and missing headers fail structural validation (`DocumentMalformedException`).
5. **Polyglot Neutralization:** Ambiguous files (e.g. `GIF89a` prepended to PDF commands) are caught by binary signature checks and rejected fail-closed.
6. **Extension Spoofing:** Double extensions (e.g. `invoice.pdf.exe`) are evaluated by extracting the true trailing extension (`.exe`), defeating extension-spoofing attacks.

---

## 4. Size and Resource-Limit Results

1. **Upload Size Boundaries:** Buffers at or below 10 MB are admitted. Buffers exceeding 10 MB (e.g. 11 MB) throw `DocumentSizeLimitExceededException` (`413 Payload Too Large`).
2. **Content-Length Spoofing:** When a client declares `size: 500` in metadata while transmitting an 11 MB buffer, validation evaluates `buffer.length`, discarding the spoofed value.
3. **Multipart Bounding:** `KNOWLEDGE_DOCUMENT_UPLOAD_MULTER_OPTIONS` configures Multer to enforce `fileSize: 10MB`, `files: 1`, `fields: 10`, and `parts: 15`, mitigating multipart denial-of-service vectors.
4. **Extracted Character Ceilings:** Parsed document representations exceeding 5,000,000 characters trigger `ExtractionResourceLimitExceededException` in `ParserSandboxService`.
5. **Sandbox Timeout Enforcement:** Long-running or stalled parser tasks abort after timeout (default: 30s; 40ms in test harness) with `ExtractionTimeoutException`.

---

## 5. Filename and Path Traversal Results

1. **Synthetic Storage Key Generation:** Client-provided filenames are completely discarded when constructing internal storage paths. Storage keys follow the synthetic UUID pattern:
   `knowledge_base/<uuid>.<ext>`
2. **Directory Traversal Neutralization:** Inputs such as `../../../../etc/passwd.pdf`, `C:\Windows\System32\cmd.exe.pdf`, and `%2e%2e%2fboot.ini.pdf` cannot escape storage boundaries. The internal storage key remains strictly anchored to the tenant folder.
3. **Null-Byte Injection:** Filenames containing embedded null characters (e.g. `patient.pdf\0.exe`) are intercepted during initial filename validation in `DocumentContentValidatorService` and rejected immediately.
4. **OS Reserved Names:** Windows reserved device names (`CON.pdf`, `PRN.pdf`, `AUX.docx`, `NUL.txt`) are handled safely without device locking or filesystem corruption.
5. **Collision Resistance:** Multiple uploads sharing the same display name (`protocol.pdf`) receive distinct synthetic UUIDs, preventing storage overwrites.
6. **Command Metacharacters:** Filenames containing shell metacharacters (`; rm -rf /`, `$(whoami)`) are treated purely as inert metadata labels. Subprocess invocation disables shell execution (`shell: false`).

---

## 6. Malware and Archive Results

1. **EICAR Detection:** Buffers matching the standard EICAR test signature are flagged `INFECTED` by `IMalwareScannerPort`. Upload is aborted fail-closed with `DocumentSecurityRiskException`. Client error messages redact the virus name.
2. **Fail-Closed Availability:** When the malware scanner daemon is unreachable (`ECONNREFUSED`), the upload pipeline fails closed (`503 Service Unavailable`), refusing to admit unscanned content.
3. **ZIP Path Traversal:** DOCX packages containing internal ZIP entries with relative traversal sequences (`../../malicious.xml`) or absolute paths are rejected with `DocumentSecurityRiskException`.
4. **Decompression Bomb Defense:** DOCX packages where individual entry compression ratios exceed 100:1 or total uncompressed volume exceeds 50 MB trigger decompression bomb protection (`DocumentSecurityRiskException`).
5. **Nested Archive Rejection:** DOCX containers containing nested `.zip`, `.tar`, or `.gz` archives are rejected to prevent recursive decompression attacks.
6. **Ephemeral Scratch Cleanup:** When archive validation or extraction fails, intermediate scratch directories created by `TempFileStorageService` are completely removed.

---

## 7. Parser Isolation Results

1. **Subprocess Isolation:** `ParserSandboxService.executeSafeSubprocess` spawns child processes using Node `execFile` with explicit argument arrays, preventing shell injection.
2. **Process Reaping & Zombie Prevention:** Timed-out subprocesses are killed via `SIGTERM` / `SIGKILL` process-group termination, ensuring no orphaned processes remain.
3. **Environment Secret Stripping:** Subprocess environments are scrubbed of all sensitive keys (`DATABASE_URL`, `JWT_SECRET`, `AWS_SECRET_ACCESS_KEY`), exposing only a minimal whitelist of system paths.
4. **Output Sanitization:** Non-printable ASCII control characters (`\x00`, `\x08`), ANSI escapes, and dangerous HTML script tags (`<script>`) are stripped from extracted paragraph text.
5. **Diagnostic Path Redaction:** Parser error messages disclosing host filesystem paths (`C:\inetpub\...`, `/var/run/...`) are scrubbed by `sandbox.scrubSensitiveDiagnostics`, replacing paths with `[REDACTED_PATH]`.

---

## 8. Ingestion Lifecycle Results

1. **Admission Gate:** Malformed, unsupported, or oversized files are halted during upload validation and never reach the parsing stage.
2. **Quarantine Halt:** If malware is discovered during background scanning, `IngestionOrchestratorService` soft-deletes the document, marks the job `FAILED` with `SECURITY_VIOLATION`, and halts pipeline execution before chunking.
3. **Chunk Provenance Integrity:** Every persisted chunk is strictly bound to authoritative `tenantId`, `documentId`, and `versionId` generated by the backend. Text claims within documents cannot forge chunk provenance.
4. **Security Re-Execution on Retry:** Retried jobs re-execute checksum validation and malware scanning from scratch before parsing resumed.
5. **Vector Indexing Guard:** Jobs that fail during extraction or normalization never reach `IDocumentIndexingPort.indexDocument`, preventing unvalidated or corrupted chunks from entering vector retrieval.

---

## 9. Multi-Tenant Concurrency Results

1. **Simultaneous Tenant Isolation:** Concurrent uploads initiated by separate tenants (`tenant_clinic_a` and `tenant_clinic_b`) execute simultaneously without cross-tenant metadata leakage or version collision.
2. **UUID Storage Collision Resistance:** Three concurrent uploads of identical filenames produce three distinct synthetic storage keys in object storage.
3. **Fault Isolation:** A malformed upload that fails in Tenant A has zero impact on a simultaneous valid upload in Tenant B.
4. **Scratch Directory Non-Collision:** Concurrent scratch directory allocations by `TempFileStorageService.createIsolatedTempDir` generate unique paths under the tenant root, preventing file overwrite races.

## 12. Recommended Remediation & Hardening Roadmap

1. **Continuous Antivirus Signature Updates:** Ensure production deployment automates `freshclam` updates for ClamAV daemon containers on a 2-hour schedule.
2. **ICAP Protocol Integration:** For high-volume enterprise deployments, evaluate offloading scanning to dedicated ICAP appliances (e.g. Trend Micro, Symantec).
3. **Seccomp & AppArmor Profiles:** In Linux container runtimes, apply restrictive seccomp profiles to the worker container to deny `execve` of shell interpreters.
