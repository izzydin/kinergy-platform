# ADR-AI-004: Embedding and Generation Model Abstraction Architecture

## 1. ADR Identifier

ADR-AI-004

## 2. Title

Independent Provider Abstractions for LLM Generation and Dense Embeddings with BGE-M3 Standardization

## 3. Status

Proposed

## 4. Date

2026-11-19

## 5. Context

In enterprise RAG architectures, generative language models (LLMs) and dense embedding models serve fundamentally different mathematical and operational purposes. LLMs generate natural language completions from prompts, while embedding models project text into fixed-dimensional geometric vector spaces. Treating these as a monolithic "AI Provider" tightly couples retrieval to generation, prevents independent model scaling, and obscures vector space versioning. Furthermore, changing an embedding model invalidates all existing vector distances, requiring complete database re-indexing.

## 6. Problem Statement

How should LLM generation and vector embedding generation be decoupled behind independent application abstractions such that either model can be upgraded or replaced without breaking the domain core, mixing incompatible vector spaces, or forcing simultaneous migrations?

## 7. Decision Drivers

- **Separation of Concerns**: Isolate token generation from high-dimensional geometric encoding.
- **Vector Space Invariance**: Guarantee that vectors generated by different models or dimensionalities are never compared.
- **Multi-Lingual Precision**: Support technical biomechanical, fitness, and administrative terminology across Spanish and English.
- **Provider Portability**: Allow swapping Ollama for cloud or alternative local inference backends via adapter replacement.
- **Fail-Fast Type Safety**: Trap dimension mismatches at the domain boundary before database insertion.

## 8. Decision

We establish **independent, technology-neutral port abstractions** for generative LLMs and embedding models, and propose **BAAI/BGE-M3** as the canonical initial embedding model:

1. **Independent Port Separation**:
   - `ILLMProviderPort`: Governs text generation, token streaming (`AsyncIterable<string>`), stop sequences, temperature, and client cancellation (`AbortSignal`).
   - `IEmbeddingProviderPort`: Governs single and batch vector generation (`number[][]`), dimension contracts (`getDimensions() -> 1024`), and model identity (`getModelIdentifier()`).
2. **BGE-M3 Model Selection**:
   - Generates **1,024-dimensional** dense vectors.
   - High semantic accuracy across English and Spanish.
   - Fits within host GPU VRAM (~1.5 GB footprint).
   - Supports extended context window (up to 8,192 tokens), preventing clipping of complex operational SOPs.
3. **Strict Vector-Space Lineage & Immutability**:
   - The database records the generating model name and vector space ID (`vector_space_id: "kinergy-bge-m3-cosine-v1"`).
   - **Cross-Model Mixing Prohibited**: Embeddings generated by different models (e.g. BGE-M3 vs. text-embedding-ada-002) occupy different geometric spaces; cosine similarity between them is mathematically meaningless.
   - Upgrading the embedding model requires an explicit re-indexing workflow: all documents must be re-embedded into a new vector column or table partition before traffic is cut over.
4. **Domain Value Object Validation**:
   - `VectorEmbedding` value object strictly validates that `values.length === 1024`. Any dimension mismatch throws an immediate domain exception before reaching persistence adapters.

## 9. Alternatives Considered

- **Alternative 1: Monolithic "AI Client" Port**: Single interface handling both `complete()` and `embed()`. _Rejected_: Violates Interface Segregation Principle; prevents using different providers for generation and embeddings (e.g., local BGE-M3 embeddings combined with cloud Gemini LLM).
- **Alternative 2: all-MiniLM-L6-v2 (384 dimensions)**: Smaller, faster embedding model. _Rejected_: Weaker multi-lingual semantic retention in Spanish medical/kinesiology domains; lower precision on complex multi-paragraph policies.
- **Alternative 3: OpenAI text-embedding-3-small**: Cloud embedding API. _Rejected_: Sends all company documentation bytes over public networks; introduces continuous operational cost and external internet dependencies for document uploads.

## 10. Positive Consequences

- **Independent Scaling**: LLM generation and embedding generation can be throttled, updated, or hosted on separate infrastructure independently.
- **Mathematical Integrity**: Vector space tagging prevents corrupted retrieval distances caused by model version drift.
- **Bilingual Accuracy**: High retrieval recall for both English and Spanish clinical/gym queries.
- **Sub-Millisecond Unit Testing**: Application use cases can test retrieval logic using mock deterministic embedding arrays without downloading 1.5 GB model weights.

## 11. Negative Consequences

- 1,024 dimensions require ~4 KB of raw float storage per chunk, slightly higher than 384-dimensional models.
- Upgrading the embedding model in the future requires full background re-indexing of all ingested documents.

## 12. Security Implications

- Embedding generation runs 100% locally on host GPU; no document text leaves the platform boundary during indexing.
- Dimension assertions prevent malformed payload attacks intended to corrupt vector indexes.

## 13. Operational Implications

- GPU VRAM allocation is fixed: ~1.5 GB dedicated to BGE-M3 alongside ~2.8 GB for Qwen 4B.
- Document processing can batch up to 16 chunks per embedding inference pass to maximize GPU tensor core utilization.

## 14. Dependencies

- Ollama runtime with `bge-m3:latest` model weights pulled.
- PostgreSQL `vector(1024)` column definition.

## 15. Implementation Implications

- Define `IEmbeddingProviderPort` in `packages/core/src/ai/ports/outbound/embedding-provider.port.ts`.
- Implement `OllamaEmbeddingAdapter` in `apps/api/src/ai/adapters/embedding/ollama-embedding.adapter.ts`.
- Bind adapter to injection token `AI_EMBEDDING_PROVIDER_TOKEN` in `AiModule`.

## 16. Validation Requirements

- Unit test asserting that `VectorEmbedding` throws `EmbeddingDimensionMismatchException` when initialized with array length $\neq 1024$.
- Integration test verifying that `OllamaEmbeddingAdapter` generates exactly 1,024 floats for sample text inputs.

## 17. Conditions for Reconsideration

- If specialized medical or biomechanical embedding models demonstrate substantially superior retrieval accuracy on Kinergy's evaluation dataset.
- If memory constraints require downgrading to a 512- or 768-dimensional model.
