## 3. Detailed Root Causes & Corrections

### 3.1 Remediation 1: `chk_terminal_attempt_no_active_lease` Constraint Compliance

**Problem:**  
In milestone BE.07.05, recovering a turn in `STREAMING` status with an active lease failed upon finalization with:

```
PostgresError { code: "23514", message: "new row for relation \"ai_conversation_messages\" violates check constraint \"chk_terminal_attempt_no_active_lease\"" }
```

PostgreSQL migration `20261123103500_add_ai_conversation_persistence` establishes:

```sql
ALTER TABLE "ai_conversation_messages"
ADD CONSTRAINT "chk_terminal_attempt_no_active_lease"
CHECK (
    "status" IN ('PENDING', 'STREAMING')
    OR ("lease_token" IS NULL AND "lease_owner_instance_id" IS NULL AND "lease_expires_at" IS NULL)
);
```

**Fix:**  
In `packages/core/src/ai/infrastructure/persistence/prisma/mappers/prisma-ai-conversation-message.mapper.ts`:

```typescript
if (
  update.status === GenerationStatus.SUCCESS ||
  update.status === GenerationStatus.FAILED ||
  update.status === GenerationStatus.CANCELLED ||
  update.status === GenerationStatus.INTERRUPTED
) {
  data.leaseToken = null;
  data.leaseOwnerInstanceId = null;
  data.leaseExpiresAt = null;
}
```

When transitioning to any terminal state, lease ownership is completely released, fulfilling the database invariant.

### 3.2 Remediation 2: Information Disclosure Prevention & Error Sanitization

**Problem:**  
Database driver errors (e.g. timeout, connection dropped) may embed connection URIs containing username, password, host, and port in `error.message`.

**Fix:**

1. In `packages/core/src/ai/ports/inbound/ai-turn-error-classifier.ts`:
   Extended detection to match `postgres` and `prisma` connection errors, sanitizing the message to:
   `Knowledge retrieval database encountered a temporary failure.`
2. In `apps/api/src/ai/conversation/filters/ai-conversation-exception.filter.ts`:
   Applied `AiTurnErrorClassifier.classify` on uncaught errors to prevent raw error strings from leaking into application log streams.
3. In `apps/api/src/ai/services/generation/ai-turn-generation.worker.ts`:
   Applied `AiTurnErrorClassifier.classify` on polling errors.

### 3.3 Remediation 3: Server-Side Tenant Context Derivation

**Verified Invariant:**  
Clients cannot access or mutate cross-tenant conversation data by supplying a foreign `tenantId` in request bodies or query parameters. The controller derives tenant identity exclusively from the validated JWT principal (`TrustedAiContext`). Requests targeting a foreign tenant's conversation throw `ConversationNotFoundError` without revealing the existence of the conversation.

### 3.4 Remediation 4: Privileged Inspection Audit Enforcement

**Verified Invariant:**  
Privileged inspection endpoints (`/api/v1/ai/conversations/:id/audit-inspect`) require:

1. `Owner` role.
2. `ai.conversations.audit` permission.
3. A clinical justification reason of at least 10 characters.
4. **Fail-closed guarantee:** If the immutable audit log record cannot be persisted to PostgreSQL, the operation aborts immediately and no conversation details or messages are returned to the caller.

### 3.5 Remediation 5: Transactional Fencing Against Stale Execution

**Verified Invariant:**  
If a generation attempt is superseded (e.g. coordinator increments `activeAttemptNumber` due to lease timeout), the stale worker's late finalization is rejected inside the atomic transaction with `ATTEMPT_SUPERSEDED`. No stale messages are designated canonical.

## 4. Database Schema & Migration Assessment

- **Schema Changes Required:** **NONE**.
- **Assessment:**
  The check constraints (`chk_terminal_attempt_no_active_lease`, `chk_canonical_requires_success`), partial unique indexes (`ai_conversation_active_generation_idx`, `uq_turn_single_canonical_assistant`), and unique keys were already present and correctly defined in PostgreSQL.
  The defect was an omission in the application persistence mapper where lease fields were not nullified upon terminal status transitions. Fixing the application mapper restored full compliance with the existing database schema without requiring a migration.

## 6. Deferred / Accepted Operational Risks

1. **In-Memory Active Registry Across Multiple Node Instances**:
   - `AiTurnDispatcherService` maintains an in-memory `activeExecutions` Map on each API instance.
   - _Risk Assessment & Mitigation:_ In a multi-replica deployment, cross-instance deduplication does not rely on in-memory state; it is enforced persistently by PostgreSQL partial index `ai_conversation_active_generation_idx` and `activeAttemptNumber` transactional fencing. This is an accepted distributed design.
2. **Deterministic Lease Timeout Granularity**:
   - Stalled turns are reclaimed after the configured lease threshold (default: 5 minutes). In-flight generations exceeding this threshold are marked stale.
   - _Risk Assessment & Mitigation:_ Fencing prevents late stale workers from overwriting newer attempts.
