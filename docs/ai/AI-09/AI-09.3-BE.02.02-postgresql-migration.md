### 3.3 Partial Unique Indexes (Enforcing Semantic Invariants)

1. **Active Assistant Generation Uniqueness (`ai_conversation_active_generation_idx`):**
   ```sql
   CREATE UNIQUE INDEX "ai_conversation_active_generation_idx"
       ON "ai_conversation_messages"("conversation_id")
       WHERE "role" = 'ASSISTANT' AND "status" IN ('PENDING', 'STREAMING');
   ```
   _Guarantee:_ Exactly at most one active assistant generation attempt can exist per conversation concurrently across all turns.
2. **Single User Message Per Turn (`uq_turn_single_user_message`):**
   ```sql
   CREATE UNIQUE INDEX "uq_turn_single_user_message"
       ON "ai_conversation_messages"("turn_id")
       WHERE "role" = 'USER';
   ```
   _Guarantee:_ Enforces exactly one prompt per logical turn at the database level.
3. **Single Canonical Assistant Message Per Turn (`uq_turn_single_canonical_assistant`):**
   ```sql
   CREATE UNIQUE INDEX "uq_turn_single_canonical_assistant"
       ON "ai_conversation_messages"("turn_id")
       WHERE "role" = 'ASSISTANT' AND "is_canonical" = TRUE;
   ```
   _Guarantee:_ Exactly one assistant attempt can be designated as the canonical response for a completed turn.

   ```sql

       FOREIGN KEY ("active_attempt_id")
       REFERENCES "ai_conversation_messages"("id") ON DELETE SET NULL;
   ```

### 4.2 PostgreSQL Check Constraints

1. **Canonical Message Requires SUCCESS (`chk_canonical_requires_success`):**
   ```sql
   CHECK ("is_canonical" = FALSE OR ("role" = 'ASSISTANT' AND "status" = 'SUCCESS'))
   ```
2. **Terminal Attempts Cannot Retain Active Leases (`chk_terminal_attempt_no_active_lease`):**
   ```sql
   CHECK (
       "status" IN ('PENDING', 'STREAMING')
       OR ("lease_token" IS NULL AND "lease_expires_at" IS NULL)
   )
   ```
3. **Monotonic Positive Numbers:**
   - `chk_turn_index_positive`: `"turn_index" >= 1`
   - `chk_active_attempt_number_positive`: `"active_attempt_number" >= 1`
   - `chk_sequence_number_positive`: `"sequence_number" >= 1`
   - `chk_attempt_number_positive`: `"attempt_number" >= 1`

## 5. PostgreSQL Triggers & Validation Procedures

### 5.1 Active Attempt Integrity Trigger (`trg_validate_turn_active_attempt`)

```sql
CREATE OR REPLACE FUNCTION validate_turn_active_attempt_membership()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.active_attempt_id IS NOT NULL THEN
        IF NOT EXISTS (
            SELECT 1 FROM "ai_conversation_messages" m
            WHERE m."id" = NEW.active_attempt_id
              AND m."turn_id" = NEW."id"
              AND m."conversation_id" = NEW."conversation_id"
              AND m."tenant_id" = NEW."tenant_id"
              AND m."role" = 'ASSISTANT'
        ) THEN
            RAISE EXCEPTION 'Constraint violation: active_attempt_id % must reference an ASSISTANT message in the same turn %, conversation %, and tenant %',
                NEW.active_attempt_id, NEW.id, NEW.conversation_id, NEW.tenant_id;
        END IF;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE CONSTRAINT TRIGGER trg_validate_turn_active_attempt
    AFTER INSERT OR UPDATE OF active_attempt_id ON "ai_conversation_turns"
    DEFERRABLE INITIALLY DEFERRED
    FOR EACH ROW
    EXECUTE FUNCTION validate_turn_active_attempt_membership();
```

_Behavior:_ Enforces that the `active_attempt_id` pointer resolves to an `ASSISTANT` attempt created for the exact same turn, conversation, and tenant. Being `DEFERRABLE INITIALLY DEFERRED`, it allows transactions to insert the turn first, insert the message attempt second, and bind the pointer before transaction commit without intermediate FK deadlocks.

### 5.2 Message Immutability Trigger (`trg_protect_message_immutability`)

```sql
CREATE OR REPLACE FUNCTION prevent_message_relational_mutation()
RETURNS TRIGGER AS $$
BEGIN
    IF (OLD.role <> NEW.role) THEN
        RAISE EXCEPTION 'Constraint violation: message role is immutable once inserted.';
    END IF;
    IF (OLD.turn_id <> NEW.turn_id OR OLD.conversation_id <> NEW.conversation_id OR OLD.tenant_id <> NEW.tenant_id) THEN
        RAISE EXCEPTION 'Constraint violation: message parent bindings (turn_id, conversation_id, tenant_id) are immutable.';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_protect_message_immutability
    BEFORE UPDATE ON "ai_conversation_messages"
    FOR EACH ROW
    EXECUTE FUNCTION prevent_message_relational_mutation();
```

_Behavior:_ Blocks any update attempting to alter `role`, `turn_id`, `conversation_id`, or `tenant_id`, while permitting updates to mutable operational fields (`status`, `content`, `sources`, `metadata`, `lease_token`, `lease_expires_at`).
