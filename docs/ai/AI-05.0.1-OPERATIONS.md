## 2. Backup & Disaster Recovery Procedures

### 2.1 Pre-Migration Backup Locations

Prior to upgrading PostgreSQL to `pgvector/pgvector:pg16`, full custom-format dumps were generated and archived in `backups/pre-pgvector/`:

- `backups/pre-pgvector/pre_pgvector_demo.dump` (Demo database `kinergy_dev`)
- `backups/pre-pgvector/pre_pgvector_dev.dump` (Dev database `kinergy_dev`)
- `backups/pre-pgvector/pre_pgvector_staging.dump` (Staging database `kinergy_staging`)

### 2.2 Taking an On-Demand Backup

```powershell
$timestamp = Get-Date -Format "yyyyMMdd_HHmmss"
$backupFile = "backups/kinergy_backup_$timestamp.dump"

docker exec kinergy-demo-postgres pg_dump -U kinergy_user -d kinergy_dev -Fc -f /tmp/backup.dump
docker cp kinergy-demo-postgres:/tmp/backup.dump $backupFile
docker exec kinergy-demo-postgres rm -f /tmp/backup.dump

Write-Host "Backup saved to: $backupFile"
```

### 2.3 Restoring from a Custom Dump

```powershell
# Step 1: Copy dump file into container
docker cp ./backups/pre-pgvector/pre_pgvector_demo.dump kinergy-demo-postgres:/tmp/restore.dump

# Step 2: Execute pg_restore (clean and recreate objects)
docker exec kinergy-demo-postgres pg_restore -U kinergy_user -d kinergy_dev --clean --if-exists /tmp/restore.dump

# Step 3: Remove temporary dump
docker exec kinergy-demo-postgres rm -f /tmp/restore.dump
```

## 3. Emergency Rollback Plan

If an unexpected incompatibility or corruption requires rolling back to standard `postgres:16-alpine`:

1. **Step 1: Stop the pgvector Container:**
   ```powershell
   docker compose -f docker-compose.demo.yml stop demo-postgres
   ```
2. **Step 2: Revert Compose Configuration:**
   Change `image: pgvector/pgvector:pg16` back to `image: postgres:16-alpine` in `docker-compose.demo.yml`.
3. **Step 3: Recreate Container:**
   ```powershell
   docker compose -f docker-compose.demo.yml up -d demo-postgres
   ```
4. **Step 4: Verify or Restore Data:**
   If the volume fails to start due to glibc/musl catalog state, restore the clean backup:
   ```powershell
   # Restore clean pre-pgvector backup
   docker exec -i kinergy-demo-postgres pg_restore -U kinergy_user -d kinergy_dev --clean /tmp/pre_pgvector_demo.dump
   ```

## 4. Diagnostics & Health Monitoring

### 4.1 Checking Extension Installation & Version

```sql
SELECT name, default_version, installed_version, comment
FROM pg_available_extensions
WHERE name = 'vector';
```

### 4.2 Inspecting Active Vector Indexes (Downstream Milestone AI-05)

```sql
SELECT
    schemaname,
    tablename,
    indexname,
    indexdef
FROM pg_indexes
WHERE indexdef ILIKE '%hnsw%' OR indexdef ILIKE '%ivfflat%';
```

### 4.3 Container Resource Utilization

```powershell
docker stats kinergy-demo-postgres --no-stream
```
