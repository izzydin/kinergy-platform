## 4. Shared HTTP Infrastructure Reused

The client directly consumes `httpClient` from `apps/web/src/shared/api/http-client.ts`:

1. **Bearer Authentication:** Interceptor resolves active token via `authTokenGetter` (`Authorization: Bearer <token>`).
2. **Tenant Forwarding:** Injects `X-Tenant-ID` header if configured in frontend context.
3. **Request Cancellation:** Supports caller-provided `AbortSignal` via `RequestOptions.signal` on all methods.
4. **Header Normalization:** Enforces `Content-Type: application/json` and `Accept: application/json`.
5. **Zero Redundancy:** Does not create duplicate `axios`, `fetch`, or authentication interceptors.

---

## 5. Stable Idempotent Request Handling

The turn submission methods (`createConversation` and `reserveTurn`) enforce strict client-stable idempotency:

1. **Caller-Managed `clientTurnId`:** The caller generates the idempotency key (e.g. `crypto.randomUUID()`) and provides it in the request payload.
2. **Stable Across Retries:** If an HTTP failure occurs (network glitch, timeout, 503), the client **never** generates a replacement `clientTurnId`. The original key and payload are retained.
3. **Conflict Differentiation:**
   - **In-Flight Lock Conflict (`409 Conflict`):** The client surfaces this when another turn is currently generating on the conversation (`isTurnInProgressConflict(err) === true`). Captures server-provided `Retry-After: 2` header via `getRetryAfterSeconds(err)`.
   - **Payload Hash Mismatch Conflict (`409 Conflict`):** The client surfaces this when the same `clientTurnId` is re-sent with a modified prompt (`isPayloadMismatchConflict(err) === true`).
4. **Zero Non-Idempotent Auto-Retries:** Mutating operations (`PATCH`, `DELETE`) are never automatically retried without caller intent.

## 6. Error Normalization & Contract Validation

Implemented in [`conversation-api.errors.ts`](file:///c:/Projects/kinergy-platform/apps/web/src/modules/intelligence/assistant/api/conversation-api.errors.ts):

### 6.1 Platform Error Mapping

| Backend Response / Condition | Normalized Error Class | Status Code | Diagnostic Information Preserved                                                    |
| :--------------------------- | :--------------------- | :---------: | :---------------------------------------------------------------------------------- |
| `401 Unauthorized`           | `AuthenticationError`  |     401     | Safe session expired message.                                                       |
| `403 Forbidden`              | `AuthorizationError`   |     403     | Missing permissions or tenant context.                                              |
| `404 Not Found`              | `NotFoundError`        |     404     | Conceals cross-tenant conversation existence.                                       |
| `400 Bad Request`            | `ValidationError`      |     400     | Field-level validation constraints.                                                 |
| `409 Conflict`               | `ConflictError`        |     409     | `responseData.code`, `retryAfterSeconds`, in-flight vs payload mismatch indicators. |
| `429 Too Many Requests`      | `RateLimitError`       |     429     | `retryAfterSeconds` from `Retry-After` header.                                      |
| `500 Server Error`           | `ServerError`          |     500     | Sanitized error message; raw database/stack details stripped.                       |
| Network / Timeout            | `NetworkError`         |      0      | Connection failure / offline state.                                                 |
| AbortSignal Cancelled        | `RequestCanceledError` |      0      | Clean abort indicator.                                                              |

### 6.2 Response Validation Failures (`ContractValidationError`)

If a backend response violates the Zod schema (e.g. missing required identifiers, malformed cursors, or invented status values like `RECOVERING`):

- Throws `ContractValidationError` with HTTP status `502 Bad Gateway` and code `'CONTRACT_VALIDATION_ERROR'`.
- Preserves safe diagnostic paths (`validationIssues: ["turnStatus: Invalid enum value"]`).
- **Data Protection:** Does not log or leak raw prompt text, user content, or credentials.
